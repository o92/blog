为简洁起见，本 AIP 在此定义一些常用术语，而不在每篇 AIP 中分别定义。

## Guidance

下列术语 **should** 在各 AIP 中一致使用。

### API

Application programming interface。可以是本地接口（例如 client library），也可以是 Network API（定义见下）。

### API backend

实现 API service 业务逻辑的一组服务器及相关基础设施。单个 API backend 服务器常称为 API server。

### API consumer

消费 API service 的实体。对 Google APIs 而言，通常是拥有客户端应用或服务器资源的 Google project。

### API definition

API 的定义，通常定义在 Protocol Buffer service 中。一个 API definition 可由任意数量的 API service 实现。

### API frontend

为各 API service 提供共性功能（例如负载均衡与认证）的一组服务器及相关基础设施。单个 API frontend 服务器常称为 API proxy。

**Note:** API frontend 与 API backend 可能彼此邻近，也可能相距很远。有时它们可以编译进同一个应用程序二进制，并在同一进程内运行。

### API interface

API 规范 IDL 中对 API method 分组的元素，例如 Protocol Buffers 的 `service` 定义。它通常映射到多数编程语言中类似的高层分组机制，如 `class` 或 `interface`。

### API method

API 中的单个操作。在 Protocol Buffers 中通常由 `rpc` 定义表示，并在多数编程语言中映射为 API 中的函数。

### API producer

产出 API service 的实体。对 Google APIs 而言，通常是负责该 API service 的 Google 团队。

### API product

API service 及其相关组件（例如服务条款、文档、client libraries 与服务支持）一并作为 API product 呈现给客户。例如 Google Calendar API。

**Note:** 人们有时把 API product 直接称为 API。

### API service

一个或多个 API 的已部署实现，暴露在一个或多个网络地址上，例如 Cloud Pub/Sub API。

### API service definition

用于定义 API service 的 API definitions（`.proto` 文件）与 API service configurations（`.yaml` 文件）的组合。Google API service definition 的 schema 是 `google.api.Service`。

### API service endpoint

指 API service 用来处理入站 API 请求的网络地址。一个 API service 可以有多个 API service endpoint，例如 `https://pubsub.googleapis.com` 与 `https://content-pubsub.googleapis.com`。

### API service name

指 API service 的逻辑标识符。Google APIs 使用 RFC 1035 DNS 兼容名作为其 API service name，例如 `pubsub.googleapis.com`。

### API title

指 API service 面向用户的产品标题，例如 "Cloud Pub/Sub API"。

### API request

对一个 API method 的单次调用。常作为计费、日志、监控与限流的单位。

### API version

一个 API 的版本，或一组一并定义的 API 的版本。API version 常用字符串表示，例如 "v1"，并出现在 API 请求与 Protocol Buffers 包名中。

### Client

Client 是通过调用 API 完成特定任务的程序，或把 API 以用户可访问的方式暴露出来、或对静态资源数据操作的通用工具（例如命令行界面）。

client 的例子包括：

- 命令行界面
- 库，例如面向特定编程语言的 Software Development Kit
- 从 API 读取资源后，对资源的 JSON 表示进行操作的脚本
- 工具，例如 [Declarative Clients](#declarative-clients)
- 可视化界面，例如 web application

### Google API

由 Google 服务暴露的 Network API。其中多数托管在 `googleapis.com` 域。不包括其它类型的 API，例如 client libraries 与 Software Development Kit。

### Declarative Clients

Declarative Clients，亦称 Infrastructure as Code，指一类 client：消费表示 API 所暴露资源的标记语言或代码，并执行相应的命令式动作，把资源驱动到该期望状态。为判断要做哪些变更、以及一组更新是否成功，声明式 client 会把服务端资源属性与客户端定义的值比较。该比较功能确保创建或更新的准确性，但要求服务把客户端设定的字段当作只读，并认真保留这些值。

Declarative Clients 所抽象掉的复杂性例子包括：

- 判断达到期望状态所需的恰当命令式动作（create / update / delete）。
- 这些命令式动作的顺序。

[Terraform](https://www.terraform.io/) 是此类 client 的一个例子。

### User

直接使用 API 的人，例如用 cURL。定义此术语是为了在 AIP 中区分人类 *user* 与程序化 *client*。

### Network API

跨计算机网络运作的 API。Network APIs 使用包括 HTTP 在内的网络协议通信，且常常由与消费方不同的组织生产。
