各篇 AIP 会反复用到同一批词。这里统一定义一次，后面就不必每篇重讲。各 AIP 应当用这里的说法。

## 术语

### API

Application programming interface。可以是本地接口（例如 client library），也可以是 Network API（见下）。

### API backend

实现 API service 业务逻辑的那组服务器和配套基础设施。其中一台常常叫 API server。

### API consumer

消费 API service 的实体。对 Google APIs 来说，通常是拥有客户端应用或服务器资源的 Google project。

### API definition

API 的定义，通常写在 Protocol Buffer service 里。一份 API definition 可以由任意数量的 API service 实现。

### API frontend

给各 API service 提供共性功能的那组服务器和配套基础设施，例如负载均衡、认证。其中一台常常叫 API proxy。

API frontend 和 API backend 可能挨得很近，也可能离得很远。有时可以编进同一个二进制，跑在同一进程里。

### API interface

API 规范 IDL 里用来给 API method 分组的元素。例如 Protocol Buffers 的 `service`。多数编程语言里会映射成类似的高层分组，如 `class` 或 `interface`。

### API method

API 里的单个操作。Protocol Buffers 里通常是一条 `rpc`，多数语言里映射成函数。

### API producer

产出 API service 的实体。对 Google APIs 来说，通常是负责该 API service 的 Google 团队。

### API product

API service 加上配套（服务条款、文档、client libraries、服务支持）一起卖给客户，叫 API product。例如 Google Calendar API。

人们有时把 API product 直接叫 API。

### API service

一个或多个 API 的已部署实现，暴露在一个或多个网络地址上。例如 Cloud Pub/Sub API。

### API service definition

用来定义 API service 的那堆东西：API definitions（`.proto`）加上 API service configurations（`.yaml`）。Google API service definition 的 schema 是 `google.api.Service`。

### API service endpoint

API service 用来接入境请求的网络地址。一个 API service 可以有多个 endpoint，例如 `https://pubsub.googleapis.com` 与 `https://content-pubsub.googleapis.com`。

### API service name

API service 的逻辑标识符。Google APIs 用 RFC 1035 DNS 兼容名，例如 `pubsub.googleapis.com`。

### API title

面向用户的产品标题，例如 "Cloud Pub/Sub API"。

### API request

对一个 API method 的单次调用。常常是计费、日志、监控、限流的单位。

### API version

一个 API 的版本，或一组一并定义的 API 的版本。常用字符串表示，例如 "v1"，出现在请求和 Protocol Buffers 包名里。

### Client

通过调用 API 完成特定任务的程序；或把 API 以用户能用的方式露出来、或对静态资源数据动手的通用工具（例如命令行界面）。

例子：

- 命令行界面
- 库，例如面向特定语言的 Software Development Kit
- 从 API 读出资源后，对资源的 JSON 表示动手的脚本
- 工具，例如 Declarative Clients
- 可视化界面，例如 web application

### Google API

Google 服务暴露的 Network API。多数托管在 `googleapis.com`。不包括 client libraries、Software Development Kit 这类别的 API。

### Declarative Clients

Declarative Clients，也叫 Infrastructure as Code。这类 client 吃一份标记语言或代码，里面写的是 API 所暴露资源的期望状态，然后发出相应的命令式动作，把资源赶到那个状态。

为了判断要改什么、一组更新算不算成功，声明式 client 会拿服务端资源属性和客户端写死的值比。这个比较保证创建或更新对得上；也就要求服务把客户端设过的字段当只读，并认真把这些值保住。

它们抽象掉的复杂性，例如：

- 到达期望状态该用 create、update 还是 delete。
- 这些动作的顺序。

[Terraform](https://www.terraform.io/) 是一例。

### User

直接使用 API 的人，例如用 cURL。用来在 AIP 里把人类 user 和程序化 client 分开。

### Network API

跨计算机网络运作的 API。用包括 HTTP 在内的网络协议通信，常常由与消费方不同的组织生产。
