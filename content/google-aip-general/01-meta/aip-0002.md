AIP 要能当索引、当单一事实来源，还要能公开迭代。编号就是检索键：一篇一个号，状态另标，避免「没批的就没有号」。

本文讲编号怎么分、哪一段留给谁。

## 谁分配

AIP editors（见 [AIP-1]({{< ref "aip-0001" >}})）在一篇 AIP 被收成待评审草稿时分配编号。所有 AIP 都有编号，不只是已批准的。[AIP Index](https://google.aip.dev/) 会分清：哪些已批准、有约束力，哪些还在讨论。

editors 可以为相关的一组 AIP 预留号段。例如只适用于某一类 API 的那一组。

除此之外，编号是任意分的。一般从栈上取下一个给草稿。偶尔会用好记的、带点玩笑的号。

## 号段

当前已识别的号段如下。

### 通用

- **1-99：** 留给 meta-AIP（多半跟过程有关）。
- **100-999：** 通用 API 设计指导

### Google Product Areas

- **2700-2799：** Apps (Google Workspace)
- **2500-2599：** Cloud
- **3000-3099：** Actions on Google
- **3200-3299：** Firebase
- **4100-4199：** Auth libraries
- **4200-4299：** Client libraries
- **4600-4699：** Geo

某团队要发只适用于自己的 API 指导或文档，并想申请号段，联系 api-editors@。
