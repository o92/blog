AIP 系统提供一种机制，为 API Improvement Proposals 建立索引与单一事实来源，并让它们以协作、透明的方式迭代。

本文描述 AIP 编号系统。

## 分配 AIP 编号

AIP editors（见 [AIP-1]({{< ref "aip-0001" >}})）负责在每篇 AIP 被接受为待评审草稿时分配编号。重要的是，**所有** AIP 都有编号，不只是已批准的。[AIP Index](https://google.aip.dev/) 会清楚区分哪些 AIP 已批准且具约束力，哪些仍在讨论。

editors 可以决定为在某种意义上相关的一组 AIP 预留特定编号段（例如只适用于某一子集的 API）。

除此之外，AIP 编号是任意分配的。一般而言，editors 会从栈上取下一个 AIP 编号分给草稿 AIP，但偶尔也会使用特殊/玩笑编号，若这对记忆或其他原因有用。

## AIP 编号段

当前已识别的 AIP 编号段如下。

### Generally Applicable

- **1-99：** 留给 meta-AIPs（一般与过程相关）。
- **100-999：** 通用 API 设计指导

### Google Product Areas

- **2700-2799：** Apps (Google Workspace)
- **2500-2599：** Cloud
- **3000-3099：** Actions on Google
- **3200-3299：** Firebase
- **4100-4199：** Auth libraries
- **4200-4299：** Client libraries
- **4600-4699：** Geo

若某团队要发布仅适用于该团队的 API 指导或文档，并希望申请编号段，请联系 api-editors@。
