AIP 会改。改完之后，旧 API 仍可能要引用「当时那一版」来说明自己的设计选择。所以 AIP 自己也要有版本，而且要能钉到某一天。

## 怎么做

- AIP 必须按日期版本化，格式是 [ISO-8601 的 `YYYY-MM-DD`](https://www.w3.org/TR/NOTE-datetime)，对应该版本加入的日期。
- 版本必须在存放 AIP 的源码控制系统上以 tag 提供，格式为 `v{version}`。例如 `v2023-03-28`。
- 一篇或多篇 AIP 发生显著变更时，必须打一个新版本。
- 每篇 AIP 必须有 changelog：写明变更日期和一句短描述。

## 为什么

版本是某一时间点上的参照。指导可能被推翻，也可能改到几乎不像当初那版。用 AIP 的 API 需要能指回旧指导，证明当时为什么那样设计。

### 为什么用日期

按日期版本化，客户端容易找到「这个 API 写的那会儿」AIP 怎么说。

### 为什么不给每篇 AIP 单独版本

另一种做法是每篇 AIP 自己一个版本号。

AIP 常常互相交叉引用。若每篇都有独立版本，交叉引用也必须钉死被引用那篇的具体版本，整套指导才能拼完整。一套日期版本更省事。
