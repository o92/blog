本 AIP 定义 AIP 的版本方案。

## Guidance

- AIP **must** 按日期版本化，使用 [ISO-8601 的 `YYYY-MM-DD` 格式](https://www.w3.org/TR/NOTE-datetime)，对应该版本加入的日期。
- AIP 版本 **must** 在存放 AIP 的源码控制系统上以 tag 提供，格式为 `v{version}`。示例：`v2023-03-28`。
- 当一篇或多篇 AIP 发生显著变更时，AIP **must** 产生新版本。
- 每篇 AIP **must** 包含 changelog 一节，写明变更日期与简短描述。

## Rationale

版本是某一时间点上 AIP 的参照点。这一点很关键，因为一篇 AIP 上的指导可能被推翻，或发生显著变更，以至于不再类似于原先的设计。使用 AIP 的 API 可能需要引用较旧的 AIP 指导，以证明其设计选择合理。

### 采用基于日期的版本控制的理由

有了基于日期的版本控制，客户端可以容易地找到某 API 撰写当时的 AIP 指导。

### 为何不对各 AIP 单独版本化

通用版本之外的另一种做法，是给每篇 AIP 附上各自的版本。

AIP 常常互相交叉引用。若每篇 AIP 都有独立版本，则交叉引用也必须指定那些被引用 AIP 的具体版本，才能提供完整指导。
