**英文标题**：Standard methods: Update  
**原文**：[AIP-134](https://google.aip.dev/134) · approved · 创建 2019-01-24 · 更新 2022-06-02  
**许可**：原文 © Google，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

在 REST APIs 中，习惯对资源的 URI（例如 `/v1/publishers/{publisher}/books/{book}`）发出 `PATCH` 或 `PUT` 请求以更新该资源。

面向资源的设计（[AIP-121]({{< ref "aip-0121" >}})）通过 `Update` 方法尊重此模式（镜像 REST `PATCH` 行为）。这些 RPCs 接受表示该资源的 URI，并返回该资源。

## Guidance

除非对用户没有价值，APIs **should** 一般为资源提供 update 方法。update 方法的目的是在不引起副作用的情况下变更资源。

Update methods 使用下列模式指定：

```proto
rpc UpdateBook(UpdateBookRequest) returns (Book) {
  option (google.api.http) = {
    patch: "/v1/{book.name=publishers/*/books/*}"
    body: "book"
  };
  option (google.api.method_signature) = "book,update_mask";
}
```

- RPC 的名称 **must** 以单词 `Update` 开头。RPC 名称的其余部分 **should** 为该资源 message 名称的单数形式。
- 请求 message **must** 与 RPC 名称匹配，并带 `Request` 后缀。
- 响应 message **must** 为资源本身。（没有 `UpdateBookResponse`。）
  - 响应 **should** 包含完全填充的资源，并且 **must** 包含所发送且包含在 update mask 中的任何字段，除非它们是 input only（见 [AIP-203]({{< ref "aip-0203" >}})）或有理由返回部分响应（见 [AIP-157]({{< ref "aip-0157" >}})）。
  - 若 update RPC 是 [长时运行的](#long-running-update)，响应 message **must** 为解析为资源本身的 `google.longrunning.Operation`。
- 该方法 **should** 支持部分资源更新，HTTP 动词 **should** 为 `PATCH`。
  - 若该方法永远只支持完整资源替换，则 HTTP 动词 **may** 为 `PUT`。然而这被强烈不鼓励，因为向资源添加字段会成为向后不兼容变更。
- 资源的 `name` 字段 **should** 映射到 URI 路径。
  - `{resource}.name` 字段 **should** 是 URI 路径中的唯一变量。
- `google.api.http` annotation 中 **must** 有 `body` 键，并且它 **must** 映射到请求 message 中的资源字段。
  - 其余字段 **should** 映射到 URI query parameters。
- **should** 恰好有一个 `google.api.method_signature` annotation，值为 `"{resource},update_mask"`。
- 若 API 操作于 management plane（[AIP-111]({{< ref "aip-0111" >}})），该操作应具有强一致性（[AIP-121]({{< ref "aip-0121" >}})）：update 操作的完成 **must** 意味着所有用户可设置的值以及资源的存在都已达到稳态，并且读取资源状态返回一致响应。

**Note:** 与其它四个标准方法不同，此处 URI 路径引用嵌套字段（示例中的 `book.name`）。若资源字段有词分隔，使用 `snake_case`。

### Request message

Update methods 实现一种常见的请求 message 模式：

```proto
message UpdateBookRequest {
  // The book to update.
  //
  // The book's `name` field is used to identify the book to update.
  // Format: publishers/{publisher}/books/{book}
  Book book = 1 [(google.api.field_behavior) = REQUIRED];

  // The list of fields to update.
  google.protobuf.FieldMask update_mask = 2;
}
```

- 请求 message **must** 包含资源字段。
  - 该字段 **must** 映射到 `PATCH` body。
  - 该字段 **should** 被标注为 required（[AIP-203]({{< ref "aip-0203" >}})）。
  - 资源 message 中 **must** 包含 `name` 字段。它 **should** 称为 `name`。
  - 该字段 **must** 标识正在更新的资源的 resource type（[AIP-123]({{< ref "aip-0123" >}})）。
- 若支持部分资源更新，**must** 包含 field mask。它 **must** 为类型 `google.protobuf.FieldMask`，并且 **must** 称为 `update_mask`。
  - field mask 中使用的字段对应正在更新的资源（不是请求 message）。
  - 该字段 **must** 为可选，并且服务 **must** 把省略的 field mask 视为隐含 field mask，等价于所有已填充（有非空值）的字段。
  - Update masks **must** 支持特殊值 `*`，表示完整替换（`PUT` 的等价物）。
  - API producer 需要意识到：在消费者使用 `*` 且不知道新可变字段时，向资源添加新的可变字段会如何被处理。同样，消费者仅应在可接受风险时使用 `*`。一般而言，显式指定要更新的字段比使用 `*` 更安全。
- 请求 message **must not** 包含任何其它必填字段，并且 **should not** 包含其它可选字段，除非本文或另一篇 AIP 有描述。

### Side effects

一般而言，update methods 旨在更新资源内的数据。Update methods **should not** 触发其它副作用。副作用 **should** 由 custom methods 触发。

特别地，这要求 state fields（[AIP-216]({{< ref "aip-0216" >}})） **must not** 在 update methods 中直接可写。

### PATCH and PUT

**TL;DR:** Google APIs 一般只使用 `PATCH` HTTP 动词，不支持 `PUT` 请求。

我们标准化为 `PATCH`，因为 Google 会在稳定 APIs 上就地做向后兼容改进。常常需要向现有资源添加新字段，但在使用 `PUT` 时这会成为破坏性变更。

为说明这一点，考虑对 `Book` 资源的 `PUT` 请求：

```
PUT /v1/publishers/123/books/456

{"title": "Mary Poppins", "author": "P.L. Travers"}
```

接下来考虑该资源后来增加了新字段（此处添加 `rating`）：

```proto
message Book {
  string title = 1;
  string author = 2;

  // Subsequently added to v1 in place...
  int32 rating = 3;
}
```

若一本书已设置 rating，再执行现有 `PUT` 请求，它会抹掉该书的 rating。本质上，`PUT` 请求无意中抹掉了数据，因为先前版本不知道该字段。

### Long-running update

有些资源更新所需时间超出常规 API 请求的合理范围。此时，API **should** 改用 long-running operation（[AIP-151]({{< ref "aip-0151" >}})）：

```proto
rpc UpdateBook(UpdateBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    patch: "/v1/{book.name=publishers/*/books/*}"
    body: "book"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- 响应类型 **must** 设为该资源（若 RPC 不是长时运行时的返回类型）。
- `response_type` 与 `metadata_type` 字段都 **must** 指定。

**Note:** 声明式友好资源（[AIP-128]({{< ref "aip-0128" >}})）**should** 使用 long-running update。

### Create or update

若服务使用客户端分配的 resource names，`Update` methods **may** 暴露 `bool allow_missing` 字段：用户试图更新不存在的资源时该方法会成功（并在此过程中创建该资源）：

```proto
message UpdateBookRequest {
  // The book to update.
  //
  // The book's `name` field is used to identify the book to be updated.
  // Format: publishers/{publisher}/books/{book}
  Book book = 1 [(google.api.field_behavior) = REQUIRED];

  // The list of fields to be updated.
  google.protobuf.FieldMask update_mask = 2;

  // If set to true, and the book is not found, a new book will be created.
  // In this situation, `update_mask` is ignored.
  bool allow_missing = 3;
}
```

更具体地，`allow_missing` 标志触发下列行为：

- 若方法调用针对不存在的资源，则创建该资源。无论提供何种 field mask，都应用所有字段。
  - 然而，若缺少任何必填字段或字段值无效，则返回 `INVALID_ARGUMENT` 错误。
- 若方法调用针对已存在的资源，且所有字段都匹配，则原样返回现有资源。
- 若方法调用针对已存在的资源，则仅更新 field mask 中声明的字段。

即使用户把 `allow_missing` 设为 `true`，调用 `Update` **must** 仍具备 update 权限。若客户希望阻止用户用 update 方法创建资源，**should** 使用 IAM conditions。

### Etags

API 有时需要允许用户发送保证针对最新数据的 update 请求（常见用例是检测并避免竞态）。需要此能力的资源通过包含 `string etag` 字段实现，该字段含有表示资源内容的不透明、服务器计算值。

此时，资源 **should** 包含 `string etag` 字段：

```proto
message Book {
  option (google.api.resource) = {
    type: "library.googleapis.com/Book"
    pattern: "publishers/{publisher}/books/{book}"
  };

  // The resource name of the book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [(google.api.field_behavior) = IDENTIFIER];

  // The title of the book.
  // Example: "Mary Poppins"
  string title = 2;

  // The author of the book.
  // Example: "P.L. Travers"
  string author = 3;

  // The etag for this book.
  // If this is provided on update, it must match the server's etag.
  string etag = 4;
}
```

`etag` 字段 **may** 为 required（[AIP-203]({{< ref "aip-0203" >}})）或 optional（[AIP-203]({{< ref "aip-0203" >}})）。若已设置，则当且仅当所提供 etag 与服务器计算值匹配时请求 **must** 成功，否则 **must** 以 `ABORTED` 错误失败。请求中的 `update_mask` 字段不影响 `etag` 字段的行为，因为它不是*正在*更新的字段。

### Expensive fields

APIs 有时会遇到资源上某些字段昂贵或无法可靠返回的情况。

这可能发生在几种情形：

- 资源可能有一些计算非常昂贵、且客户在 update 请求上一般用不到的字段。
- 单个资源有时代表来自多个底层（且最终一致）数据源的数据聚合。此时，无法返回未变更字段的权威信息。

此时，API **may** 只返回被更新的字段并省略其余字段，并且若这样做 **should** 文档化此行为。

### Errors

见 errors（[AIP-193]({{< ref "aip-0193" >}})），尤其是何时使用 PERMISSION_DENIED 与 NOT_FOUND 错误（[AIP-193]({{< ref "aip-0193" >}})）。

此外，若用户确有适当权限，但所请求的资源不存在，则除非 `allow_missing` 设为 `true`，服务 **must** 以 `NOT_FOUND`（HTTP 404）报错。
