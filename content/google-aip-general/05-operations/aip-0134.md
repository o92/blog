**英文标题**：Standard methods: Update  
**原文**：[AIP-134](https://google.aip.dev/134) · approved · 创建 2019-01-24 · 更新 2022-06-02  
**许可**：原文 © Google，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

用户要改一个已有资源，而且不该顺带触发别的副作用。Update 就是这条路：给资源（通常再加一个 field mask），拿回更新后的那一份。REST 里对应的是对资源 URI 发 `PATCH` 或 `PUT`。面向资源的设计（见 [AIP-121]({{< ref "aip-0121" >}})）把这套语义收成 `Update`，并镜像 REST `PATCH` 的行为。

## 怎么写

除非对用户没有价值，API 应当一般为资源提供 update。目的是在不引起副作用的情况下变更资源。

模式如下：

```proto
rpc UpdateBook(UpdateBookRequest) returns (Book) {
  option (google.api.http) = {
    patch: "/v1/{book.name=publishers/*/books/*}"
    body: "book"
  };
  option (google.api.method_signature) = "book,update_mask";
}
```

- RPC 名称必须以 `Update` 开头。其余部分应当是该资源 message 名称的单数。
- 请求 message 必须与 RPC 名称匹配，并带 `Request` 后缀。
- 响应 message 必须是资源本身。没有 `UpdateBookResponse`。
  - 响应应当包含完全填充的资源，并且必须包含所发送且包含在 update mask 中的任何字段，除非它们是 input only（见 [AIP-203]({{< ref "aip-0203" >}})）或有理由返回部分响应（见 [AIP-157]({{< ref "aip-0157" >}})）。
  - 若 update RPC 是长时运行的，响应必须是解析为该资源本身的 `google.longrunning.Operation`。
- 该方法应当支持部分资源更新，HTTP 动词应当是 `PATCH`。
  - 若该方法永远只支持完整资源替换，HTTP 动词可以是 `PUT`。但这被强烈不鼓励：往资源上加字段会变成向后不兼容变更。
- 资源的 `name` 字段应当映射到 URI 路径。
  - `{resource}.name` 应当是 URI 路径里唯一的变量。
- `google.api.http` annotation 中必须有 `body` 键，并且必须映射到请求里的资源字段。
  - 其余字段应当映射到 URI query parameters。
- 应当恰好有一个 `google.api.method_signature`，值为 `"{resource},update_mask"`。
- 若 API 操作于 management plane（见 [AIP-111]({{< ref "aip-0111" >}})），该操作应具有强一致性（见 [AIP-121]({{< ref "aip-0121" >}})）：update 一旦完成，所有用户可设置的值以及资源的存在都必须已经达到稳态，再读资源状态必须得到一致响应。

跟其它四个标准方法不同，这里 URI 路径引用的是嵌套字段（示例中的 `book.name`）。资源字段有词分隔时，用 `snake_case`。

### 请求 message

```proto
message UpdateBookRequest {
  // The book to update.
  //
  // The book's `name` field is used to identify the book to update.
  // Format: publishers/{publisher}/books/{book}
  Book book = 1 [(google.api.field_behavior) = REQUIRED];

  // The list of fields to update.
  google.protobuf.FieldMask update_mask = 2;
}
```

- 请求必须包含资源字段。
  - 该字段必须映射到 `PATCH` body。
  - 该字段应当标为 required（见 [AIP-203]({{< ref "aip-0203" >}})）。
  - 资源 message 中必须包含 `name` 字段。应当叫 `name`。
  - 该字段必须标明正在更新的资源的 resource type（见 [AIP-123]({{< ref "aip-0123" >}})）。
- 若支持部分资源更新，必须包含 field mask。类型必须是 `google.protobuf.FieldMask`，名字必须叫 `update_mask`。
  - mask 里的字段对应正在更新的资源，不是请求 message。
  - 该字段必须是可选的。服务必须把省略的 field mask 视为隐含 mask，等价于所有已填充（有非空值）的字段。
  - Update masks 必须支持特殊值 `*`，表示完整替换（`PUT` 的等价物）。
  - 往资源上加新的可变字段时，生产者要意识到：消费者用 `*` 且不知道新字段时会发生什么。消费者也只应在可接受风险时用 `*`。一般而言，显式列出要更新的字段更安全。
- 请求不得包含任何其它必填字段，也不应当包含其它可选字段，除非本文或另一篇 AIP 有描述。

### 副作用

Update 的本意是改资源里的数据。不应当触发其它副作用。副作用应当由 custom methods 触发。

特别地，state fields（见 [AIP-216]({{< ref "aip-0216" >}})）不得在 update 里直接可写。

### 为什么用 PATCH 而不是 PUT

Google APIs 一般只用 `PATCH`，不支持 `PUT`。

原因是 Google 会在稳定 APIs 上就地做向后兼容改进。常常要往现有资源加新字段；用 `PUT` 时这会变成破坏性变更。

看一个对 `Book` 的 `PUT`：

```
PUT /v1/publishers/123/books/456

{"title": "Mary Poppins", "author": "P.L. Travers"}
```

后来资源加了新字段（这里是 `rating`）：

```proto
message Book {
  string title = 1;
  string author = 2;

  // Subsequently added to v1 in place...
  int32 rating = 3;
}
```

一本书已经有 rating，再跑原来的 `PUT`，会把 rating 抹掉。本质上，旧客户端不知道这个字段，`PUT` 却把它清了。

### 长时运行的 update

有些资源更新所需时间超出常规 API 请求的合理范围。这时应当改用 long-running operation（见 [AIP-151]({{< ref "aip-0151" >}})）：

```proto
rpc UpdateBook(UpdateBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    patch: "/v1/{book.name=publishers/*/books/*}"
    body: "book"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- 响应类型必须设为该资源（也就是 RPC 若不是长时运行时会返回的类型）。
- `response_type` 与 `metadata_type` 都必须指定。

声明式友好资源（见 [AIP-128]({{< ref "aip-0128" >}})）应当使用 long-running update。

### Create or update

若服务使用客户端分配的 resource names，`Update` 可以暴露 `bool allow_missing`：用户更新不存在的资源时该方法会成功（并在此过程中创建该资源）：

```proto
message UpdateBookRequest {
  // The book to update.
  //
  // The book's `name` field is used to identify the book to be updated.
  // Format: publishers/{publisher}/books/{book}
  Book book = 1 [(google.api.field_behavior) = REQUIRED];

  // The list of fields to be updated.
  google.protobuf.FieldMask update_mask = 2;

  // If set to true, and the book is not found, a new book will be created.
  // In this situation, `update_mask` is ignored.
  bool allow_missing = 3;
}
```

`allow_missing` 触发的行为：

- 针对不存在的资源时，创建它。无论提供何种 field mask，都应用所有字段。
  - 若缺少任何必填字段或字段值无效，则返回 `INVALID_ARGUMENT`。
- 针对已存在的资源、且所有字段都匹配时，原样返回现有资源。
- 针对已存在的资源时，仅更新 field mask 中声明的字段。

即使用户把 `allow_missing` 设为 `true`，调用 `Update` 仍必须具备 update 权限。若希望阻止用户用 update 创建资源，应当用 IAM conditions。

### Etags

有时用户要保证这次 update 针对的是最新数据（常见用途是检测并避免竞态）。需要这个能力的资源带一个 `string etag`：不透明、由服务器计算、表示资源内容。

此时资源应当包含 `string etag`：

```proto
message Book {
  option (google.api.resource) = {
    type: "library.googleapis.com/Book"
    pattern: "publishers/{publisher}/books/{book}"
  };

  // The resource name of the book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [(google.api.field_behavior) = IDENTIFIER];

  // The title of the book.
  // Example: "Mary Poppins"
  string title = 2;

  // The author of the book.
  // Example: "P.L. Travers"
  string author = 3;

  // The etag for this book.
  // If this is provided on update, it must match the server's etag.
  string etag = 4;
}
```

`etag` 可以是 required（见 [AIP-203]({{< ref "aip-0203" >}})）或 optional。若已设置，则当且仅当所提供 etag 与服务器计算值匹配时请求必须成功，否则必须以 `ABORTED` 失败。请求里的 `update_mask` 不影响 `etag` 的行为，因为它不是*正在*更新的字段。

### 昂贵的字段

有时资源上某些字段昂贵，或无法可靠返回。例如：

- 计算非常贵，客户在 update 上一般也用不到。
- 单个资源聚合了多个底层（且最终一致）数据源。未变更字段拿不到权威信息。

此时 API 可以只返回被更新的字段、省略其余字段。若这样做，应当把行为写进文档。

### 错误

见 [AIP-193]({{< ref "aip-0193" >}})，尤其是何时用 PERMISSION_DENIED 与 NOT_FOUND。

此外，若用户确有适当权限，但所请求的资源不存在，则除非 `allow_missing` 设为 `true`，服务必须以 `NOT_FOUND`（HTTP 404）报错。
