**英文标题**：Batch methods: Create  
**原文**：[AIP-233](https://google.aip.dev/233) · approved · 创建 2019-06-18 · 更新 2022-06-02  
**许可**：原文 © Google，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

有些 APIs 需要允许用户在单个事务中创建多个资源。batch create 方法提供此功能。

## Guidance

APIs **may** 使用下列两种模式支持 Batch Create：

同步返回响应

```proto
rpc BatchCreateBooks(BatchCreateBooksRequest) returns (BatchCreateBooksResponse) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books:batchCreate"
    body: "*"
  };
}
```

返回异步解析为响应的 Operation

```proto
rpc BatchCreateBooks(BatchCreateBooksRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books:batchCreate"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "BatchCreateBooksResponse"
    metadata_type: "BatchCreateBooksOperationMetadata"
  };
}
```

- RPC 的名称 **must** 以 `BatchCreate` 开头。RPC 名称的其余部分 **should** 为正在创建的资源的复数形式。
- 请求与响应 messages **must** 与 RPC 名称匹配，并带 `Request` 与 `Response` 后缀。
- 若 batch 方法返回 `google.longrunning.Operation`，`response_type` 与 `metadata_type` 字段都 **must** 指定。
- HTTP 动词 **must** 为 `POST`。
- HTTP URI **must** 以 `:batchCreate` 结尾。
- URI 路径 **should** 表示该资源的集合，与简单 CRUD 操作使用的集合匹配。若操作跨越 parents，**may** 接受短横线（`-`）作为通配符。
- `google.api.http` annotation 中的 body 子句 **should** 为 `"*"`。

### Atomic vs. Partial Success

- batch create 方法 **may** 支持原子（所有资源都创建或都不创建）或部分成功行为。做选择时考虑下列因素：
  - **确保原子性的复杂度：** 作为简单透传数据库事务的操作 **should** 使用原子操作，而管理复杂资源的操作 **should** 使用部分成功操作。
  - **最终用户体验：** 从 API 消费者的视角考虑。对该用例而言，即使意味着大批次可能因单个或少数条目的问题而失败，原子行为是否仍更可取？
- 同步 batch create **must** 是原子的。
- 异步 batch create **may** 支持原子或部分成功。
  - 若支持部分成功，见 [Operation metadata message](#operation-metadata-message) 要求。

### Request message

batch create 方法的请求 **should** 使用下列模式指定：

```proto
message BatchCreateBooksRequest {
  // The parent resource shared by all books being created.
  // Format: publishers/{publisher}
  // If this is set, the parent field in the CreateBookRequest messages
  // must either be empty or match this field.
  string parent = 1 [
    (google.api.resource_reference) = {
      child_type: "library.googleapis.com/Book"
    }];

  // The request message specifying the resources to create.
  // A maximum of 1000 books can be created in a batch.
  repeated CreateBookRequest requests = 2
    [(google.api.field_behavior) = REQUIRED];
}
```

- **should** 包含 `parent` 字段，除非正在创建的资源是顶层资源。若调用方设置此字段，且任何 child 请求 message 的 `parent` 字段不匹配，请求 **must** 失败。若本请求中的 `parent` 字段已设置，child 请求 messages 的 `parent` 字段可以省略。
  - 若每个请求只允许 1 个 parent，该字段 **should** 为必填。
  - 该字段 **should** 标识它所引用的 [resource type]({{< ref "aip-0122" >}})。
  - 该字段的注释 **should** 文档化资源 pattern。
- 请求 message **must** 包含一个 repeated 字段，接受指定要创建资源的请求 messages，如 [标准 Create methods]({{< ref "aip-0133" >}}) 所指定。该字段 **should** 名为 `requests`。
  - 该字段 **should** 为必填。
- 其它字段 **may** 从 [标准 Create 请求]({{< ref "aip-0133" >}})「提升」，意味着该字段可以在 batch 级或 child 请求级设置。与 `parent` 类似，若同一字段在 batch 级与 child 请求级都设置，值 **must** 匹配。
  - 必须唯一的字段不能提升（例如客户提供的 id 字段）。
- 请求 message **must not** 包含任何其它必填字段，并且 **should not** 包含其它可选字段，除非本文或另一篇 AIP 有描述。
- `requests` 字段上方的注释 **should** 文档化允许的最大请求数。

### Response message

batch create 方法的响应 **should** 使用下列模式指定：

```proto
message BatchCreateBooksResponse {
  // Books created.
  repeated Book books = 1;
}
```

- 响应 message **must** 包含一个对应已创建资源的 repeated 字段。

### Operation metadata message

- `metadata_type` message **must** 要么与 RPC 名称匹配并带 `OperationMetadata` 后缀，要么若该类型由多个 Batch methods 共享，则用 `Batch` 前缀与 `OperationMetadata` 后缀命名。
- 若 batch create 方法支持部分成功，metadata message **must** 包含 `map<int32, google.rpc.Status> failed_requests` 字段以传达部分失败。
  - 此 map 中的键是 batch 请求中 `requests` 字段里该请求的索引。
  - 每个 map 条目中的值 **must** 镜像单个标准 Create 方法通常会返回的错误。
  - 若失败请求可能因服务端重试最终成功，此类瞬时错误 **must not** 用 `failed_requests` 传达。
  - 当 batch 中所有请求都失败时，`Operation.error` **must** 设为 `code = google.rpc.Code.Aborted` 且 `message = "None of the requests succeeded, refer to the BatchCreateBooksOperationMetadata.failed_requests for individual error details"`
- metadata message **may** 包含其它字段以传达操作进度。

### Adopting Partial Success

现有 Batch API 要采用部分成功模式，必须做到下列事项：

- 必须保留默认行为，以避免不兼容的行为变更。
- 若 API 返回 Operation：
  - 请求 message **must** 有 `bool return_partial_success` 字段。
  - Operation `metadata_type` **must** 包含 `map<int32, google.rpc.Status> failed_requests` 字段。
  - 当请求中 `bool return_partial_success` 字段设为 true 时，API 应允许部分成功行为，否则应继续以原子行为为默认。
- 若 API 同步返回直接响应：
  - 由于现有客户端会把成功响应当作原子操作，现有版本的 API **must not** 采用部分成功模式。
  - 必须改为创建新版本，返回 Operation 并遵循本文描述的部分成功模式。

## Rationale

### Restricting synchronous batch methods to be atomic

限制同步 batch methods 必须原子，来自下列考虑。

本文先前迭代建议 batch methods 必须原子。同步响应状态码没有清晰方式传达部分失败，因为 OK 意味着全部成功。因此，向响应添加指示部分失败的新字段会是破坏性变更，因为现有客户端会把 OK 响应解释为所有资源都已创建。

另一方面，如 [AIP-193]({{< ref "aip-0193" >}}) 所述，Operations 更有能力呈现部分状态。Operation 的响应状态码不传达底层操作的结果，客户端必须检查响应体来确定操作是否成功。

### Communicating partial failures

本文建议使用 `map<int32, google.rpc.Status> failed_requests` 字段传达部分失败，其中键是原始 batch 请求中失败请求的索引。考虑过的其它选项：

- `repeated google.rpc.Status` 字段。被拒绝是因为不清楚哪个条目对应哪个请求。
- `map<string, google.rpc.Status>` 字段，键为失败请求的 request id。被拒绝是因为：
  - 客户端需要维护 request_id → request 的 map 才能使用部分成功响应。
  - 为传达错误而填充 request id 可能与 [AIP-155]({{< ref "aip-0155" >}}) 冲突，若服务无法保证单个请求跨多个 batch 请求的幂等性。
- `repeated FailedRequest` 字段，其中 FailedRequest 包含单个 create 请求与 `google.rpc.Status`。被拒绝是因为把请求 payload 回显到响应中不被鼓励，会带来用户数据敏感性方面的额外挑战。
