**英文标题**：Standard methods: Create  
**原文**：[AIP-133](https://google.aip.dev/133) · approved · 创建 2019-01-23 · 更新 2022-06-02  
**许可**：原文 © Google，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

在 REST APIs 中，习惯对集合的 URI（例如 `/v1/publishers/{publisher}/books`）发出 `POST` 请求，以在该集合内创建新资源。

面向资源的设计（[AIP-121]({{< ref "aip-0121" >}})）通过 `Create` 方法尊重此模式。这些 RPCs 接受 parent collection 与要创建的资源（以及可能的其它参数），并返回已创建的资源。

## Guidance

除非对用户没有价值，APIs **should** 一般为资源提供 create 方法。create 方法的目的是在已经存在的集合中创建新资源。

Create methods 使用下列模式指定：

```proto
rpc CreateBook(CreateBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books"
    body: "book"
  };
  option (google.api.method_signature) = "parent,book";
}
```

- RPC 的名称 **must** 以单词 `Create` 开头。RPC 名称的其余部分 **should** 为正在创建的资源的单数形式。
- 请求 message **must** 与 RPC 名称匹配，并带 `Request` 后缀。
- 响应 message **must** 为资源本身。没有 `CreateBookResponse`。
  - 响应 **should** 包含完全填充的资源，并且 **must** 包含所提供的任何字段，除非它们是 input only（见 [AIP-203]({{< ref "aip-0203" >}})）或有理由返回部分响应（见 [AIP-157]({{< ref "aip-0157" >}})）。
  - 若 create RPC 是 [长时运行的](#long-running-create)，响应 message **must** 为解析为资源本身的 `google.longrunning.Operation`。
- HTTP 动词 **must** 为 `POST`。
- 正在向其中添加资源的集合 **should** 映射到 URI 路径。
  - 集合的 parent 资源 **should** 称为 `parent`，并且 **should** 是 URI 路径中的唯一变量。
  - Collection identifier（上例中的 `books`）**must** 为字面字符串。
- `google.api.http` annotation 中 **must** 有 `body` 键，并且它 **must** 映射到请求 message 中的资源字段。
  - 其余字段 **should** 映射到 URI query parameters。
- **should** 恰好有一个 `google.api.method_signature` annotation，值为 `"parent,{resource},{resource}_id"`；若 resource ID 非必需，则为 `"parent,{resource}"`。
- 若 API 操作于 [management plane]({{< ref "aip-0111" >}})，该操作应具有 [强一致性]({{< ref "aip-0121" >}})：create 操作的完成 **must** 意味着所有用户可设置的值以及资源的存在都已达到稳态，并且读取资源状态返回一致响应。

### Request message

Create methods 实现一种常见的请求 message 模式：

```proto
message CreateBookRequest {
  // The parent resource where this book will be created.
  // Format: publishers/{publisher}
  string parent = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference) = {
      child_type: "library.googleapis.com/Book"
    }];

  // The ID to use for the book, which will become the final component of
  // the book's resource name.
  //
  // This value should be 4-63 characters, and valid characters
  // are /[a-z][0-9]-/.
  string book_id = 2 [(google.api.field_behavior) = REQUIRED];

  // The book to create.
  Book book = 3 [(google.api.field_behavior) = REQUIRED];
}
```

- 除非正在创建的资源是顶层资源，**must** 包含 `parent` 字段。它 **should** 称为 `parent`。
  - 该字段 **should** 被 [标注为 required]({{< ref "aip-0203" >}})。
  - 该字段 **must** 标识正在创建的资源的 [resource type]({{< ref "aip-0123" >}})。
- 对 management plane 资源 **must** 包含 `{resource}_id` 字段，对 data plane 资源 **should** 包含。
- 资源字段 **must** 包含，并且 **must** 映射到 POST body。
- 请求 message **must not** 包含任何其它必填字段，并且 **should not** 包含其它可选字段，除非本文或另一篇 AIP 有描述。

### Long-running create

有些资源创建所需时间超出常规 API 请求的合理范围。此时，API **should** 改用 long-running operation（AIP-151）：

```proto
rpc CreateBook(CreateBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books"
    body: "book"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- 响应类型 **must** 设为该资源（若 RPC 不是长时运行时的返回类型）。
- `response_type` 与 `metadata_type` 字段都 **must** 指定。

**Important:** 声明式友好资源（AIP-128）**should** 使用 long-running operations。若请求实际上是立即的，服务 **may** 返回已经设为 done 的 LRO。

### User-specified IDs

若 API 操作于 [management plane]({{< ref "aip-0111" >}})，API **must** 允许用户在创建时指定资源的 ID 分量（resource name 的最后一段）。

在 [data plane]({{< ref "aip-0111" >}}) 上，API **should** 允许用户指定 ID。例外情形应有下列行为：

- Data plane 资源允许相同记录，无需在两者之间消歧（例如没有主键的表中的行）。
- Data plane 资源不会在 [Declarative Clients]({{< ref "aip-0009" >}}) 中暴露。

API **may** 允许 `{resource}_id` 字段具有 [field_behavior]({{< ref "aip-0203" >}}) `OPTIONAL`，并在未指定时生成系统生成的 ID。

例如：

```
// Using user-specified IDs.
publishers/lacroix/books/les-miserables

// Using system-generated IDs.
publishers/012345678-abcd-cdef/books/12341234-5678-abcd
```

- `{resource}_id` 字段 **must** 存在于请求 message 上，而不是资源本身。
  - 该字段 **may** 为必填或可选。若为必填，它 **should** 包含相应 annotation。
- 资源上的 `name` 字段 **must** 被忽略。
- RPC 上 **should** 恰好有一个 `google.api.method_signature` annotation：若正在创建的资源不是顶层资源，值为 `"parent,{resource},{resource}_id"`；若是顶层资源，值为 `"{resource},{resource}_id"`。
- 文档 **should** 解释可接受的格式，并且该格式 **should** 遵循 [AIP-122]({{< ref "aip-0122" >}}) 中关于 resource name 格式的指导。
- 若用户试图用会导致重复 resource name 的 ID 创建资源，服务 **must** 以 `ALREADY_EXISTS` 报错。
  - 然而，若发出调用的用户没有查看该重复资源的权限，服务 **must** 改为以 `PERMISSION_DENIED` 报错。

**Note:** 对 REST APIs，用户指定的 ID 字段 `{resource}_id` 作为请求 URI 上的 query parameters 提供。

## Rationale

### 要求用户指定 ids

[Declarative Clients]({{< ref "aip-0009" >}}) 把 resource ID 用作标识资源以应用更新与解决冲突的方式。缺少用户指定的 ID 意味着除非客户端本地存储标识符，否则无法找到该资源，并可能导致重新创建该资源。这进而对所有引用它的资源产生下游影响，迫使它们更新为新创建资源的 ID。

有用户指定的 ID 也意味着客户端可以预先计算 resource name，并在其它资源的引用中使用它。
