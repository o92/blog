**英文标题**：Standard methods: Create  
**原文**：[AIP-133](https://google.aip.dev/133) · approved · 创建 2019-01-23 · 更新 2022-06-02  
**许可**：原文 © Google，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

用户要在已有集合里加一个新资源。Create 就是这条路：给 parent 和要创建的资源，拿回已创建的那一份。REST 里对应的是对集合 URI（例如 `/v1/publishers/{publisher}/books`）发 `POST`。面向资源的设计（见 [AIP-121]({{< ref "aip-0121" >}})）把这套语义收成 `Create` 方法。

## 怎么写

除非对用户没有价值，API 应当一般为资源提供 create。目的是在已经存在的集合中创建新资源。

模式如下：

```proto
rpc CreateBook(CreateBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books"
    body: "book"
  };
  option (google.api.method_signature) = "parent,book";
}
```

- RPC 名称必须以 `Create` 开头。其余部分应当是正在创建的资源的单数。
- 请求 message 必须与 RPC 名称匹配，并带 `Request` 后缀。
- 响应 message 必须是资源本身。没有 `CreateBookResponse`。
  - 响应应当包含完全填充的资源，并且必须包含所提供的任何字段，除非它们是 input only（见 [AIP-203]({{< ref "aip-0203" >}})）或有理由返回部分响应（见 [AIP-157]({{< ref "aip-0157" >}})）。
  - 若 create RPC 是长时运行的，响应必须是解析为该资源本身的 `google.longrunning.Operation`。
- HTTP 动词必须是 `POST`。
- 正在向其中添加资源的集合应当映射到 URI 路径。
  - 集合的 parent 应当叫 `parent`，并且应当是 URI 路径里唯一的变量。
  - Collection identifier（上例中的 `books`）必须是字面字符串。
- `google.api.http` annotation 中必须有 `body` 键，并且必须映射到请求里的资源字段。
  - 其余字段应当映射到 URI query parameters。
- 应当恰好有一个 `google.api.method_signature`，值为 `"parent,{resource},{resource}_id"`；若 resource ID 非必需，则为 `"parent,{resource}"`。
- 若 API 操作于 management plane（见 [AIP-111]({{< ref "aip-0111" >}})），该操作应具有强一致性（见 [AIP-121]({{< ref "aip-0121" >}})）：create 一旦完成，所有用户可设置的值以及资源的存在都必须已经达到稳态，再读资源状态必须得到一致响应。

### 请求 message

```proto
message CreateBookRequest {
  // The parent resource where this book will be created.
  // Format: publishers/{publisher}
  string parent = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference) = {
      child_type: "library.googleapis.com/Book"
    }];

  // The ID to use for the book, which will become the final component of
  // the book's resource name.
  //
  // This value should be 4-63 characters, and valid characters
  // are /[a-z][0-9]-/.
  string book_id = 2 [(google.api.field_behavior) = REQUIRED];

  // The book to create.
  Book book = 3 [(google.api.field_behavior) = REQUIRED];
}
```

- 除非正在创建的资源是顶层资源，必须包含 `parent`。应当叫 `parent`。
  - 该字段应当标为 required（见 [AIP-203]({{< ref "aip-0203" >}})）。
  - 该字段必须标明正在创建的资源的 resource type（见 [AIP-123]({{< ref "aip-0123" >}})）。
- management plane 资源必须包含 `{resource}_id` 字段；data plane 资源应当包含。
- 资源字段必须包含，并且必须映射到 POST body。
- 请求不得包含任何其它必填字段，也不应当包含其它可选字段，除非本文或另一篇 AIP 有描述。

### 长时运行的 create

有些资源创建所需时间超出常规 API 请求的合理范围。这时应当改用 long-running operation（见 [AIP-151]({{< ref "aip-0151" >}})）：

```proto
rpc CreateBook(CreateBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books"
    body: "book"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- 响应类型必须设为该资源（也就是 RPC 若不是长时运行时会返回的类型）。
- `response_type` 与 `metadata_type` 都必须指定。

声明式友好资源（见 [AIP-128]({{< ref "aip-0128" >}})）应当使用 long-running operations。若请求实际上是立即的，服务可以返回已经设为 done 的 LRO。

### 用户指定的 IDs

若 API 操作于 management plane（见 [AIP-111]({{< ref "aip-0111" >}})），创建时必须允许用户指定资源的 ID 分量（resource name 的最后一段）。

在 data plane（见 [AIP-111]({{< ref "aip-0111" >}})）上，应当允许用户指定 ID。例外应当满足：

- Data plane 资源允许相同记录，无需在两者之间消歧（例如没有主键的表中的行）。
- Data plane 资源不会在 Declarative Clients（见 [AIP-9]({{< ref "aip-0009" >}})）中暴露。

`{resource}_id` 可以标为 `OPTIONAL`（field_behavior，见 [AIP-203]({{< ref "aip-0203" >}})），未指定时由系统生成 ID。

例如：

```
// Using user-specified IDs.
publishers/lacroix/books/les-miserables

// Using system-generated IDs.
publishers/012345678-abcd-cdef/books/12341234-5678-abcd
```

- `{resource}_id` 必须在请求 message 上，而不是资源本身。
  - 该字段可以必填或可选。若必填，应当带相应 annotation。
- 资源上的 `name` 字段必须被忽略。
- RPC 上应当恰好有一个 `google.api.method_signature`：不是顶层资源时值为 `"parent,{resource},{resource}_id"`；是顶层资源时值为 `"{resource},{resource}_id"`。
- 文档应当解释可接受的格式，并且该格式应当遵循 [AIP-122]({{< ref "aip-0122" >}}) 关于 resource name 格式的指导。
- 用户试图用会导致重复 resource name 的 ID 创建时，服务必须以 `ALREADY_EXISTS` 报错。
  - 但若发出调用的用户没有查看该重复资源的权限，必须改为 `PERMISSION_DENIED`。

对 REST APIs，用户指定的 ID 字段 `{resource}_id` 作为请求 URI 上的 query parameters 提供。

### 错误

见 [AIP-193]({{< ref "aip-0193" >}})，尤其是何时用 PERMISSION_DENIED 与 NOT_FOUND。

## 延伸阅读

- 确保 `Create` 的幂等性，见 [AIP-155]({{< ref "aip-0155" >}})。
- 涉及 Unicode 的资源命名，见 [AIP-210]({{< ref "aip-0210" >}})。

## 为什么要用户指定 ids

Declarative Clients（见 [AIP-9]({{< ref "aip-0009" >}})）靠 resource ID 来找到资源、应用更新、解决冲突。没有用户指定的 ID，客户端除非本地存了标识符，否则找不到这个资源，还可能重新创建一份。所有引用它的资源都得跟着改 ID。

有用户指定的 ID，客户端还能预先算出 resource name，拿去填别的资源上的引用。
