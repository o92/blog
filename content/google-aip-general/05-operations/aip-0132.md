**英文标题**：Standard methods: List  
**原文**：[AIP-132](https://google.aip.dev/132) · approved · 创建 2019-01-21 · 更新 2022-06-02  
**许可**：原文 © Google，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

用户常常要看某个集合里有哪些资源。List 就是这条路：给 parent collection（以及可能的过滤、排序、分页），拿回匹配的列表。REST 里对应的是对集合 URI（例如 `/v1/publishers/1/books`）发 `GET`。面向资源的设计（见 [AIP-121]({{< ref "aip-0121" >}})）把这套语义收成 `List` 方法。

## 怎么写

除非资源是 singleton（见 [AIP-156]({{< ref "aip-0156" >}})），API 必须为资源提供 `List`。目的是从有限集合返回数据。一般是单个集合；支持跨集合读取时见 [AIP-159]({{< ref "aip-0159" >}})。

模式如下：

```proto
rpc ListBooks(ListBooksRequest) returns (ListBooksResponse) {
  option (google.api.http) = {
    get: "/v1/{parent=publishers/*}/books"
  };
  option (google.api.method_signature) = "parent";
}
```

- RPC 名称必须以 `List` 开头。其余部分应当是正在列出的资源的复数。
- 请求与响应 messages 必须与 RPC 名称匹配，并带 `Request` 与 `Response` 后缀。
- HTTP 动词必须是 `GET`。
- 正在列出其资源的集合应当映射到 URI 路径。
  - 集合的 parent 应当叫 `parent`，并且应当是 URI 路径里唯一的变量。其余参数应当映射到 URI query parameters。
  - Collection identifier（上例中的 `books`）必须是字面字符串。
- `google.api.http` annotation 中的 `body` 键必须省略。
- 被列出的资源不是顶层资源时，应当恰好有一个 `google.api.method_signature`，值为 `"parent"`。若是顶层资源，应当要么没有该 annotation，要么恰好有一个值为 `""` 的 annotation。

### 请求 message

List 用一套常见的请求形状：

```proto
message ListBooksRequest {
  // The parent, which owns this collection of books.
  // Format: publishers/{publisher}
  string parent = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference) = {
      child_type: "library.googleapis.com/Book"
    }];

  // The maximum number of books to return. The service may return fewer than
  // this value.
  // If unspecified, at most 50 books will be returned.
  // The maximum value is 1000; values above 1000 will be coerced to 1000.
  int32 page_size = 2;

  // A page token, received from a previous `ListBooks` call.
  // Provide this to retrieve the subsequent page.
  //
  // When paginating, all other parameters provided to `ListBooks` must match
  // the call that provided the page token.
  string page_token = 3;
}
```

- 除非被列出的资源是顶层资源，必须包含 `parent` 字段。应当叫 `parent`。
  - 该字段应当标为 required（见 [AIP-203]({{< ref "aip-0203" >}})）。
  - 该字段必须标明正在列出的资源的 resource type（见 [AIP-123]({{< ref "aip-0123" >}})）。
- 支持分页的 `page_size` 与 `page_token` 必须出现在所有 list 请求上。细节见 [AIP-158]({{< ref "aip-0158" >}})。
  - `page_size` 上方的注释应当写清允许的最大值，以及该字段省略（或设为 `0`）时的默认值。API 可以声明服务器将使用合理默认值。此默认值可以随时间变化。
  - 用户给的值大于允许最大值时，应当把该值强制为允许的最大值。
  - 用户给负数或其它无效值时，必须返回 `INVALID_ARGUMENT`。
- `page_token` 必须包含在所有 list 请求上。
- 请求可以包含与 list 相关的常见字段，例如 `string filter` 与 `string order_by`。
- 请求不得包含任何其它必填字段，也不应当包含其它可选字段，除非本文或另一篇 AIP 有描述。

对任何有权限对集合发出成功 List 请求的用户，List 应当返回相同结果。Search 在这一点上更宽松。

### 响应 message

```proto
message ListBooksResponse {
  // The books from the specified publisher.
  repeated Book books = 1;

  // A token, which can be sent as `page_token` to retrieve the next page.
  // If this field is omitted, there are no subsequent pages.
  string next_page_token = 2;
}
```

- 响应必须包含一个对应所返回资源的 repeated 字段，并且不应当包含任何其它 repeated 字段，除非另一篇 AIP 有描述（例如 [AIP-217]({{< ref "aip-0217" >}})）。
  - 除非有理由返回部分响应（见 [AIP-157]({{< ref "aip-0157" >}})），响应应当通常包含完全填充的资源。
- 支持分页的 `next_page_token` 必须出现在所有 list 响应上。有后续页时必须设置；这是最后一页时不得设置。细节见 [AIP-158]({{< ref "aip-0158" >}})。
- 该 message 可以包含 `int32 total_size`（或 `int64 total_size`），表示集合中的条目数。
  - 该值可以是估计值（若如此，字段应当写清楚）。
  - 若用了过滤，`total_size` 应当反映 *应用过滤器之后* 的集合大小。

### 排序

`List` 可以允许客户端指定排序。若如此，请求应当包含 `string order_by`。

- 值应当是逗号分隔的字段列表。例如：`"foo,bar"`。
- 默认升序。某字段要降序，用户加 `" desc"` 后缀；例如：`"foo desc, bar"`。
- 语法里多余的空格无意义。`"foo, bar desc"`、`" foo , bar desc "` 与 `"foo,bar desc"` 都等价。
- 子字段用 `.` 指定，例如 `foo.bar` 或 `address.street`。
- 结果顺序应当基于字段类型的自然比较器：数值按数值、字符串按字典序。API 可以选择不同排序；若如此，必须在 `order_by` 定义里写清。
  - [well-known](https://protobuf.dev/reference/protobuf/google.protobuf) 类型按其代表类型比较：`Timestamp` 按时间（先或后），`Duration` 按量（多或少）。

只有既定需要时才加排序。以后随时可以加；拿掉是破坏性变更。

### 过滤

List 可以允许客户端指定过滤器。若如此，请求应当包含 `string filter`。过滤细节见 [AIP-160]({{< ref "aip-0160" >}})。

只有既定需要时才加过滤。以后随时可以加；拿掉是破坏性变更。

### 软删除的资源

有些 API 做 soft delete（见 [AIP-135]({{< ref "aip-0135" >}})）：把资源标为已删除或待删除，并可选择稍后清除。

这样做的 API 不应当默认在 list 里带上已删除资源。应当在 list 请求里加 `bool show_deleted`；设了才包含软删除的资源。

### 错误

见 [AIP-193]({{< ref "aip-0193" >}})，尤其是何时用 PERMISSION_DENIED 与 NOT_FOUND。
