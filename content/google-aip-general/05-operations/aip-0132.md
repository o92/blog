**英文标题**：Standard methods: List  
**原文**：[AIP-132](https://google.aip.dev/132) · approved · 创建 2019-01-21 · 更新 2022-06-02  
**许可**：原文 © Google，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

在许多 APIs 中，习惯对集合的 URI（例如 `/v1/publishers/1/books`）发出 `GET` 请求，以检索该集合内的资源列表。

面向资源的设计（[AIP-121]({{< ref "aip-0121" >}})）通过 `List` 方法尊重此模式。这些 RPCs 接受 parent collection（以及可能的其它参数），并返回匹配该输入的响应列表。

## Guidance

除非资源是 [singleton]({{< ref "aip-0156" >}})，APIs **must** 为资源提供 `List` 方法。`List` 方法的目的是从有限集合返回数据（一般是单个集合，除非该操作支持 [跨集合读取]({{< ref "aip-0159" >}})）。

List methods 使用下列模式指定：

```proto
rpc ListBooks(ListBooksRequest) returns (ListBooksResponse) {
  option (google.api.http) = {
    get: "/v1/{parent=publishers/*}/books"
  };
  option (google.api.method_signature) = "parent";
}
```

- RPC 的名称 **must** 以单词 `List` 开头。RPC 名称的其余部分 **should** 为正在列出的资源的复数形式。
- 请求与响应 messages **must** 与 RPC 名称匹配，并带 `Request` 与 `Response` 后缀。
- HTTP 动词 **must** 为 `GET`。
- 正在列出其资源的集合 **should** 映射到 URI 路径。
  - 集合的 parent 资源 **should** 称为 `parent`，并且 **should** 是 URI 路径中的唯一变量。其余参数 **should** 映射到 URI query parameters。
  - Collection identifier（上例中的 `books`）**must** 为字面字符串。
- `google.api.http` annotation 中的 `body` 键 **must** 省略。
- 若被列出的资源不是顶层资源，**should** 恰好有一个 `google.api.method_signature` annotation，值为 `"parent"`。若被列出的资源是顶层资源，**should** 要么没有 `google.api.method_signature` annotation，要么恰好有一个值为 `""` 的 `google.api.method_signature` annotation。

### Request message

List methods 实现一种常见的请求 message 模式：

```proto
message ListBooksRequest {
  // The parent, which owns this collection of books.
  // Format: publishers/{publisher}
  string parent = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference) = {
      child_type: "library.googleapis.com/Book"
    }];

  // The maximum number of books to return. The service may return fewer than
  // this value.
  // If unspecified, at most 50 books will be returned.
  // The maximum value is 1000; values above 1000 will be coerced to 1000.
  int32 page_size = 2;

  // A page token, received from a previous `ListBooks` call.
  // Provide this to retrieve the subsequent page.
  //
  // When paginating, all other parameters provided to `ListBooks` must match
  // the call that provided the page token.
  string page_token = 3;
}
```

- 除非被列出的资源是顶层资源，**must** 包含 `parent` 字段。它 **should** 称为 `parent`。
  - 该字段 **should** 被 [标注为 required]({{< ref "aip-0203" >}})。
  - 该字段 **must** 标识正在列出的资源的 [resource type]({{< ref "aip-0123" >}})。
- 支持分页的 `page_size` 与 `page_token` 字段 **must** 在所有 list 请求 messages 上指定。更多信息见 [AIP-158]({{< ref "aip-0158" >}})。
  - `page_size` 字段上方的注释 **should** 文档化允许的最大值，以及该字段省略（或设为 `0`）时的默认值。若愿意，API **may** 声明服务器将使用合理的默认值。此默认值 **may** 随时间变化。
  - 若用户提供大于允许最大值的值，API **should** 把该值强制为允许的最大值。
  - 若用户提供负数或其它无效值，API **must** 发送 `INVALID_ARGUMENT` 错误。
- `page_token` 字段 **must** 包含在所有 list 请求 messages 上。
- 请求 message **may** 包含与 list methods 相关的常见设计模式字段，例如 `string filter` 与 `string order_by`。
- 请求 message **must not** 包含任何其它必填字段，并且 **should not** 包含其它可选字段，除非本文或另一篇 AIP 有描述。

**Note:** 对任何有权限对集合发出成功 List 请求的用户，List methods **should** 返回相同结果。Search methods 在这一点上更宽松。

### Response message

List methods 实现一种常见的响应 message 模式：

```proto
message ListBooksResponse {
  // The books from the specified publisher.
  repeated Book books = 1;

  // A token, which can be sent as `page_token` to retrieve the next page.
  // If this field is omitted, there are no subsequent pages.
  string next_page_token = 2;
}
```

- 响应 message **must** 包含一个对应所返回资源的 repeated 字段，并且 **should not** 包含任何其它 repeated 字段，除非另一篇 AIP 有描述（例如 [AIP-217]({{< ref "aip-0217" >}})）。
  - 除非有理由返回部分响应（见 AIP-157），响应 **should** 通常包含完全填充的资源。
- 支持分页的 `next_page_token` 字段 **must** 包含在所有 list 响应 messages 上。若有后续页，它 **must** 被设置；若该响应代表最后一页，它 **must not** 被设置。更多信息见 AIP-158。
- 该 message **may** 包含 `int32 total_size`（或 `int64 total_size`）字段，表示集合中的条目数。
  - 该值 **may** 是估计值（若如此，字段 **should** 清楚文档化）。
  - 若使用了过滤，`total_size` 字段 **should** 反映 *应用过滤器之后* 的集合大小。

### Ordering

`List` methods **may** 允许客户端指定排序；若如此，请求 message **should** 包含 `string order_by` 字段。

- 值 **should** 为逗号分隔的字段列表。例如：`"foo,bar"`。
- 默认排序为升序。要为某字段指定降序，用户附加 `" desc"` 后缀；例如：`"foo desc, bar"`。
- 语法中多余的空格字符无意义。`"foo, bar desc"`、`" foo , bar desc "` 与 `"foo,bar desc"` 都等价。
- 子字段用 `.` 字符指定，例如 `foo.bar` 或 `address.street`。
- 结果列表顺序 **should** 基于字段类型的自然比较器，例如数值按数值排序、字符串按字典序排序等。然而 APIs **may** 选择使用不同排序；若如此，**must** 在 `order_by` 定义中文档化。
  - 此外，[well-known](https://protobuf.dev/reference/protobuf/google.protobuf) 类型如 `Timestamp` 与 `Duration` 按其代表类型比较；`Timestamp` 按时间比较（例如先或后），`Duration` 按量比较（例如多或少）。

**Note:** 仅在有既定需要时才包含排序。以后总可以加上排序，但去掉它是破坏性变更。

### Filtering

List methods **may** 允许客户端指定过滤器；若如此，请求 message **should** 包含 `string filter` 字段。过滤在 [AIP-160]({{< ref "aip-0160" >}}) 中有更详细描述。

**Note:** 仅在有既定需要时才包含过滤。以后总可以加上过滤，但去掉它是破坏性变更。

### Soft-deleted resources

有些 APIs 需要「[soft delete]({{< ref "aip-0135" >}})」资源，把它们标为已删除或待删除（并可选择稍后清除）。

这样做的 APIs **should not** 默认在 list 请求中包含已删除资源。带资源软删除的 APIs **should** 在 list 请求中包含 `bool show_deleted` 字段；若设置，将导致包含软删除的资源。
