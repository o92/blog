**英文标题**：Standard methods: Delete  
**原文**：[AIP-135](https://google.aip.dev/135) · approved · 创建 2019-01-24 · 更新 2022-06-02  
**许可**：原文 © Google，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

在 REST APIs 中，习惯对资源的 URI（例如 `/v1/publishers/{publisher}/books/{book}`）发出 `DELETE` 请求以删除该资源。

面向资源的设计（[AIP-121]({{< ref "aip-0121" >}})）通过 `Delete` 方法尊重此模式。这些 RPCs 接受表示该资源的 URI，通常返回空响应。

## Guidance

除非对用户没有价值，APIs **should** 一般为资源提供 delete 方法。

Delete methods 使用下列模式指定：

```proto
rpc DeleteBook(DeleteBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    delete: "/v1/{name=publishers/*/books/*}"
  };
  option (google.api.method_signature) = "name";
}
```

- RPC 的名称 **must** 以单词 `Delete` 开头。RPC 名称的其余部分 **should** 为该资源 message 名称的单数形式。
- 请求 message **must** 与 RPC 名称匹配，并带 `Request` 后缀。
- 响应 message **should** 为 `google.protobuf.Empty`。
  - 若资源被 [软删除](#soft-delete)，响应 message **should** 为资源本身。
  - 若 delete RPC 是 [长时运行的](#long-running-delete)，响应 message **must** 为解析为正确响应的 `google.longrunning.Operation`。
- HTTP 动词 **must** 为 `DELETE`。
- 接收 resource name 的请求 message 字段 **should** 映射到 URI 路径。
  - 该字段 **should** 称为 `name`。
  - `name` 字段 **should** 是 URI 路径中的唯一变量。其余参数 **should** 映射到 URI query parameters。
- `google.api.http` annotation 中 **must not** 有 `body` 键。
- **should** 恰好有一个 `google.api.method_signature` annotation，值为 `"name"`。若使用 etag 或 force 字段，它们 **may** 包含在 signature 中。
- 若 API 操作于 Management Plane（[AIP-111]({{< ref "aip-0111" >}})），该操作应具有强一致性（[AIP-121]({{< ref "aip-0121" >}})）：delete 操作的完成 **must** 意味着资源的存在已达到稳态，并且读取资源状态返回一致响应。
- 若存在 child resources，API **must** 以 `FAILED_PRECONDITION` 错误失败。若需要强制删除 parent 与 child resources，见 [Cascading Delete](#cascading-delete) 指导。
  - 若唯一的 child resource type 是 Singleton（[AIP-156]({{< ref "aip-0156" >}})），则 **must** 允许删除，因为 Singleton 的生命周期与其 parent resource 绑定。即使同一 parent resource 有多个不同 Singleton resource types，也适用。

当且仅当资源存在且被成功删除时，Delete 方法 **should** 成功。若资源不存在，该方法 **should** 发送 `NOT_FOUND` 错误。

### Request message

Delete methods 实现一种常见的请求 message 模式：

```proto
message DeleteBookRequest {
  // The name of the book to delete.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference) = {
      type: "library.googleapis.com/Book"
    }];
}
```

- **must** 包含 `name` 字段。它 **should** 称为 `name`。
  - 该字段 **should** 被标注为 required（[AIP-203]({{< ref "aip-0203" >}})）。
  - 该字段 **must** 标识它所引用的 resource type（[AIP-123]({{< ref "aip-0123" >}})）。
- 该字段的注释 **should** 文档化资源 pattern。
- 请求 message **must not** 包含任何其它必填字段，并且 **should not** 包含其它可选字段，除非本文或另一篇 AIP 有描述。

### Long-running delete

有些资源删除所需时间超出常规 API 请求的合理范围。此时，API **should** 改用 long-running operation：

```proto
rpc DeleteBook(DeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    delete: "/v1/{name=publishers/*/books/*}"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
}
```

- 响应类型 **must** 设为若 RPC 不是长时运行时的适当返回类型：大多数 Delete RPCs 为 `google.protobuf.Empty`，软删除（[AIP-164]({{< ref "aip-0164" >}})）则为资源本身。
- `response_type` 与 `metadata_type` 字段都 **must** 指定（即使它们是 `google.protobuf.Empty`）。

### Cascading delete

有时用户需要能够删除一个资源及其所有适用的 child resources。然而，由于删除通常是永久的，用户也不应意外这样做，因为重建被抹掉的 child resources 可能相当困难。

若 API 允许删除可能有 child resources 的资源，API **should** 在请求上提供 `bool force` 字段，由用户设置以显式选择级联删除。

```proto
message DeletePublisherRequest {
  // The name of the publisher to delete.
  // Format: publishers/{publisher}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference) = {
      type: "library.googleapis.com/Publisher"
    }];

  // If set to true, any books from this publisher will also be deleted.
  // (Otherwise, the request will only work if the publisher has no books.)
  bool force = 2;
}
```

若 `force` 字段为 `false`（或未设置）且存在 child resources，API **must** 以 `FAILED_PRECONDITION` 错误失败。

### Protected delete

有时用户需要确保被删除的资源没有发生任何变更。若资源提供 etag（[AIP-134]({{< ref "aip-0134" >}})），delete 请求 **may** 接受 etag（作为 required 或 optional）：

```proto
message DeleteBookRequest {
  // The name of the book to delete.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference) = {
      type: "library.googleapis.com/Book"
    }];

  // Optional. The etag of the book.
  // If this is provided, it must match the server's etag.
  string etag = 2;
}
```

若提供了 etag 且与服务器计算的 etag 不匹配，请求 **must** 以 `ABORTED` 错误码失败。

**Note:** 声明式友好资源（[AIP-128]({{< ref "aip-0128" >}})）**must** 为 Delete 请求提供 `etag` 字段。

### Delete if existing

若服务使用客户端分配的 resource names，`Delete` methods **may** 暴露 `bool allow_missing` 字段：用户试图删除不存在的资源时该方法会成功（此时请求为 no-op）：

```proto
message DeleteBookRequest {
  // The book to delete.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];

  // If set to true, and the book is not found, the request will succeed
  // but no action will be taken on the server
  bool allow_missing = 2;
}
```

更具体地，`allow_missing` 标志触发下列行为：

- 若方法调用针对不存在的资源，则请求为 no-op。
  - `etag` 字段被忽略。
- 若方法调用针对已存在的资源，则删除该资源（受其它检查约束）。

**Note:** 声明式友好资源（[AIP-128]({{< ref "aip-0128" >}})）**should** 暴露 `bool allow_missing` 字段。

### Errors

若用户没有访问该资源的权限，无论它是否存在，服务 **must** 以 `PERMISSION_DENIED`（HTTP 403）报错。**must** 在检查资源是否存在之前检查权限。

若用户确有适当权限，但所请求的资源不存在，则除非 `allow_missing` 设为 `true`，服务 **must** 以 `NOT_FOUND`（HTTP 404）报错。
