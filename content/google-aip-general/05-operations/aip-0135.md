**英文标题**：Standard methods: Delete  
**原文**：[AIP-135](https://google.aip.dev/135) · approved · 创建 2019-01-24 · 更新 2022-06-02  
**许可**：原文 © Google，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

用户要删掉一个资源。Delete 就是这条路：给 resource name，通常拿回空响应。REST 里对应的是对资源 URI（例如 `/v1/publishers/{publisher}/books/{book}`）发 `DELETE`。面向资源的设计（见 [AIP-121]({{< ref "aip-0121" >}})）把这套语义收成 `Delete` 方法。

## 怎么写

除非对用户没有价值，API 应当一般为资源提供 delete。

模式如下：

```proto
rpc DeleteBook(DeleteBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    delete: "/v1/{name=publishers/*/books/*}"
  };
  option (google.api.method_signature) = "name";
}
```

- RPC 名称必须以 `Delete` 开头。其余部分应当是该资源 message 名称的单数。
- 请求 message 必须与 RPC 名称匹配，并带 `Request` 后缀。
- 响应 message 应当是 `google.protobuf.Empty`。
  - 若资源被软删除，响应应当是资源本身。
  - 若 delete RPC 是长时运行的，响应必须是解析为正确响应的 `google.longrunning.Operation`。
- HTTP 动词必须是 `DELETE`。
- 接收 resource name 的请求字段应当映射到 URI 路径。
  - 该字段应当叫 `name`。
  - `name` 应当是 URI 路径里唯一的变量。其余参数应当映射到 URI query parameters。
- `google.api.http` annotation 中不得有 `body` 键。
- 应当恰好有一个 `google.api.method_signature`，值为 `"name"`。若使用 etag 或 force 字段，可以把它们放进 signature。
- 若 API 操作于 Management Plane（见 [AIP-111]({{< ref "aip-0111" >}})），该操作应具有强一致性（见 [AIP-121]({{< ref "aip-0121" >}})）：delete 一旦完成，资源的存在必须已经达到稳态，再读资源状态必须得到一致响应。
- 若存在 child resources，API 必须以 `FAILED_PRECONDITION` 失败。需要强制删除 parent 与 child 时，见下文级联删除。
  - 若唯一的 child resource type 是 Singleton（见 [AIP-156]({{< ref "aip-0156" >}})），则必须允许删除：Singleton 的生命周期绑在 parent 上。即使同一 parent 下有多个不同 Singleton 类型，也适用。

当且仅当资源存在且被成功删除时，Delete 应当成功。资源不存在时，应当返回 `NOT_FOUND`。

### 请求 message

```proto
message DeleteBookRequest {
  // The name of the book to delete.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference) = {
      type: "library.googleapis.com/Book"
    }];
}
```

- 必须包含 `name` 字段。应当叫 `name`。
  - 该字段应当标为 required（见 [AIP-203]({{< ref "aip-0203" >}})）。
  - 该字段必须标明它所引用的 resource type（见 [AIP-123]({{< ref "aip-0123" >}})）。
- 该字段的注释应当写清资源 pattern。
- 请求不得包含任何其它必填字段，也不应当包含其它可选字段，除非本文或另一篇 AIP 有描述。

### 长时运行的 delete

有些资源删除所需时间超出常规 API 请求的合理范围。这时应当改用 long-running operation：

```proto
rpc DeleteBook(DeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    delete: "/v1/{name=publishers/*/books/*}"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
}
```

- 响应类型必须设为 RPC 若不是长时运行时的适当返回类型：大多数 Delete 是 `google.protobuf.Empty`，软删除（见 [AIP-164]({{< ref "aip-0164" >}})）则是资源本身。
- `response_type` 与 `metadata_type` 都必须指定（即使它们是 `google.protobuf.Empty`）。

### 级联删除

有时用户需要删掉一个资源以及它所有适用的 child。删除通常是永久的，用户不该一不小心就把 child 抹掉——重建往往很难。

若 API 允许删除可能有 child 的资源，应当在请求上提供 `bool force`，由用户显式选择级联删除。

```proto
message DeletePublisherRequest {
  // The name of the publisher to delete.
  // Format: publishers/{publisher}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference) = {
      type: "library.googleapis.com/Publisher"
    }];

  // If set to true, any books from this publisher will also be deleted.
  // (Otherwise, the request will only work if the publisher has no books.)
  bool force = 2;
}
```

若 `force` 为 `false`（或未设置）且存在 child resources，API 必须以 `FAILED_PRECONDITION` 失败。

### 带保护的删除

有时用户要确保被删的资源期间没有发生任何变更。若资源提供 etag（见 [AIP-134]({{< ref "aip-0134" >}})），delete 请求可以接受 etag（required 或 optional）：

```proto
message DeleteBookRequest {
  // The name of the book to delete.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference) = {
      type: "library.googleapis.com/Book"
    }];

  // Optional. The etag of the book.
  // If this is provided, it must match the server's etag.
  string etag = 2;
}
```

若提供了 etag 且与服务器计算的 etag 不匹配，请求必须以 `ABORTED` 失败。

声明式友好资源（见 [AIP-128]({{< ref "aip-0128" >}})）必须为 Delete 请求提供 `etag` 字段。

### 资源不存在也当成功

若服务使用客户端分配的 resource names，`Delete` 可以暴露 `bool allow_missing`：用户删除不存在的资源时该方法会成功（此时请求是 no-op）：

```proto
message DeleteBookRequest {
  // The book to delete.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];

  // If set to true, and the book is not found, the request will succeed
  // but no action will be taken on the server
  bool allow_missing = 2;
}
```

`allow_missing` 触发的行为：

- 针对不存在的资源时，请求是 no-op。
  - `etag` 字段被忽略。
- 针对已存在的资源时，删除该资源（仍受其它检查约束）。

声明式友好资源（见 [AIP-128]({{< ref "aip-0128" >}})）应当暴露 `bool allow_missing`。

### 错误

若用户没有访问该资源的权限，无论它是否存在，服务必须以 `PERMISSION_DENIED`（HTTP 403）报错。必须在检查资源是否存在之前先检查权限。

若用户确有适当权限，但所请求的资源不存在，则除非 `allow_missing` 设为 `true`，服务必须以 `NOT_FOUND`（HTTP 404）报错。
