**英文标题**：Beta-blocking changes  
**原文**：[AIP-205](https://google.aip.dev/205) · approved · 创建 2019-02-18 · 亦见 [aip.dev/beta-blocker](https://google.aip.dev/beta-blocker)

API 常常先发布 API 的 Alpha 版本，以便尽早从客户那里收集反馈。该 API 是临时的，在重要反馈被纳入、API 为 Beta 而稳定下来之前，可以变更多次。

既然 Alpha 的目的是收集反馈，API 此时不必完美，API 作者也并非严格必须处理每一个可用性关切或 API 标准中的每一点。API 作者与 API reviewers 常常无法就最佳设计达成一致，而找出答案的最好办法就是让用户试用该 API。

然而，一旦反馈已收集、API 将升到 Beta，可用性关切与文体问题就必须处理。为确保这些问题不被忘记，它们应在 API 中显式记录。

## Guidance

若某 API 存在可用性关切或违反 API 标准，且当前设计在带到 Beta 版本之前应再受审视，则 **must** 有一条内部注释，用其描述性链接（[aip.dev/beta-blocker](https://google.aip.dev/beta-blocker)）指向本文，以确保在 API 发布到 Beta 之前该设计得到纠正。

该注释 **must** 同时标明 Beta 应做何种变更。例如：

```proto
message InputConfig {
  // Parameters for input.
  // (-- aip.dev/beta-blocker: Convert well-known parameters into explicit
  //     fields before the Beta launch. --)
  map<string, string> parameters = 1;
}
```

若对 API 标准的例外**确实**需要带到 Beta 与 GA，见 [AIP-200]({{< ref "aip-0200" >}})。
