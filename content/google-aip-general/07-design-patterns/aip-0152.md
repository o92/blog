有些任务耗时长，但瞬时的 long-running operation（见 [AIP-151]({{< ref "aip-0151" >}})）并不合适。典型场景：任务要反复跑，或者「配任务」和「跑任务」权限要拆开。这时可以单独暴露一个 `Job` 资源。

## 什么时候用 Job

API 可以定义 `Job` 资源，表示一项有明确 setup、configuration 与 execution 的任务：

```proto
message WriteBookJob {
  option (google.api.resource) = {
    type: "library.googleapis.com/WriteBookJob"
    pattern: "publishers/{publisher}/writeBookJobs/{write_book_job}"
  };

  // Name and other fields...
}
```

- 资源名称必须以单词 `Job` 结尾。
- 前缀应当是有效的 RPC 名称：一个动词加一个名词。
- 服务应当提供全部五个标准方法（见 [AIP-131]({{< ref "aip-0131" >}}) 到 [AIP-135]({{< ref "aip-0135" >}})），并把它们当作配置该 job 的主要方式。

## Run

服务应当定义一个立刻执行该 job 的 `Run` custom method：

```proto
rpc RunWriteBookJob(RunWriteBookJobRequest)
    returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/writeBookJobs/*}:run"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "RunWriteBookJobResponse"
    metadata_type: "RunWriteBookJobMetadata"
  };
}
```

- RPC 名称必须以 `Run` 开头。其余部分应当是正在运行的 job 资源的单数形式。
- 请求 message 必须与 RPC 名称匹配，并带 `Request` 后缀。
- 该方法应当返回 long-running operation（见 [AIP-151]({{< ref "aip-0151" >}})）。operation 必须解析为包含这次运行结果的响应 message。
  - 响应 message 名称必须与 RPC 名称匹配，并带 `Response` 后缀。
  - metadata message 可以按需要自定。
- HTTP 动词必须为 `POST`，和 custom methods 通常一样（见 [AIP-136]({{< ref "aip-0136" >}})）。
- `google.api.http` annotation 里的 body 子句应当为 `"*"`。
- URI 路径应当包含单个 `name` 变量，对应正在运行的 job 资源名称。
- URI 路径必须以 `:run` 结尾。
- 阻止 job 执行*启动*的错误必须返回错误响应（见 [AIP-193]({{< ref "aip-0193" >}})），和其他方法一样。执行过程中发生的错误可以放在 metadata message 里。错误本身仍必须用 [`google.rpc.Status`](https://github.com/googleapis/googleapis/blob/master/google/rpc/status.proto) 对象表示。

## Run 请求

`Run` 用一套常见的请求 message 模式：

```proto
message RunWriteBookJobRequest {
  // The name of the job to run.
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference) = {
      type: "library.googleapis.com/WriteBookJob"
    }];
}
```

- 必须包含单数 `string name` 字段。
- 该字段应当标注为 required（见 [AIP-203]({{< ref "aip-0203" >}})）。
- 该字段应当标识它所引用的 resource type（见 [AIP-123]({{< ref "aip-0123" >}})）。

## 执行记录与结果

通常，应当把结果作为 `Run` 的最终响应交给用户。有时不够：后台按重复调度跑的 job，没法用这一次响应把结果交出去。

服务可以把个别 executions 及其结果存成该 job 下的子集合，让用户列出过去的 job executions。这样做时，应当为 execution 资源定义 `Get`、`List` 与 `Delete`：

```proto
message WriteBookJobExecution {
  option (google.api.resource) = {
    type: "library.googleapis.com/WriteBookJobExecution"
    pattern: "publishers/{publisher}/writeBookJobs/{write_book_job}/executions/{execution}"
  };

  // Name and other information about the execution, such as metadata, the
  // result, error information, etc.
}
```

此时，job 的 `Run` 返回的 operation 应当引用这个 child resource。
