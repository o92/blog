常常，在列出资源时（使用 [AIP-132]({{< ref "aip-0132" >}}) 中定义的 list 方法或某种合理类似的方法），希望过滤集合并只返回用户感兴趣的结果。

为每个 API 的精确过滤需求定义结构很诱人。然而，过滤要求频繁演进，因此明智的做法是使用带结构化语法、非技术受众也能访问的字符串字段。这允许透明地更新，而无需等待 UI 或客户端更新。

**Note:** 因为 list filters 面向潜在非技术受众，它们有时借用口语模式，而不是代码中常见的模式。

## Guidance

APIs **may** 在 `List` 方法（或查询集合的类似方法，例如 `Search`）上向用户提供过滤。若选择这样做，它们 **should** 遵循此处讨论的过滤器通用规范。语法在 [EBNF grammar](https://google.aip.dev/assets/misc/ebnf-filtering.txt) 中正式定义。

采用过滤时，请求 message **should** 恰好有一个过滤字段 `string filter`。相关对象的过滤通过 [traversal](#traversal-operator) 或 [functions](#functions) 处理。

**Note:** List Filters 具有模糊匹配特征，并支持结果排名与打分。对确定性求值 list filters 感兴趣的开发者，见 [CEL](https://github.com/google/cel-spec)。

### Literals

裸字面值（例如："42"、"Hugo"）是要匹配的值。单独出现（没有指定字段）的字面量 **should** 通常在对象字段值中任何可能出现的地方匹配。

然而，服务 **may** 选择只考虑某些字段；若如此，它 **must** 文档化它考虑哪些字段。服务 **may** 随时间包含新字段，但 **should** 审慎这样做并考虑对现有用户的影响。

**Note:** 被空白分隔的字面量被视为 `AND` 的模糊变体。因此，`Victor Hugo` 大致等价于 `Victor AND Hugo`。

### Logical Operators

过滤实现 **should** 提供二元运算符：

| 运算符 | 示例 | 含义 |
|--|--|--|
| `AND` | `a AND b` | 若 `a` 与 `b` 为真则为真。 |
| `OR` | `a OR b OR c` | 若 `a`、`b`、`c` 任一为真则为真。 |

**Note:** 为匹配常见口语模式，`OR` 运算符的优先级高于 `AND`，与大多数编程语言不同。表达式 `a AND b OR c` 求值为：`a AND (b OR c)`。API 文档与示例 **should** 鼓励使用显式括号以避免困惑，但 **should not** 要求显式括号。

### Negation Operators

过滤实现 **should** 提供一元运算符 `NOT` 与 `-`。它们可互换使用，支持否定的服务 **must** 支持两种格式。

| 运算符 | 示例 | 含义 |
|--|--|--|
| `NOT` | `NOT a` | 若 `a` 不为真则为真。 |
| `-` | `-a` | 若 `a` 不为真则为真。 |

### Comparison Operators

过滤实现 **should** 为 string、numeric、timestamp 与 duration 字段提供二元比较运算符 `=`、`!=`、`<`、`>`、`<=` 与 `>=`（但 **should not** 为布尔或 enums 提供它们）。

| 运算符 | 示例 | 含义 |
|--|--|--|
| `=` | `a = true` | 若 `a` 为真则为真。 |
| `!=` | `a != 42` | 除非 `a` 等于 42 则为真。 |
| `<` | `a < 42` | 若 `a` 为低于 42 的数值则为真。 |
| `>` | `a > "foo"` | 若 `a` 在词典序上排在 "foo" 之后则为真。 |
| `<=` | `a <= "foo"` | 若 `a` 为 "foo" 或在词典序上在它之前则为真。 |
| `>=` | `a >= 42` | 若 `a` 为 42 或更高的数值则为真。 |

**Note:** 与大多数编程语言不同，字段名 **must** 出现在比较运算符的左侧；右侧只接受字面量与逻辑运算符。

因为过滤器作为 query strings 接受，会发生类型转换以把字符串翻译为适当的强类型值：

- Enums 期望 enum 的字符串表示（大小写敏感）。
- Booleans 期望 `true` 与 `false` 字面值。
- Numbers 期望标准整数或浮点表示。对 floats，支持指数（例如 `2.997e9`）。
- [Durations](https://github.com/protocolbuffers/protobuf/blob/master/src/google/protobuf/duration.proto) 期望后跟 `s` 后缀（表示秒）的数值表示。例如：`20s`、`1.2s`。
- [Timestamps](https://github.com/protocolbuffers/protobuf/blob/master/src/google/protobuf/timestamp.proto) 期望 [RFC-3339](https://tools.ietf.org/html/rfc3339) 格式的字符串（例如 `2012-04-21T11:30:00-04:00`）。支持 UTC 偏移。

**Warning:** 标识符 `true`、`false` 与 `null` 仅在类型化字段引用的语境中才带有内在含义。

此外，比较字符串相等时，服务 **should** 支持使用 `*` 字符的通配符；例如，若 `a` *以* ".foo" 结尾，则 `a = "*.foo"` 为真。

### Traversal operator

过滤实现 **should** 提供 `.` 运算符，它表示穿过 message、map 或 struct 的遍历。

| 示例 | 含义 |
|--|--|
| `a.b = true` | 若 `a` 有为真的布尔 `b` 字段则为真。 |
| `a.b > 42` | 若 `a` 有高于 42 的数值 `b` 字段则为真。 |
| `a.b.c = "foo"` | 若 `a.b` 有为 "foo" 的字符串 `c` 字段则为真。 |

Traversal **must** 使用资源上的字段名编写。若服务希望支持某种「隐式字段」，它们 **must** 通过文档充分的 [functions](#functions) 来做。服务 **may** 指定支持遍历的字段子集。

若用户试图遍历到 message 上未定义的字段，服务 **should** 以 `INVALID_ARGUMENT` 返回错误。服务 **may** 允许遍历到 maps 与 structs 上未定义的键，并且 **should** 文档化此时如何表现。

求值涉及遍历的表达式时，若链中任何非 primitive 字段在被求值的条目上未设置，该条目 **should** 被跳过，即不匹配过滤表达式。即使比较是 `!=`（这会暗示匹配空值）也适用。在上例中，若资源实例上未设置资源字段 `a`，该实例作为非匹配被跳过。

**Important:** `.` 运算符 **must not** 用于穿过 repeated 字段或 list 的遍历，除了与 `:` 运算符的特定配合使用。

### Has Operator

过滤实现 **must** 提供 `:` 运算符，意为 "has"。它可用于集合（repeated 字段或 maps）以及 messages，并在每种情形下行为略有不同。

Repeated 字段查询重复结构是否包含匹配元素：

| 示例 | 含义 |
|--|--|
| `r:42` | 若 `r` 包含 42 则为真。 |
| `r.foo:42` | 若 `r` 包含使得 `e.foo = 42` 的元素 `e` 则为真。 |

**Important:** 过滤器不能查询 repeated 字段上*特定*元素的值。例如，`e.0.foo = 42` 与 `e[0].foo = 42` **不是** 有效过滤器。

Maps、structs、messages 可以查询 map 中字段的存在或特定值：

| 示例 | 含义 |
|--|--|
| `m:foo` | 若 `m` 包含键 "foo" 则为真。 |
| `m.foo:*` | 若 `m` 包含键 "foo" 则为真。 |
| `m.foo:42` | 若 `m.foo` 为 42 则为真。 |

解析 messages 时有两处细微区别：

- 遍历 messages 时，字段仅在有非默认值时才视为存在。
- 遍历 messages 时，字段名为 snake case，尽管实现 **may** 选择支持 camel case 与 snake case 之间的自动转换。

对所有前述类型，可以用 `*` 值检查顶层资源字段的存在：

| 示例 | 含义 |
|--|--|
| `r:*` | 若 `repeated` 字段 `r` 存在则为真。 |
| `p:*` | 若 `map` 字段 `p` 存在则为真。 |
| `m:*` | 若 `message` 字段 `m` 存在则为真。 |

**Note:** 对 `map` 与 `repeated` 字段，未设置字段与「设为空值」没有语义区别——二者都解析为「不存在」。

### Functions

过滤语言支持函数调用语法以便支持 API 特定扩展。API **may** 使用 `call(arg...)` 语法定义函数，并且 **must** 文档化它支持的任何特定函数。

### Limitations

服务 **may** 为过滤查询指定超出此处定义的进一步结构或限制。例如，服务可能支持逻辑运算符但只允许一定数量（以避免「死亡查询」或其它性能顾虑）。

进一步结构或限制 **must** 清楚文档化，并且 **must not** 违反本文规定的要求。

### Validation

若指定了不合规或 schema 无效的 `filter` 字符串，API **should** 以 `INVALID_ARGUMENT` 报错。无论何处对 `filter` 放宽校验，API **must** 文档化差异。

Schema 校验指但不限于下列：

- `filter` 中引用的字段 **must** 存在于被过滤的 schema 上
- `filter` 中提供的字段值 **must** 与字段类型对齐
  - 例如，对字段 `int32 age`，类似 `"age=hello"` 的 `filter` 无效
- 对有界数据类型例如 `enum`，`filter` 中提供的字段值 **must** 为集合中的有效值
- 对标准化类型例如 `Timestamp`，字段值 **must** 符合所文档化的标准（此类类型列表见 [Comparison Operators](#comparison-operators)）
