列出资源时（List，见 [AIP-132]({{< ref "aip-0132" >}})；或 Search 这类差不多的方法），常常只想回用户关心的那一部分。

为每个 API 单独设计一套过滤结构，很诱人。但过滤需求经常变。更稳妥的做法是：一个带结构化语法的字符串字段，非技术受众也能用。语法可以透明演进，不必等 UI 或客户端先改。

List filters 面向可能非技术的受众，有时借用口语习惯，而不是代码里常见的习惯。

## 怎么提供过滤

API 可以在 `List`（或查询集合的类似方法，例如 `Search`）上给用户过滤。若做，应当遵循这里的通用规范。语法在 [EBNF grammar](https://google.aip.dev/assets/misc/ebnf-filtering.txt) 里正式定义。

采用过滤时，请求 message 应当恰好有一个过滤字段 `string filter`。相关对象的过滤通过[遍历](#遍历运算符)或[函数](#函数)处理。

List Filters 带模糊匹配，并支持结果排名与打分。要对 list filters 做确定性求值，见 [CEL](https://github.com/google/cel-spec)。

## 字面量

裸字面值（例如 `"42"`、`"Hugo"`）是要匹配的值。单独出现、没有指定字段的字面量，应当通常在对象字段值里任何可能出现的地方匹配。

服务也可以选择只考虑某些字段；若如此，必须文档化考虑哪些字段。服务可以随时间纳入新字段，但应当审慎，并考虑对现有用户的影响。

被空白分隔的字面量视为 `AND` 的模糊变体。因此 `Victor Hugo` 大致等价于 `Victor AND Hugo`。

## 逻辑运算符

过滤实现应当提供二元运算符：

| 运算符 | 示例 | 含义 |
|--|--|--|
| `AND` | `a AND b` | 若 `a` 与 `b` 为真则为真。 |
| `OR` | `a OR b OR c` | 若 `a`、`b`、`c` 任一为真则为真。 |

为匹配常见口语习惯，`OR` 的优先级高于 `AND`，和大多数编程语言不同。表达式 `a AND b OR c` 求值为 `a AND (b OR c)`。API 文档与示例应当鼓励用显式括号，免得搞混，但不应当强制要求显式括号。

## 否定运算符

过滤实现应当提供一元运算符 `NOT` 与 `-`。二者可互换。支持否定的服务必须两种格式都支持。

| 运算符 | 示例 | 含义 |
|--|--|--|
| `NOT` | `NOT a` | 若 `a` 不为真则为真。 |
| `-` | `-a` | 若 `a` 不为真则为真。 |

## 比较运算符

过滤实现应当为 string、numeric、timestamp 与 duration 字段提供二元比较运算符 `=`、`!=`、`<`、`>`、`<=` 与 `>=`。不应当为布尔或 enums 提供它们。

| 运算符 | 示例 | 含义 |
|--|--|--|
| `=` | `a = true` | 若 `a` 为真则为真。 |
| `!=` | `a != 42` | 除非 `a` 等于 42 则为真。 |
| `<` | `a < 42` | 若 `a` 为低于 42 的数值则为真。 |
| `>` | `a > "foo"` | 若 `a` 在词典序上排在 "foo" 之后则为真。 |
| `<=` | `a <= "foo"` | 若 `a` 为 "foo" 或在词典序上在它之前则为真。 |
| `>=` | `a >= 42` | 若 `a` 为 42 或更高的数值则为真。 |

和大多数编程语言不同：字段名必须出现在比较运算符的左侧；右侧只接受字面量与逻辑运算符。

过滤器作为 query strings 接受，会发生类型转换，把字符串翻成适当的强类型值：

- Enums 期望 enum 的字符串表示（大小写敏感）。
- Booleans 期望 `true` 与 `false` 字面值。
- Numbers 期望标准整数或浮点表示。floats 支持指数（例如 `2.997e9`）。
- [Durations](https://github.com/protocolbuffers/protobuf/blob/master/src/google/protobuf/duration.proto) 期望后跟 `s` 后缀（表示秒）的数值，例如 `20s`、`1.2s`。
- [Timestamps](https://github.com/protocolbuffers/protobuf/blob/master/src/google/protobuf/timestamp.proto) 期望 [RFC-3339](https://tools.ietf.org/html/rfc3339) 格式的字符串（例如 `2012-04-21T11:30:00-04:00`）。支持 UTC 偏移。

**Warning:** 标识符 `true`、`false` 与 `null` 只在类型化字段引用的语境里才带有内在含义。

比较字符串相等时，服务应当支持用 `*` 做通配符。例如：若 `a` *以* `.foo` 结尾，则 `a = "*.foo"` 为真。

## 遍历运算符

过滤实现应当提供 `.` 运算符，表示穿过 message、map 或 struct 的遍历。

| 示例 | 含义 |
|--|--|
| `a.b = true` | 若 `a` 有为真的布尔 `b` 字段则为真。 |
| `a.b > 42` | 若 `a` 有高于 42 的数值 `b` 字段则为真。 |
| `a.b.c = "foo"` | 若 `a.b` 有为 "foo" 的字符串 `c` 字段则为真。 |

Traversal 必须用资源上的字段名来写。若服务想支持某种「隐式字段」，必须通过文档充分的[函数](#函数)来做。服务可以指定支持遍历的字段子集。

用户试图遍历到 message 上未定义的字段时，服务应当以 `INVALID_ARGUMENT` 报错。服务可以允许遍历到 maps 与 structs 上未定义的键，并且应当文档化此时怎么表现。

求值涉及遍历的表达式时，若链中任何非 primitive 字段在被求值的条目上未设置，该条目应当被跳过，即不匹配过滤表达式。即使比较是 `!=`（这会暗示匹配空值）也一样。上例里，若资源实例上未设置字段 `a`，该实例作为非匹配被跳过。

`.` 运算符不得用来穿过 repeated 字段或 list，除了与 `:` 运算符的特定配合。

## Has 运算符

过滤实现必须提供 `:` 运算符，意为 "has"。它可用于集合（repeated 字段或 maps）以及 messages，每种情形行为略有不同。

Repeated 字段查询：重复结构是否包含匹配元素：

| 示例 | 含义 |
|--|--|
| `r:42` | 若 `r` 包含 42 则为真。 |
| `r.foo:42` | 若 `r` 包含使得 `e.foo = 42` 的元素 `e` 则为真。 |

过滤器不能查询 repeated 字段上*特定*元素的值。例如 `e.0.foo = 42` 与 `e[0].foo = 42` **不是**有效过滤器。

Maps、structs、messages 可以查询 map 中字段的存在或特定值：

| 示例 | 含义 |
|--|--|
| `m:foo` | 若 `m` 包含键 "foo" 则为真。 |
| `m.foo:*` | 若 `m` 包含键 "foo" 则为真。 |
| `m.foo:42` | 若 `m.foo` 为 42 则为真。 |

解析 messages 时有两处细微差别：

- 遍历 messages 时，字段仅在有非默认值时才视为存在。
- 遍历 messages 时，字段名为 snake case。实现可以选择支持 camel case 与 snake case 之间的自动转换。

对所有前述类型，可以用 `*` 检查顶层资源字段是否存在：

| 示例 | 含义 |
|--|--|
| `r:*` | 若 `repeated` 字段 `r` 存在则为真。 |
| `p:*` | 若 `map` 字段 `p` 存在则为真。 |
| `m:*` | 若 `message` 字段 `m` 存在则为真。 |

对 `map` 与 `repeated` 字段，未设置字段与「设为空值」没有语义区别——二者都解析为「不存在」。

## 函数

过滤语言支持函数调用语法，方便做 API 特定扩展。API 可以用 `call(arg...)` 语法定义函数，并且必须文档化它支持的任何特定函数。

## 限制

服务可以为过滤查询规定比这里更进一步的结构或限制。例如：支持逻辑运算符，但只允许一定数量，以免「死亡查询」或其它性能问题。

进一步结构或限制必须清楚文档化，并且不得违反本文规定的要求。

## 校验

若指定了不合规或 schema 无效的 `filter` 字符串，API 应当以 `INVALID_ARGUMENT` 报错。无论何处对 `filter` 放宽校验，都必须文档化差异。

Schema 校验指但不限于下列：

- `filter` 中引用的字段必须存在于被过滤的 schema 上
- `filter` 中提供的字段值必须与字段类型对齐
  - 例如，对字段 `int32 age`，类似 `"age=hello"` 的 `filter` 无效
- 对有界数据类型例如 `enum`，`filter` 中提供的字段值必须为集合中的有效值
- 对标准化类型例如 `Timestamp`，字段值必须符合所文档化的标准（此类类型列表见[比较运算符](#比较运算符)）
