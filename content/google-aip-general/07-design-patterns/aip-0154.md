**英文标题**：Resource freshness validation  
**原文**：[AIP-154](https://google.aip.dev/154) · approved · 创建 2019-07-24  
**许可**：原文 © Google，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

APIs 常常需要在对资源采取某种动作之前，校验客户端与服务器对该资源当前状态达成一致。例如，两个进程并行更新同一资源可能造成竞态，后者「踩过」前者的努力。

ETags 提供了一种处理方式：允许服务器基于资源当前内容发送 checksum；当客户端把该 checksum 发回时，服务器可以在处理请求之前确保 checksums 匹配。

## Guidance

当在采取某些请求之前确保客户端有最新资源很重要时，资源 **may** 在任何此类资源上包含 `etag` 字段：

```proto
// A representation of a book.
message Book {
  // Other fields...

  // This checksum is computed by the server based on the value of other
  // fields, and may be sent on update and delete requests to ensure the
  // client has an up-to-date value before proceeding.
  string etag = 99;
}
```

- etag 字段 **must** 为 string，并且 **must** 名为 `etag`。
- *资源*上的 etag 字段 **should not** 被赋予任何 behavior annotations。
- etag 字段 **must** 由服务器在输出上提供，并且值 **should** 符合 [RFC 7232](https://tools.ietf.org/html/rfc7232#section-2.3)。
- 若用户发回匹配当前 etag 值的 etag，服务 **must** 允许该请求（除非有其它失败原因）。
- 若用户发回不匹配当前 etag 值的 etag，服务 **must** 发送 `ABORTED` 错误响应（除非另一错误优先，例如用户未授权时的 `PERMISSION_DENIED`）。
- 若用户完全不发送 etag 值，服务 **should** 允许该请求。然而，有强一致性或并行要求的服务 **may** 要求用户始终发送 etags，并在此时以 `INVALID_ARGUMENT` 错误拒绝请求。

**Note:** ETag 值 **should** 包含 [RFC 7232](https://tools.ietf.org/html/rfc7232#section-2.3) 中描述的引号。例如，有效 etag 是 `"foo"`，不是 `foo`。

### Declarative-friendly resources

声明式友好（[AIP-128]({{< ref "aip-0128" >}})）的资源 **must** 包含 `etag` 字段。

### Etags on request methods

有些情形下，etag 需要属于请求 message 而不是资源本身。例如，`Update` 标准方法可以「搭」资源上的 `etag` 字段，但 `Delete` 标准方法不能：

```proto
message DeleteBookRequest {
  // The name of the book.
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference) = {
      type: "library.googleapis.com/Book"
    }];

  // The current etag of the book.
  // If an etag is provided and does not match the current etag of the book,
  // deletion will be blocked and an ABORTED error will be returned.
  string etag = 2 [(google.api.field_behavior) = OPTIONAL];
}
```

在请求 message 上，`etag` 字段 **should** 被赋予 behavior annotation——要么 `REQUIRED` 要么 `OPTIONAL`。更多信息见 [AIP-203]({{< ref "aip-0203" >}})。

`etag` 字段也 **may** 用于 custom methods，与上例类似。

### Strong and weak etags

ETags 可以是「强验证」或「弱验证」：

- 强验证 etag 意味着两个带相同 etag 的资源是逐字节相同的。
- 弱验证 etag 意味着两个带相同 etag 的资源是等价的，但可能在服务认为不重要的方面有差异。

资源 **may** 按需使用强或弱 etags，但 **should** 文档化该行为。此外，弱 etags **must** 有 [RFC 7232](https://tools.ietf.org/html/rfc7232#section-2.3) 所强制的 `W/` 前缀。
