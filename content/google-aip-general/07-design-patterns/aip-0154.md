**英文标题**：Resource freshness validation  
**原文**：[AIP-154](https://google.aip.dev/154) · approved · 创建 2019-07-24  
**许可**：原文 © Google，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

对资源动手之前，客户端和服务器最好先对齐「当前状态」。两个进程并行更新同一资源，后者很容易把前者的改动踩掉。

ETag 就是干这个的：服务器按资源当前内容算出 checksum；客户端把 checksum 发回来，服务器先核对再处理请求。

## 资源上的 etag

在动手之前必须确认客户端拿到的是最新资源时，资源上可以加 `etag` 字段：

```proto
// A representation of a book.
message Book {
  // Other fields...

  // This checksum is computed by the server based on the value of other
  // fields, and may be sent on update and delete requests to ensure the
  // client has an up-to-date value before proceeding.
  string etag = 99;
}
```

- etag 字段必须是 string，并且必须名为 `etag`。
- *资源*上的 etag 字段不应当加任何 behavior annotations。
- etag 字段必须由服务器在输出上提供，值应当符合 [RFC 7232](https://tools.ietf.org/html/rfc7232#section-2.3)。
- 用户发回的 etag 与当前值匹配时，服务必须允许该请求（除非另有失败原因）。
- 用户发回的 etag 与当前值不匹配时，服务必须返回 `ABORTED`（除非另一错误优先，例如用户未授权时的 `PERMISSION_DENIED`）。
- 用户完全不发 etag 时，服务应当允许该请求。有强一致性或并行要求的服务可以要求用户始终带 etag，此时以 `INVALID_ARGUMENT` 拒绝。

ETag 值应当包含 [RFC 7232](https://tools.ietf.org/html/rfc7232#section-2.3) 里说的引号。有效 etag 是 `"foo"`，不是 `foo`。

## 声明式友好资源

声明式友好资源（见 [AIP-128]({{< ref "aip-0128" >}})）必须包含 `etag` 字段。

## 请求方法上的 etag

有时 etag 要放在请求 message 上，而不是资源本身。`Update` 可以「搭」资源上的 `etag` 字段，`Delete` 不行：

```proto
message DeleteBookRequest {
  // The name of the book.
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference) = {
      type: "library.googleapis.com/Book"
    }];

  // The current etag of the book.
  // If an etag is provided and does not match the current etag of the book,
  // deletion will be blocked and an ABORTED error will be returned.
  string etag = 2 [(google.api.field_behavior) = OPTIONAL];
}
```

在请求 message 上，`etag` 字段应当加 behavior annotation：要么 `REQUIRED`，要么 `OPTIONAL`。见 [AIP-203]({{< ref "aip-0203" >}})。

`etag` 也可以用在 custom methods 上，写法同上。

## 强 etag 与弱 etag

ETag 可以是强验证或弱验证：

- 强验证 etag：两个带相同 etag 的资源逐字节相同。
- 弱验证 etag：两个带相同 etag 的资源等价，但可能在服务认为不重要的方面有差异。

资源可以按需用强或弱 etags，但应当文档化该行为。弱 etags 必须带 [RFC 7232](https://tools.ietf.org/html/rfc7232#section-2.3) 要求的 `W/` 前缀。
