**英文标题**：Resource expiration  
**原文**：[AIP-214](https://google.aip.dev/214) · approved · 创建 2018-06-19  
**许可**：原文 © Google，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

客户常常想指定：某个资源或资源属性从什么时候起不再有用或有效。例如轮换的安全密钥。常见做法是把精确的 expiration time 写进 `google.protobuf.Timestamp expire_time`。但用户若只想给相对时间偏移，而不是一个具体过期时刻，负担就多了一截。

另外，世界已经理解 time-to-live，常缩写为 TTL。此字段的典型格式是以秒衡量的整数。自动生成的客户端库用起来体验不好。

## 怎么表示过期

1. 希望传达过期的 API，必须依赖名为 `expire_time` 的 [`google.protobuf.Timestamp`](https://github.com/protocolbuffers/protobuf/blob/master/src/google/protobuf/timestamp.proto) 字段。
2. 希望允许相对过期时间的 API，必须定义名为 `expiration`（或 `{something}_expiration`）的 `oneof`，里面同时包含 `expire_time`，以及单独的、标为 input only 的 [`google.protobuf.Duration`](https://github.com/protocolbuffers/protobuf/blob/master/src/google/protobuf/duration.proto) 字段 `ttl`。
3. 检索资源时，API 必须始终在 `expire_time` 字段里返回过期时间，并让 `ttl` 字段留空。
4. 依赖 time to live 特定语义的 API（例如必须把 TTL 表示为整数的 DNS）可以用 `int64 ttl` 字段。此时应当提供 aip.dev/not-precedent 注释（见 [AIP-200]({{< ref "aip-0200" >}})）。

## 示例

```proto
message ExpiringResource {
  // google.api.resource and other annotations and fields

  oneof expiration {
    // Timestamp in UTC of when this resource is considered expired.
    // This is *always* provided on output, and is calculated using
    // the value of [ttl][] if set when created.
    google.protobuf.Timestamp expire_time = 2;

    // Input only. The TTL for this resource.
    google.protobuf.Duration ttl = 3 [(google.api.field_behavior) = INPUT_ONLY];
  }
}
```

## 为什么这样规定

### 考虑过的替代方案

#### 一个叫 `ttl` 的标准字段

曾经考虑允许名为 `ttl` 的标准字段作为定义过期的另一种方式。那样服务得持续更新该字段，像倒计时钟。读-改-写会出问题：资源处理了一段时间，寿命实际上因处理时间而被延长了。

#### 永远只用 `expire_time`

这是当前世界的默认状态，少数例外除外。那种场景下，可以把 `now + ttl = expire_time` 的计算推到客户端库里。但命令行和 REST/JSON 用起来会别扭。保持原样通常是默认选择，但许多客户就是想定义相对过期时间：更简单，也去掉时区、陈旧时钟和其它愚蠢错误。
