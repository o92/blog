用户有时想先看看打算做的变更会得到什么结果，再真正动手。例如：在机群里供给新服务器，会影响整体规模和成本，还可能带出意外的下游效应。

## validate_only

API 可以提供选项：只校验、不实际执行请求，同时给出与真正执行时本会给出的相同响应（状态码、headers 与响应体）。

为此，该方法应当在请求 message 里包含 `bool validate_only` 字段：

```proto
message ReviewBookRequest {
  string name = 1 [(google.api.resource_reference) = {
    type: "library.googleapis.com/Book"
  }];
  int32 rating = 2;
  string comment = 3;

  // If set, validate the request and preview the review, but do not actually
  // post it.
  bool validate_only = 4;
}
```

API 必须执行权限检查，以及会对「live」请求执行的任何其它校验。`validate_only` 请求若确定实际请求会失败，就必须失败。

偶尔可能没法给出完整输出。例如：创建资源会生成自动 ID，校验时去做没有意义。这时应当在校验请求上省略这类字段。

## 声明式友好资源

声明式友好资源（见 [AIP-128]({{< ref "aip-0128" >}})）必须在变更该资源的方法上包含 `validate_only` 字段。
