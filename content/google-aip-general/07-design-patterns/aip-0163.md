**英文标题**：Change validation

偶尔，用户希望校验打算做的变更，看看结果会是什么，然后再实际做出变更。例如，在机群中供给新服务器的请求会影响整体机群规模与成本，并可能有意外的下游效应。

## Guidance

APIs **may** 提供选项来校验但不实际执行请求，并提供与请求实际执行时本会提供的相同响应（状态码、headers 与响应体）。

为提供此选项，该方法 **should** 在请求 message 中包含 `bool validate_only` 字段：

```proto
message ReviewBookRequest {
  string name = 1 [(google.api.resource_reference) = {
    type: "library.googleapis.com/Book"
  }];
  int32 rating = 2;
  string comment = 3;

  // If set, validate the request and preview the review, but do not actually
  // post it.
  bool validate_only = 4;
}
```

API **must** 执行权限检查以及会对「live」请求执行的任何其它校验；使用 `validate_only` 的请求若确定实际请求会失败，**must** 失败。

**Note:** 偶尔可能不可行提供完整输出。例如，若创建资源会创建自动生成的 ID，在校验时这样做没有意义。此时 APIs **should** 在校验请求上省略此类字段。

### Declarative-friendly resources

声明式友好（[AIP-128]({{< ref "aip-0128" >}})）的资源 **must** 在变更该资源的方法上包含 `validate_only` 字段。
