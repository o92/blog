**英文标题**：Request identification  
**原文**：[AIP-155](https://google.aip.dev/155) · approved · 创建 2019-05-06  
**许可**：原文 © Google，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

有时 API 对特定请求有一个唯一、客户提供的标识符很有用。这可以用于若干目的，例如对并行进程的请求去重、确保重试安全，或审计。

request IDs 最重要的目的是提供幂等性保证：允许同一请求发出不止一次，而后续调用没有任何效果。在网络失败时，客户端可以重试该请求，服务器可以检测重复并确保该请求只被处理一次。

## Guidance

APIs **may** 向请求 messages（包括标准方法的）添加 `string request_id` 参数，以便唯一标识特定请求。

```proto
message CreateBookRequest {
  // The parent resource where this book will be created.
  // Format: publishers/{publisher}
  string parent = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference) = {
      child_type: "library.googleapis.com/Book"
    }];

  // The ID to use for the book, which will become the final component of
  // the book's resource name.
  //
  // This value should be 4-63 characters, and valid characters
  // are /[a-z][0-9]-/.
  string book_id = 2 [(google.api.field_behavior) = REQUIRED];

  // The book to create.
  Book book = 3 [(google.api.field_behavior) = REQUIRED];

  // A unique identifier for this request. Restricted to 36 ASCII characters.
  // A random UUID is recommended.
  // This request is only idempotent if a `request_id` is provided.
  string request_id = 4 [(google.api.field_info).format = UUID4];
}
```

- 提供 request ID **must** 保证幂等性。
  - 若检测到重复请求，服务器 **should** 返回先前成功请求的响应，因为客户端很可能没有收到先前的响应。
  - APIs **may** 选择任何合理的时间窗口来兑现 request IDs。
- `request_id` 字段 **must** 提供在它所适用的请求 message 上（并且它 **must not** 是资源本身上的字段）。
- Request IDs **should** 为可选。
- Request IDs **should** 能够是 UUIDs，并且 **may** 只允许 UUIDs 为有效格式。request IDs 的格式限制 **must** 被文档化。
  - 作为 UUIDs 的 Request IDs **must** 用扩展 `(google.api.field_info).format = UUID4` 标注 `google.api.FieldInfo.Format` 值 `UUID4`。更多见 [AIP-202]({{< ref "aip-0202" >}})。

### Stale success responses

在某些不寻常的情形下，可能无法返回相同的成功响应。例如，创建资源的重复请求可能在该资源不仅已被创建、而且随后已被更新之后才到达；因为服务没有其它需要保留历史数据，不再可行返回相同的成功响应。

此时，该方法 **may** 改为返回资源的当前状态。换句话说，允许用反映更当前数据的类似响应替代历史成功响应。

## Rationale

### Using UUIDs for request identification

当值需要唯一时，把格式保持开放可能导致 API 消费者错误地提供重复标识符。因此，标准化为 universally unique identifier 在正确完成时大幅降低碰撞机会。
