**英文标题**：Request identification  
**原文**：[AIP-155](https://google.aip.dev/155) · approved · 创建 2019-05-06  
**许可**：原文 © Google，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

有时 API 需要一个由客户提供的、针对这次请求的唯一标识。用途包括：并行进程去重、重试安全、审计。

最重要的是幂等：同一请求可以发不止一次，后续调用没有额外效果。网络失败时，客户端可以重试；服务器认出重复，保证只处理一次。

## 请求上的 request_id

API 可以在请求 messages（包括标准方法）上加 `string request_id`，用来唯一标识这次请求。

```proto
message CreateBookRequest {
  // The parent resource where this book will be created.
  // Format: publishers/{publisher}
  string parent = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference) = {
      child_type: "library.googleapis.com/Book"
    }];

  // The ID to use for the book, which will become the final component of
  // the book's resource name.
  //
  // This value should be 4-63 characters, and valid characters
  // are /[a-z][0-9]-/.
  string book_id = 2 [(google.api.field_behavior) = REQUIRED];

  // The book to create.
  Book book = 3 [(google.api.field_behavior) = REQUIRED];

  // A unique identifier for this request. Restricted to 36 ASCII characters.
  // A random UUID is recommended.
  // This request is only idempotent if a `request_id` is provided.
  string request_id = 4 [(google.api.field_info).format = UUID4];
}
```

- 提供 request ID 必须保证幂等。
  - 若检测到重复请求，服务器应当返回先前成功请求的响应。客户端多半没收到那一次的响应。
  - API 可以用任何合理的时间窗口来兑现 request IDs。
- `request_id` 必须放在它所适用的请求 message 上，不得做成资源本身上的字段。
- Request IDs 应当是可选的。
- Request IDs 应当能做成 UUID，也可以只允许 UUID 为有效格式。格式限制必须写进文档。
  - 作为 UUID 的 Request IDs 必须用扩展 `(google.api.field_info).format = UUID4` 标注 `google.api.FieldInfo.Format` 值 `UUID4`。见 [AIP-202]({{< ref "aip-0202" >}})。

## 过期的成功响应

偶尔没法返回同一份成功响应。例如：创建资源的重复请求赶到时，资源不但已经建好，后来还被改过了。服务没有别的历史数据要留，再吐同一份旧成功响应已经做不到。

这时，该方法可以改为返回资源的当前状态。也就是说：允许用反映更新数据的类似响应，替代历史成功响应。

## 为什么这样规定

### 用 UUID 做请求标识

值需要唯一时，格式留得太开，消费者很容易误交重复标识符。标准化成 universally unique identifier，做对了就能大幅降低碰撞机会。
