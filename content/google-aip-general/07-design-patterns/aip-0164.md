**英文标题**：Soft delete  
**原文**：[AIP-164](https://google.aip.dev/164) · approved · 创建 2020-10-06  
**许可**：原文 © Google，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

客户端想要软删除和 undelete，原因可以有很多。压倒性的一条是：从错误里恢复。支持 undelete 的服务，能让用户把误删的资源捞回来。

## 软删除怎么做

API 可以支持 undelete，专门应对用户误删、需要恢复的情形。

若资源需要支持 undelete，`Delete` 必须只把资源标为已删除，不完全从系统里拿掉。方法若这样表现，应当返回更新后的资源，而不是 `google.protobuf.Empty`。

支持软删除的资源应当同时有 `delete_time` 与 `purge_time`（见 [AIP-148]({{< ref "aip-0148" >}})）。此外，若资源包含 `state` 字段（见 [AIP-216]({{< ref "aip-0216" >}})），应当包含 `DELETED` state 值。

## Undelete

支持软删除的资源应当提供 `Undelete` 方法：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP 动词必须为 `POST`。
- `body` 子句必须为 `"*"`。
- 响应 message 必须是资源本身。没有 `UndeleteBookResponse`。
  - 除非不可行，响应应当包含完全填充的资源。
  - 若 undelete RPC 是[长时运行的](#长时运行-undelete)，响应 message 必须是解析为资源本身的 `google.longrunning.Operation`。

## Undelete 请求

Undelete 用一套常见的请求 message 模式：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- 必须包含 `name` 字段。它应当称为 `name`。
  - 该字段应当标注为 required（见 [AIP-203]({{< ref "aip-0203" >}})）。
  - 该字段应当标识它所引用的 resource type（见 [AIP-123]({{< ref "aip-0123" >}})）。
  - 该字段的注释应当文档化资源 pattern。
- 请求 message 不得包含任何其它必填字段，并且不应当包含其它可选字段，除非本文或另一篇 AIP 有描述。

## 长时运行 undelete

有些资源恢复所需时间超出常规 API 请求的合理范围。这时应当改用 long-running operation（见 [AIP-151]({{< ref "aip-0151" >}})）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- 响应类型必须设为该资源（若 RPC 不是长时运行时的返回类型）。
- `response_type` 与 `metadata_type` 字段都必须指定。

## Expunge

支持软删除的资源可以提供 `Expunge` custom method，让用户立刻永久删除资源。此方法可以对当前处于 `CREATING`、`READY` 或 `SOFT_DELETED` 状态的资源操作（例如 `delete_time` 已设置）。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URI 必须使用带 `:expunge` 后缀的 custom method。
- HTTP 动词必须为 `POST`，body 子句必须为 `"*"`。
- 响应 message 必须为 `google.protobuf.Empty` 或 `google.longrunning.Operation`。

## 长时运行 expunge

若 expunge 过程需要显著时间，该方法可以改为 `google.longrunning.Operation`（见 [AIP-151]({{< ref "aip-0151" >}})）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

## Expunge 请求

Expunge 用一套常见的请求 message 模式：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- 请求 message 必须按名称引用要 expunge 的资源。
- 不应当有任何其它请求字段。

## List 与 Get

软删除的资源默认不应当出现在 `List`（见 [AIP-132]({{< ref "aip-0132" >}})）响应里，除非 `bool show_deleted` 为 true。对软删除资源的 `Get`（见 [AIP-131]({{< ref "aip-0131" >}})）应当返回该资源，而不是 `NOT_FOUND`。

软删除资源的 API 可以选择合理策略来清除那些资源：经过合理时间（例如 30 天）后自动清除、允许用户设置过期时间（见 [AIP-214]({{< ref "aip-0214" >}})），或无限期保留。无论选哪种，都应当文档化软删除资源何时会被完全移除。

## 声明式友好资源

可软删除的资源在声明式客户端里的体验，比硬删除差：软删除资源上的 ID 除非调用 custom method（undelete）否则不可复用，必须引入命令式客户端或手写代码，才能把该 custom method 用进来。

## 错误

若用户没有访问该资源的权限，无论它是否存在，服务必须以 `PERMISSION_DENIED`（HTTP 403）报错。必须在检查资源是否存在之前检查权限。

若用户确有适当权限，但所请求的资源不存在（从未创建，或已经 expunged），服务必须以 `NOT_FOUND`（HTTP 404）报错。

若调用软 `Delete` 的用户有适当权限，但所请求的资源已经删除：`allow_missing` 为 `true` 时必须成功；`allow_missing` 为 `false` 时应当以 `NOT_FOUND`（HTTP 404）报错。

若调用 `Undelete` 的用户有适当权限，但所请求的资源未被删除，服务必须以 `ALREADY_EXISTS`（HTTP 409）响应。

若调用 `Expunge` 的用户请求不存在的资源（从未创建或已经 expunged），该方法必须返回 `NOT_FOUND`（HTTP 404）。

若资源存在但不处于 ready 或软删除状态，该方法必须返回 `FAILED_PRECONDITION`（HTTP 400）。

标准权限错误（`PERMISSION_DENIED`）适用。服务必须要求与标准 delete 权限分开的显式 expunge 权限（例如 `..expunge`）。
