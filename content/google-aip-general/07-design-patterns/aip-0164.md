**英文标题**：Soft delete  
**原文**：[AIP-164](https://google.aip.dev/164) · approved · 创建 2020-10-06  
**许可**：原文 © Google，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

客户端可能希望软删除与 undelete 功能有若干原因，但一个压倒性的原因脱颖而出：从错误中恢复。支持 undelete 的服务让用户能够恢复被意外删除的资源。

## Guidance

APIs **may** 支持「undelete」能力，以应对用户误删资源并需要恢复能力的情形。

若资源需要支持 undelete，`Delete` 方法 **must** 只把资源标为已删除，但不完全从系统中移除。若方法如此表现，它 **should** 返回更新后的资源而不是 `google.protobuf.Empty`。

支持软删除的资源 **should** 同时有 [AIP-148]({{< ref "aip-0148" >}}) 中描述的 `delete_time` 与 `purge_time` 字段。此外，若资源包含 `state` 字段（[AIP-216]({{< ref "aip-0216" >}})），资源 **should** 包含 `DELETED` state 值。

### Undelete

支持软删除的资源 **should** 提供 `Undelete` 方法：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

- HTTP 动词 **must** 为 `POST`。
- `body` 子句 **must** 为 `"*"`。
- 响应 message **must** 为资源本身。没有 `UndeleteBookResponse`。
  - 除非不可行，响应 **should** 包含完全填充的资源。
  - 若 undelete RPC 是 [长时运行的](#long-running-undelete)，响应 message **must** 为解析为资源本身的 `google.longrunning.Operation`。

### Undelete request message

Undelete methods 实现一种常见的请求 message 模式：

```proto
message UndeleteBookRequest {
  // The name of the deleted book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"];
}
```

- **must** 包含 `name` 字段。它 **should** 称为 `name`。
  - 该字段 **should** 被 [标注为 required]({{< ref "aip-0203" >}})。
  - 该字段 **should** 标识它所引用的 [resource type]({{< ref "aip-0123" >}})。
  - 该字段的注释 **should** 文档化资源 pattern。
- 请求 message **must not** 包含任何其它必填字段，并且 **should not** 包含其它可选字段，除非本文或另一篇 AIP 有描述。

### Long-running undelete

有些资源恢复所需时间超出常规 API 请求的合理范围。此时，API **should** 改用 long-running operation（[AIP-151]({{< ref "aip-0151" >}})）：

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

- 响应类型 **must** 设为该资源（若 RPC 不是长时运行时的返回类型）。
- `response_type` 与 `metadata_type` 字段都 **must** 指定。

### Expunge

支持软删除的资源 **may** 提供 `Expunge` custom method，以允许用户触发立即永久删除资源。此方法可以对当前处于 `CREATING`、`READY` 或 `SOFT_DELETED` 状态的资源操作（例如，`delete_time` 已设置）。

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.protobuf.Empty) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.api.method_signature) = "name";
}
```

- URI 必须使用带 :expunge 后缀的 custom method。
- HTTP 动词必须为 POST，body 子句必须为 "*"。
- 响应 message 必须为 `google.protobuf.Empty` 或 `google.longrunning.Operation`。

### Long-running expunge

若 expunge 过程需要显著时间，该方法 **may** 改为 `google.longrunning.Operation`（[AIP-151]({{< ref "aip-0151" >}})）：

```proto
// Permanently deletes a soft-deleted Book.
rpc ExpungeBook(ExpungeBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:expunge"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "OperationMetadata"
  };
  option (google.api.method_signature) = "name";
}
```

### Expunge request message

Expunge methods 实现一种常见的请求 message 模式：

```proto
message ExpungeBookRequest {
  // The name of the soft-deleted book to expunge.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];
}
```

- 请求 message **must** 按名称引用要 expunge 的资源。
- **should not** 有任何其它请求字段。

### List and Get

软删除的资源默认 **should not** 在 `List`（[AIP-132]({{< ref "aip-0132" >}})）响应中返回（除非 `bool show_deleted` 为 true）。对软删除资源的 `Get`（[AIP-131]({{< ref "aip-0131" >}})）请求 **should** 返回该资源（而不是 `NOT_FOUND` 错误）。

软删除资源的 APIs **may** 选择合理策略来清除那些资源，包括经过合理时间（例如 30 天）后自动清除、允许用户设置过期时间（[AIP-214]({{< ref "aip-0214" >}})），或无限期保留资源。无论选择何种策略，API **should** 文档化软删除资源何时会被完全移除。

### Declarative-friendly resources

可软删除的资源在声明式客户端中的体验比硬删除资源差：因为软删除资源上的 ID 除非调用 custom method（undelete）否则不可复用，必须引入命令式客户端或手写代码来纳入该 custom method 的用法。

### Errors

若用户没有访问该资源的权限，无论它是否存在，服务 **must** 以 `PERMISSION_DENIED`（HTTP 403）报错。**must** 在检查资源是否存在之前检查权限。

若用户确有适当权限，但所请求的资源不存在（要么从未创建，要么已经 expunged），服务 **must** 以 `NOT_FOUND`（HTTP 404）报错。

若调用软 `Delete` 的用户有适当权限，但所请求的资源已经删除，若 `allow_missing` 为 `true`，服务 **must** 成功；若 `allow_missing` 为 `false`，**should** 以 `NOT_FOUND`（HTTP 404）报错。

若调用 `Undelete` 的用户有适当权限，但所请求的资源未被删除，服务 **must** 以 `ALREADY_EXISTS`（HTTP 409）响应。

若调用 `Expunge` 的用户请求不存在的资源（从未创建或已经 expunged），该方法 **must** 返回 `NOT_FOUND`（HTTP 404）。

若资源存在但不处于 ready 或软删除状态，该方法 **must** 返回 `FAILED_PRECONDITION`（HTTP 400）。

标准权限错误（`PERMISSION_DENIED`）适用。服务 **must** 要求与标准 delete 权限分开的显式 expunge 权限（例如 `..expunge`）。
