**英文标题**：Reading across collections

有时用户想一次跨多个集合把资源捞出来，或者不知道资源在哪个集合里，也要把单个资源取到。

## List 里的 `-`

API 可以允许用户在标准 List（见 [AIP-132]({{< ref "aip-0132" >}})）里把 `-`（连字符）当成通配符，跨多个集合读资源：

```
GET /v1/publishers/-/books?filter=...
```

- URI 模式仍必须用 `*` 指定，并允许指定集合；不得把 `-` 硬编码进 URI 模式。
- 该方法必须显式文档化支持此行为。
- 响应里给出的资源必须用规范名称，带上实际 parent collection 标识符，而不是 `-`。
- 无论 child resources 的标识符是否保证唯一，服务都可以在 `List` 上支持跨集合读取。但若 child resources 可能碰撞，不得在 `Get` 上支持跨集合读取。
- 跨 parent 的请求不应当支持 `order_by`。若支持，该字段必须文档化为尽力而为。跨 parent 会引入排序歧义，某个 parent 很难到达时尤其明显（见 [AIP-217]({{< ref "aip-0217" >}})）。

跨多个集合列出若可能因不可达 parents 导致部分失败（例如跨 locations 列出），该方法必须按 [AIP-217]({{< ref "aip-0217" >}}) 表明这一点。

## 唯一资源查找

有时，子集合内的资源有跨 parent collections 唯一的标识符。这时，让 Get（见 [AIP-131]({{< ref "aip-0131" >}})）在不知道哪个 parent collection 包含它的情况下取出该资源，会很有用。API 可以允许用户指定通配符 collection ID `-`，表示任意 parent collection：

```
GET https://example.googleapis.com/v1/publishers/-/books/{book}
```

- URI 模式仍必须用 `*` 指定，并允许指定集合；不得把 `-` 硬编码进 URI 模式。
- 该方法必须显式文档化支持此行为。
- 响应里的 resource name 必须用规范名称，带上实际 parent collection 标识符，而不是 `-`。例如上面的请求返回类似 `publishers/123/books/456` 的名称，*不是* `publishers/-/books/456`。
- resource ID 必须在 parent collections 内唯一。

## 延伸阅读

因不可达资源导致的部分失败，见 [AIP-217]({{< ref "aip-0217" >}})。
