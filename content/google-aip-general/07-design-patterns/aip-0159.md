**英文标题**：Reading across collections  
**原文**：[AIP-159](https://google.aip.dev/159) · approved · 创建 2019-07-26

有时，用户能够跨多个集合检索资源，或无需知道资源在哪个集合中就能检索单个资源，很有用。

## Guidance

APIs **may** 通过允许用户在标准 List（[AIP-132]({{< ref "aip-0132" >}})）方法中指定 `-`（连字符或短横线字符）作为通配符来支持跨多个集合读取资源：

```
GET /v1/publishers/-/books?filter=...
```

- URI 模式 **must** 仍用 `*` 指定并允许指定集合；URI 模式 **must not** 硬编码 `-` 字符。
- 该方法 **must** 显式文档化支持此行为。
- 响应中提供的资源 **must** 使用资源的规范名称，带实际 parent collection 标识符（而不是 `-`）。
- 无论 child resources 的标识符是否保证唯一，服务 **may** 在 `List` 请求上支持跨集合读取。然而，若 child resources 可能碰撞，服务 **must not** 在 `Get` 请求上支持跨集合读取。
- 跨 parent 的请求 **should not** 支持 `order_by`。若支持，该字段 **must** 文档化为尽力而为。这是因为跨 parent 请求引入排序歧义，尤其在难以到达某个 parent 时（见 [AIP-217]({{< ref "aip-0217" >}})）。

**Important:** 若跨多个集合列出引入因不可达 parents 导致部分失败的可能（例如跨 locations 列出），该方法 **must** 按 [AIP-217]({{< ref "aip-0217" >}}) 的指导表明这一点。

### Unique resource lookup

有时，子集合内的资源有跨 parent collections 唯一的标识符。此时，允许 Get（[AIP-131]({{< ref "aip-0131" >}})）方法在不知道哪个 parent collection 包含它的情况下检索该资源可能有用。此时，APIs **may** 允许用户指定通配符 collection ID `-`（连字符或短横线字符）来表示任何 parent collection：

```
GET https://example.googleapis.com/v1/publishers/-/books/{book}
```

- URI 模式 **must** 仍用 `*` 指定并允许指定集合；URI 模式 **must not** 硬编码 `-` 字符。
- 该方法 **must** 显式文档化支持此行为。
- 响应中的 resource name **must** 使用资源的规范名称，带实际 parent collection 标识符（而不是 `-`）。例如，上述请求返回名称类似 `publishers/123/books/456` 的资源，*不是* `publishers/-/books/456`。
- resource ID **must** 在 parent collections 内唯一。
