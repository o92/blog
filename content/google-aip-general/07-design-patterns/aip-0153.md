**英文标题**：Import and export  
**原文**：[AIP-153](https://google.aip.dev/153) · approved · 创建 2019-12-16  
**许可**：原文 © Google，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

许多用户希望能够把数据加载进 API，或把现有数据从 API 取出。这对企业用户尤其重要，他们常常担心供应商锁定。

## Guidance

APIs **may** 支持 import 与 export 操作，它们 **may** 创建多个新资源，或 **may** 把数据填充进单个资源。

### Multiple resources

服务 **may** 支持把多个资源导入或导出 API，并且 **should** 用一种常见模式来做：

```proto
rpc ImportBooks(ImportBooksRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books:import"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "ImportBooksResponse"
    metadata_type: "ImportBooksMetadata"
  };
}

rpc ExportBooks(ExportBooksRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books:export"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "ExportBooksResponse"
    metadata_type: "ExportBooksMetadata"
  };
}
```

- 该方法 **must** 返回 long-running operation（见 [AIP-151]({{< ref "aip-0151" >}})），除非服务能保证它*永远*不需要超过几秒就能完成。
- HTTP 动词 **must** 为 `POST`，并且 `body` **must** 为 `"*"`。
- **should** 把 `parent` 字段包含为 URI 的一部分。
  - 若需要导入到或从多个资源导出，API **should** 保留 `parent` 字段并允许用户使用 `-` 字符表示多个 parents（见 [AIP-159]({{< ref "aip-0159" >}})）。
  - 在 import 上，若用户提供特定 parent，API **must** 拒绝任何会被添加到不同 parent 的导入资源。
- URI 后缀 **should** 为 `:import` 或 `:export`。

### Data for a single resource

服务 **may** 支持把数据导入或导出单个资源，并且 **should** 用一种常见模式来做：

```proto
rpc ImportPages(ImportPagesRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{book=publishers/*/books/*}:importPages"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "ImportPagesResponse"
    metadata_type: "ImportPagesMetadata"
  };
}

rpc ExportPages(ExportPagesRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{book=publishers/*/books/*}:exportPages"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "ExportPagesResponse"
    metadata_type: "ExportPagesMetadata"
  };
}
```

- 该方法 **must** 返回 long-running operation（见 [AIP-151]({{< ref "aip-0151" >}})），除非服务能保证它*永远*不需要超过几秒就能完成。
- HTTP 动词 **must** 为 `POST`，并且 `body` **must** 为 `"*"`。
- 表示正在向其中导入数据的资源的字段 **should** 包含为 URI 的一部分。该字段 **should** 以资源命名（并且 **should not** 称为 `name`）。
- URI 后缀应同时包含动词与数据本身的名词，例如 `:importPages` 或 `:exportPages`。

### Request object

Imports 与 exports 常常需要两类根本不同的配置：

1. 特定于 source 或 destination 的配置。
2. 关于被导入或导出的数据本身的配置。

Source 或 destination 配置应分组进单个 message 并放在 oneof 内：

```proto
message ImportBooksRequest {
  string parent = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference) = {
      child_type: "library.googleapis.com/Book"
    }];
  oneof source {
    AuthorSource author_source = 2;
    TranslatorSource translator_source = 3;
  }
  string isbn_prefix = 4;
}

message ExportBooksRequest {
  string parent = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference) = {
      child_type: "library.googleapis.com/Book"
    }];
  oneof destination {
    PrinterDestination printer_destination = 2;
    TranslatorDestination translator_destination = 3;
  }
  string filter = 4;
}
```

- source 配置 messages **must** 放在 `oneof source`（对 import）或 `oneof destination`（对 export）内，即使只有一个。（这保持以后添加更多的灵活性。）
- 与数据本身相关（因此跨所有 sources 共通）的配置 **must** 放在请求 message 的顶层。

**Note:** import 与 export 的配置彼此 **may** 不同。（例如，从文件导入但导出到目录是合理的。）

### Inline sources

APIs **may** 也允许「inline」import 与 export，被导入或导出的内容在请求或响应中提供。

```proto
message InlineSource {
  repeated Book books = 1;
}
```

- source 或 destination **should** 名为 `InlineSource` 或 `InlineDestination`。
- message **should** 包含表示该资源的 repeated 字段。然而，若资源结构复杂，API **may** 使用单独的 inline 表示。此时，import 与 export **must** 使用同一格式。

### Partial failures

尽管通常不鼓励部分失败，import 与 export RPCs **should** 在 metadata 对象中包含部分失败信息。每个个别错误 **should** 为描述该错误的 `google.rpc.Status` 对象。更多错误信息见 [AIP-193]({{< ref "aip-0193" >}})。
