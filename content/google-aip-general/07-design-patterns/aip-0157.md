**英文标题**：Partial responses  
**原文**：[AIP-157](https://google.aip.dev/157) · approved · 创建 2019-01-26

有时资源可能很大或计算昂贵，API 需要让用户控制它发回哪些字段。

## Guidance

APIs **may** 以两种方式之一支持部分响应：

### Field masks parameter

Field masks（`google.protobuf.FieldMask`）可用于授予用户对返回哪些字段的细粒度控制。API **should** 在旁路中支持该 mask。例如，该参数可以用 HTTP query parameter、HTTP header 或 [gRPC metadata entry](https://grpc.io/docs/what-is-grpc/core-concepts/#metadata) 指定。Google Cloud APIs 把 field masks 指定为 [system parameter](https://cloud.google.com/apis/docs/system-parameters)。

Field masks **should not** 在 [请求](#read-masks-as-a-request-field) 中指定。

- field mask 参数的值 **must** 为 `google.protobuf.FieldMask`。
- field mask 参数 **must** 为可选：
  - **should** 支持显式值 `"*"`，并且它 **must** 返回所有字段。
  - 若省略 field mask 参数，它 **must** 默认为 `"*"`，除非另有文档。
- API **may** 允许带非终端 repeated 字段的 read masks（与 update masks 不同），但没有义务这样做。

**Note:** 更改 field mask 参数的默认值是破坏性变更（[AIP-180]({{< ref "aip-0180" >}})）。

### View enumeration

或者，API **may** 用 view enums 支持部分响应。View enums 适用于 API 只想向用户暴露少量排列的情形：

```proto
enum BookView {
  // The default / unset value.
  // The API will default to the BASIC view.
  BOOK_VIEW_UNSPECIFIED = 0;

  // Include basic metadata about the book, but not the full contents.
  // This is the default value (for both ListBooks and GetBook).
  BOOK_VIEW_BASIC = 1;

  // Include everything.
  BOOK_VIEW_FULL = 2;
}
```

- enum **should** 作为请求 message 上的 `view` 字段指定。
- enum **should** 命名为以 `-View` 结尾的某种名称
- enum **should** 至少有名为 `BASIC` 与 `FULL` 的值（尽管它 **may** 有这些以外的值）。
- `UNSPECIFIED` 值 **must** 有效（不是错误），并且 API **must** 文档化未指定值会做什么。
  - 对 List RPCs，有效默认值 **should** 为 `BASIC`。
  - 对下列 RPC 类型，有效默认值 **should** 为 `BASIC` 或 `FULL`：
    - Get
    - Create
    - Update
    - Soft Delete
    - Custom Method
- enum **should** 定义在 proto 文件的顶层（因为它很可能在多个请求中需要，例如 `Get` 与 `List`）。顶层枚举见 [AIP-126]({{< ref "aip-0126" >}})。
- APIs **may** 随时间向给定 view 添加字段。APIs **must not** 从给定 view 移除字段（这是破坏性变更）。

**Note:** 若服务需要（或可能需要）多个值重叠但不同的 views，存在命名空间冲突的可能。此时，服务 **should** 把 view enum 嵌套在个别资源内。

**Note:** 让部分响应成为标准方法的默认，可能降低声明式客户端的有效性。若认为部分响应有必要，提供请求在响应中填充完整资源的机制（如本 View 模式）更可取。

### Read masks as a request field

**Warning:** 作为请求 message 上单个显式字段的 Read mask 对 Google APIs **已废弃**。**must** 改为使用 [system parameter](#field-masks-parameter)。下列指导是为现有遗留 Google 与外部非 Google 用法的利益。

API **may** 支持作为请求 message 上单个字段的 read masks：`google.protobuf.FieldMask read_mask`。

- read mask **must** 为 `google.protobuf.FieldMask`，并且 **should** 名为 `read_mask`。
- field mask **should** 为可选：
  - **should** 支持显式值 `"*"`，并且它 **must** 返回所有字段。
  - 若未提供 field mask 参数，**must** 返回所有字段。
- API **may** 允许带非终端 repeated 字段的 read masks（与 update masks 不同），但没有义务这样做。

## Rationale

### Deprecating `read_mask` in request messages

如所述，Google API 基础设施实现服务范围的响应字段过滤机制，因此个别 API 方法无需在其请求 schema 中指定 `read_mask`。这样做既冗余，也可能成为客户端或服务的冲突点。
