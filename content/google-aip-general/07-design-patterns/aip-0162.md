**英文标题**：Resource Revisions  
**原文**：[AIP-162](https://google.aip.dev/162) · **draft** · 创建 2019-09-17 · 更新 2023-09-01  
**许可**：原文 © Google，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

有些 APIs 需要带修订历史的资源，用户可以推理资源随时间的状态。这样做有若干原因：

- 用户可能希望回滚到先前修订，或与先前修订做 diff。
- API 可能创建以某种方式从给定时间点的资源派生的数据。此时，可能希望快照该资源供以后引用。

**Note:** 我们使用单词 *revision* 来指特定资源的历史引用，并有意避免术语 *version*，后者指 API 整体的版本。

## Guidance

APIs **may** 为资源存储修订历史。有用的情形包括：

- 通过 API 暴露资源的较旧版本有价值。这可以避免客户自己编写 API 来存储并启用修订检索的开销。
- 其它资源依赖某资源的不同修订。
- 需要表示资源随时间的变化。

实现带修订历史之资源的 APIs **should** 把资源修订抽象为该资源的嵌套集合。有时，修订集合可以是顶层集合，例外包括：

- 若资源修订意在比 parent 资源有更长的寿命。换句话说，资源删除后资源修订仍然存在。

```proto
message BookRevision {
  // The name of the book revision.
  string name = 1;

  // The snapshot of the book
  Book snapshot = 2
    [(google.api.field_behavior) = OUTPUT_ONLY];

  // The timestamp that the revision was created.
  google.protobuf.Timestamp create_time = 3
    [(google.api.field_behavior) = OUTPUT_ONLY];

  // Other revision IDs that share the same snapshot.
  repeated string alternate_ids = 4
    [(google.api.field_behavior) = OUTPUT_ONLY];
}
```

- `message` **must** 标注为资源（[AIP-123]({{< ref "aip-0123" >}})）。
- `message` 名称 **must** 名为 `{ResourceType}Revision`。
- 资源修订 **must** 包含一个类型为 parent 资源 message、字段名为 `snapshot` 的字段。
  - `snapshot` 的值 **must** 为创建修订时 parent 的配置。
- 资源修订 **must** 包含 `create_time` 字段（见 [AIP-142]({{< ref "aip-0142" >}})）。
- 资源修订 **may** 包含 repeated 字段 `alternate_ids`，其中会包含该修订也被知晓的 resource IDs 列表（例如 `latest`）

### Creating Revisions

取决于资源，不同 APIs 可能有不同策略：

- 每当 parent 资源有变更时创建新修订
- 当重要系统状态改变时创建新修订
- 当被特别请求时创建新修订

APIs **may** 使用这些策略中的任何一种。APIs **must** 文档化其修订创建策略。

### Resource names for revisions

当引用资源的特定修订时，子集合名称 **must** 名为 `revisions`。资源修订的名称格式为 `{resource_name}/revisions/{revision_id}`。例如：

```
publishers/123/books/les-miserables/revisions/c7cfa2a8
```

### Server-specified Aliases

服务 **may** 保留特定 IDs 作为 aliases（[AIP-122]({{< ref "aip-0122" >}})）（例如 `latest`）。这些是只读的，由服务管理。

```
GET /v1/publishers/{publisher}/books/{book}/revisions/{revision_id}
```

- 若存在 `latest` ID，它 **must** 表示最近创建的修订。`publishers/{publisher}/books/{book}/revisions/latest` 与 `publishers/{publisher}/books/{book}` 的内容可以不同，因为最新修订可能与资源的当前状态不同。

### User-Specified Aliases

APIs **may** 提供机制，让用户用 custom method "alias" 为现有修订分配 alias（[AIP-122]({{< ref "aip-0122" >}})） ID：

```proto
rpc AliasBookRevision(AliasBookRevisionRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*/revisions/*}:alias"
    body: "*"
  };
}
```

```proto
message AliasBookRevisionRequest {
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference) = {
      type: "library.googleapis.com/BookRevision"
    }];

  // The ID of the revision to alias to, e.g. `CURRENT` or a semantic
  // version.
  string alias_id = 2 [(google.api.field_behavior) = REQUIRED];
}
```

- 请求 message **must** 有 `name` 字段：
  - 该字段 **must** 被标注为 required（[AIP-203]({{< ref "aip-0203" >}})）。
  - 该字段 **must** 标识它所引用的 resource type（[AIP-123]({{< ref "aip-0123" >}})）。
- 请求 message **must** 有 `alias_id` 字段：
  - 该字段 **must** 被标注为 required（[AIP-203]({{< ref "aip-0203" >}})）。
- 若用户用现有 `alias_id` 调用该方法，请求 **must** 成功，并且 alias 将更新为指向所提供的修订。这允许用户针对特定 alias（例如 `published`）编写代码，修订可以改变而无需改代码。

### Rollback

带修订历史之资源的常见用例是回滚到给定修订的能力。APIs **should** 用 `Rollback` custom method 处理：

```proto
rpc RollbackBook(RollbackBookRequest) returns (BookRevision) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*/revisions/*}:rollback"
    body: "*"
  };
}
```

- 该方法 **must** 使用 `POST` HTTP 动词。
- 该方法 **should** 返回资源修订。

```proto
message RollbackBookRequest {
  // The revision that the book should be rolled back to.
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference) = {
      type: "library.googleapis.com/BookRevision"
    }];
}
```

- 请求 message **must** 有 `name` 字段，指向资源应回滚到其配置的资源修订。
  - 该字段 **must** 被标注为 required（[AIP-203]({{< ref "aip-0203" >}})）。
  - 该字段 **must** 标识它所引用的 resource type（[AIP-123]({{< ref "aip-0123" >}})）。

### Child resources

带修订历史的资源 **may** 有 child resources。若有，有两种潜在变体：

- 每个 child resource 是 parent 资源整体的 child。
- 每个 child resource 是 parent 资源*单个修订*的 child。

APIs **should not** 包含多层带修订的资源，因为这很快变得难以推理。

### Standard methods

任何标准方法 **must** 实现对应的 AIPs（[AIP-131]({{< ref "aip-0131" >}})、[AIP-132]({{< ref "aip-0132" >}})、[AIP-133]({{< ref "aip-0133" >}})、[AIP-134]({{< ref "aip-0134" >}})、[AIP-135]({{< ref "aip-0135" >}})），并带下列额外行为：

- List methods：默认情况下，list 响应中的修订 **must** 按逆时间顺序排列。用户可以提供 `order_by` 覆盖默认行为。
- 若修订支持 aliasing，带 alias 的 resource name（例如 `revisions/1.0.2`）的 delete 方法 **must** 移除该 alias 而不是删除该资源。

由于修订嵌套在资源下，也见 cascading delete（[AIP-135]({{< ref "aip-0135" >}})）。

## Rationale

### Abstract revisions as nested collection

修订作为嵌套集合下的资源，使修订成为一等公民。

- 修订可以提供标准 get、list 与 delete 方法。
- 它保留在资源 message 之外向修订扩展新字段的灵活性。

### Tagging to Aliases

先前存在 `tag` 概念。此概念与 alias（[AIP-122]({{< ref "aip-0122" >}})）冗余，术语被合并以降低 AIPs 中的复杂度。

### Output only resource configuration

尽管把资源配置作为 create 方法的一部分交给修订是一种选项，这样做会允许用户提交该资源从未处于的修订资源配置。

`OUTPUT_ONLY` 并要求所创建的修订表示当前时间点的资源，消除了该问题。

## History

### Switching from a collection extension to a subcollection

2023-09，修订被抽象为嵌套资源集合。在此之前，修订更像通过使用 `@` 符号对现有资源的扩展。列出与删除修订是资源集合上的 custom methods。单个 Get 方法用于检索资源修订或资源。

其主要优势是允许资源引用无缝指向资源或其修订。

它也有若干劣势：

- List revisions 是资源集合上的 custom method（:listRevisions）
- Delete revision 是资源集合上的 custom method
- 在 API discovery doc 中不可见
- Resource ID 不能使用 `@`

指导最终被修改，以使修订表现得像资源，降低用户认知负荷，并允许面向资源的客户端轻松 list、get、create 与 update 修订。

### Using resource ID instead of tag

在先前设计中，修订有单独的修订标识符称为 `tag`，会住在修订中。

Tags 实际上是影子 resource ID，需要基于 tag 的值创建、获取并过滤修订的方法。

通过把 tag 的概念合并进 revision ID，用户不再需要熟悉第二套检索与标识方法。
