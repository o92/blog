**英文标题**：Common components  
**原文**：[AIP-213](https://google.aip.dev/213) · approved · 创建 2018-08-17  
**许可**：原文 © Google，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

按 [AIP-215]({{< ref "aip-0215" >}})，APIs 必须自包含。唯一例外是使用意在被多个 APIs 使用的 common components packages。共享同一套表示，客户端少抄一份；但公共组件几乎没有版本，一改就到处生效。所以能进公共包的东西很少，限制也很硬。

有两类 common component packages：

- Organization-specific common components，覆盖组织特定概念，例如 Maps 中的 "viewport"。
- Global common components，它们是通用的（即非领域特定），例如 "timestamp" 或 "postal address"。

在跨多个 APIs 共享单个表示是安全的场合，common components 可以让客户端更容易与那些 APIs 交互。概念特定的客户端代码可以写一次；messages 可以从一个 API 的响应用于另一个 API 的请求，而不必笨拙地复制。

然而，此好处带来显著限制，不应轻易尝试。

注意：即使组件的领域是公共的，组件的要求也可能是组织特定的。例如，某些组织可能对如何表示金融值有特定要求，导致多个面向金融的 organization-specific common components——因为任何 global common component 要么不满足组织特定要求，要么对一般使用过于复杂。

## 怎么做

- 组织范围的 common component packages 必须以 `.type` 结尾，例如 `google.geo.type` 或 `google.shopping.type`。
- 组织必须在创建新的组织范围 common component package 之前咨询 API 设计团队。
- 组织范围的 common component packages 必须发布在 [the `googleapis` repository](https://github.com/googleapis/googleapis)。
- 创建并发布新的组织范围 common component package 的组织，必须更新本 AIP，把它包含在下面的列表中。
- 组织不得在 organization-specific common component packages 中定义通用组件，而是优先使用 global common components。
- Common components 不得被「移动」（即从一个 common component package 删除并添加到另一个）从 organization-specific common component package 到 global common component package 或反之。
  - 若发现比原先预期更广泛适用，common component 可以从 organization-specific common component package 复制到 global common component package（不删除原始组件）。
- 字段不应当添加到现有 messages。
- 值不应当添加到现有 enums。
- 字段不得从现有 messages 中移除。
- 值不得从现有 enums 中移除。
- 尽管文档可以被澄清，它不应当改变现有值的含义，包括任何给定 message 或一组 messages 的有效性。
- 新的 proto messages 与 enums 可以添加到 common component packages。
  - API 团队应当在其 APIs 中使用新 messages 与 enums 之前，允许足够时间传播到客户端。字段可能需要一些时间才能通过发布传播到客户端库与其它表面。
  - API 团队应当在添加新 message 或 enum 之前在其组织内广泛咨询，理想情况下与 API 设计团队咨询，因为有上述限制。

## 现有的 global common components

下列 global common components，API 的面向公众的 protos 可以安全导入：

- [`google.api.*`](https://github.com/googleapis/googleapis/blob/master/google/api)（但不是 `google.api` 的子 packages）
- [`google.longrunning.Operation`](https://github.com/googleapis/googleapis/blob/master/google/longrunning/operations.proto)
- [`google.protobuf.*`](https://github.com/protocolbuffers/protobuf/tree/master/src/google/protobuf)
- [`google.rpc.*`](https://github.com/googleapis/googleapis/blob/master/google/rpc/)
- [`google.type.*`](https://github.com/googleapis/googleapis/tree/master/google/type)

注意某些 common components 可能有仅内部字段。APIs 应当一般只依赖已 [发布到开源](https://github.com/googleapis/googleapis) 的字段。

Google APIs 也可以导入 [`google.iam.v1.*`](https://github.com/googleapis/googleapis/tree/master/google/iam/v1)，它提供 Google 通篇使用的 IAM messages。

许多 APIs 也为仅内部使用从其它 packages 导入组件（例如应用 visibility labels 或向内部基础设施提供指令）。只要公开组件不含此类引用，这是可接受的。

### Protobuf types

`google.protobuf` package 有些特殊，因为它随 protocol buffers 本身一起发布，而不是随 API 工具。对大多数 API 设计者，这应是实现细节。

此 package 包含一个用于表示常见编程语言构造的小型类型库：

- [`google.protobuf.Duration`](https://github.com/protocolbuffers/protobuf/blob/master/src/google/protobuf/duration.proto)：时长，具有纳秒级精度。protobuf runtime 提供辅助函数，在适用时转换为语言原生 duration 对象（例如 Python 的 [`timedelta`](https://docs.python.org/3/library/datetime.html#datetime.timedelta)）。
- [`google.protobuf.Struct`](https://github.com/protocolbuffers/protobuf/blob/master/src/google/protobuf/struct.proto)：类 JSON 结构（原语、列表与其它字典的字典）。protobuf runtime 在大多数语言中提供辅助函数，把 struct 对象转换为 JSON。
- [`google.protobuf.Timestamp`](https://github.com/protocolbuffers/protobuf/blob/master/src/google/protobuf/timestamp.proto)：时间戳，具有纳秒级精度。protobuf runtime 在大多数语言中提供辅助函数，转换为语言原生 timestamp 对象（例如 Python 的 [`datetime`](https://docs.python.org/3/library/datetime.html#datetime.datetime)）。

### API Types

`google.type` package 提供用于表示 APIs 中常见概念的类型「标准库」。尽管类型不时添加，确定列表始终是 [the code](https://github.com/googleapis/googleapis/tree/master/google/type)，若干类型值得注意：

- [`google.type.Color`](https://github.com/googleapis/googleapis/blob/master/google/type/color.proto)：RGB 或 RGBA 颜色。
- [`google.type.Date`](https://github.com/googleapis/googleapis/blob/master/google/type/date.proto)：日历日期，无时间或时区组件。
- [`google.type.DayOfWeek`](https://github.com/googleapis/googleapis/blob/master/google/type/dayofweek.proto)：星期几，无其它日期、时间或时区组件。
- [`google.type.LatLng`](https://github.com/googleapis/googleapis/blob/master/google/type/latlng.proto)：地理坐标。
- [`google.type.Money`](https://github.com/googleapis/googleapis/blob/master/google/type/money.proto)：货币。
- [`google.type.PostalAddress`](https://github.com/googleapis/googleapis/blob/master/google/type/postal_address.proto)：大多数国家的邮政地址。
- [`google.type.TimeOfDay`](https://github.com/googleapis/googleapis/blob/master/google/type/timeofday.proto)：墙上时钟时间，无日期或时区组件。

### 往公共 protos 里加东西

偶尔，把 protos 添加到这些 packages 或添加到常用 protos 列表可能有用。为此，在 GitHub 上的 AIP 仓库 [open an issue](https://github.com/googleapis/aip/issues)，并注意上述指导。

## 现有的 organization-specific common component packages

下列 organization-specific common component packages 存在并符合上述指导：

- [`google.apps.script.type`](https://github.com/googleapis/googleapis/tree/master/google/apps/script/type)
  Google Apps Script 的 common component package。
- [`google.geo.type`](https://github.com/googleapis/googleapis/tree/master/google/geo/type)
  Google Maps 与 Geo 组织的 common component package。
- [`google.actions.type`](https://github.com/googleapis/googleapis/tree/master/google/actions/type)

- [`google.shopping.type`](https://github.com/googleapis/googleapis/tree/master/google/shopping/type)
  Google Shopping 的 common component package。

## 不合规的 common component packages

下列 common component packages 存在，但不符合上述指导，并且不构成进一步此类 packages 的先例。

- [`google.cloud.common`](https://github.com/googleapis/googleapis/tree/master/google/cloud/common)：
  这不符合 package 名必须以 `.type` 结尾的要求。（否则这会是可接受的，并且此 package 应视为 Cloud common component package。）
- [`google.logging.type`](https://github.com/googleapis/googleapis/tree/master/google/logging/type)：
  这看起来是 API 特定的，尽管它从多个 APIs 使用；某些方面可能应是全局的或在 Cloud common component package 中。
- [`google.cloud.workflows.type`](https://github.com/googleapis/googleapis/tree/master/google/cloud/workflows/type)：
  API 特定类型。
- [`google.cloud.oslogin.common`](https://github.com/googleapis/googleapis/tree/master/google/cloud/oslogin/common)：
  API 特定类型，以及不符合的名称。
- [`google.identity.accesscontextmanager.type`](https://github.com/googleapis/googleapis/tree/master/google/identity/accesscontextmanager/type)：
  API 特定类型。
- [`google.networking.trafficdirector.type`](https://github.com/googleapis/googleapis/tree/master/google/networking/trafficdirector/type)：
  API 特定类型。

## 为什么

Common components 实际上是无版本的：APIs 彼此独立演进，无论是定义还是实现。诸如添加字段之类的变更在特定 APIs 中是向后兼容且可预测的，并且 API 团队可以确保在 API 定义发布之前服务器实现可用。相比之下，common component 中的变更实际上会普遍可用，即使大多数 API 实现并未考虑它。

添加新 message 或 enum 是向后兼容的，因为它不影响可能从同一 common component package 导入其它 messages 或 enums 的现有 APIs。

对 global common components 需要与 API 设计团队咨询，对 organization-specific common components 建议咨询，因为「通用」与「组织特定」之间的边界是灰色地带；某些通用概念有通过组件浮现的组织特定用例。
