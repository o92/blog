遵循面向资源的设计（[AIP-121]({{< ref "aip-0121" >}})）的 APIs 用 [RPCs](https://en.wikipedia.org/wiki/Remote_procedure_call) 定义，但面向资源的设计框架允许它们也呈现为大体遵循 REST/JSON 约定的 APIs。这对帮助开发者使用其现有知识很重要：超过 80% 的公开可用 APIs 遵循大多数 REST 约定，开发者习惯该模式。

## Guidance

APIs **must** 为它们定义的每个 RPC 提供 HTTP 定义，双向流 RPCs 除外，它们无法用 HTTP/1.1 原生支持。提供双向流方法时，API **should** 也提供不依赖双向流的替代方法。

### HTTP method and path

使用 protocol buffers 时，每个 RPC **must** 用 `google.api.http` 注解定义 HTTP 方法与路径：

```proto
rpc CreateBook(CreateBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books"
    body: "book"
  };
}

message CreateBookRequest {
  // The publisher who will publish this book.
  // When using HTTP/JSON, this field is automatically populated based
  // on the URI, because of the `{parent=publishers/*}` syntax.
  string parent = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference) = {
      child_type: "library.googleapis.com/Book"
    }];

  // The book to create.
  // When using HTTP/JSON, this field is populated based on the HTTP body,
  // because of the `body: "book"` syntax.
  Book book = 2 [(google.api.field_behavior) = REQUIRED];

  // The user-specified ID for the book.
  // When using HTTP/JSON, this field is populated based on a query string
  // argument, such as `?bookId=foo`. This is the fallback for fields that
  // are not included in either the URI or the body.
  // Note that clients use camelCase format to communicate the field names
  // to the service.
  string book_id = 3;
}
```

- 第一个键（本例中的 `post`）对应 HTTP 方法。RPCs **may** 使用 `get`、`post`、`patch` 或 `delete`。
  - RPCs **must** 对每个标准方法使用规定的 HTTP 动词，如 [AIP-131]({{< ref "aip-0131" >}})、[AIP-132]({{< ref "aip-0132" >}})、[AIP-133]({{< ref "aip-0133" >}})、[AIP-134]({{< ref "aip-0134" >}}) 与 [AIP-135]({{< ref "aip-0135" >}}) 所讨论。
  - RPCs **should** 对 custom methods 使用规定的 HTTP 动词，如 [AIP-136]({{< ref "aip-0136" >}}) 所讨论。
  - RPCs **should not** 使用 `put` 或 `custom`。
- 对应值表示 URI。
  - URIs **must** 使用 `{foo=bar/*}` 语法表示应填充到请求 proto 中的变量。提取 resource name（[AIP-122]({{< ref "aip-0122" >}})）时，该变量 **must** 包含整个 resource name，而不仅仅是 ID 组件。
  - URIs **may** 对其变量名使用嵌套字段。（此外，AIP-134 对 `Update` 请求强制这样做。）
  - URIs **must** 使用 `*` 字符表示 ID 组件，它匹配除 `/` 外的所有 URI-safe 字符。若需要匹配 `/`，URIs **may** 把 `**` 用作 URI 的最后一段。
- `body` 键定义请求中哪个单个顶层字段将作为 HTTP body 发送。若 body 为 `*`，则表明请求对象本身是 HTTP body。请求 body 按 protocol buffers 的规范 [JSON encoding](https://developers.google.com/protocol-buffers/docs/proto3#json) 编码为 JSON。
  - 对使用 `GET` 或 `DELETE` HTTP 动词的 RPCs，RPCs **must not** 定义 `body`。
  - RPCs **must** 对 Create（[AIP-133]({{< ref "aip-0133" >}}））与 Update（[AIP-134]({{< ref "aip-0134" >}}））请求使用规定的 `body`。
  - RPCs **should** 对 custom methods（[AIP-136]({{< ref "aip-0136" >}}））使用规定的 `body`。
  - `body` **must not** 包含嵌套字段（或使用 `.` 字符），
  - `body` **must not** 与 URI 参数相同。
  - `body` **must not** 是 `repeated` 字段。
  - 字段 **should not** 使用 `json_name` 注解来改变 JSON 中的字段名，除非为向后兼容原因这样做。

**Note:** 双向流 RPCs 根本不应包含 `google.api.http` 注解。若可行，服务 **should** 提供非流式等价 RPCs。

### Multiple URI bindings

偶尔，一个 RPC 需要对应不止一个 URI：

```proto
rpc CreateBook(CreateBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books"
    body: "book"
    additional_bindings: {
      post: "/v1/{parent=authors/*}/books"
      body: "book"
    }
    additional_bindings: {
      post: "/v1/books"
      body: "book"
    }
  };
}
```

- RPCs **may** 定义任意数量的 additional bindings。结构与 `google.api.http` 注解相同（实际上，它是递归引用）。
- RPCs **must not** 在 additional binding 内定义 additional binding。
- `body` 子句在顶层注解与每个 additional binding 中 **must** 相同。
