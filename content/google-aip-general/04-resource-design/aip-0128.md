**英文标题**：Declarative-friendly interfaces  
**原文**：[AIP-128](https://google.aip.dev/128) · approved · 创建 2020-10-06

许多服务需要与常见 DevOps 工具交互，尤其是创建并管理可网络寻址资源的工具（例如虚拟机、负载均衡器、数据库实例等）。这些工具围绕「configuration as code」原则：用户指定完整的意图景观，由工具负责做出达到用户规格所需的任何变更。

这些工具是 **declarative** 的：它们不指定要采取的具体 *actions*，而指定期望的 *outcome*，动作则根据当前景观与意图景观之间的差异推导出来。

此外，流行的 DevOps 工具众多，每年还有更多被引入。把数百种资源类型与多种工具集成需要统一性，以便集成可以自动化。

## Guidance

### Resources

声明式友好的资源 **must** 只使用强一致的标准方法来管理资源生命周期，这使工具能通用地支持这些资源，并符合其它声明式友好指导（见 [further reading](#further-reading)）。

声明式友好的资源 **should** 标明它们遵循声明式友好风格：

```proto
message Book {
  option (google.api.resource) = {
    type: "library.googleapis.com/Book"
    pattern: "publishers/{publisher}/books/{book}"
    style: DECLARATIVE_FRIENDLY
  };

  // Name and other fields...
}
```

### Reconciliation

若资源需要时间（多于几秒）才能实现更新，该资源 **should** 包含 `bool reconciling` 字段，以披露变更正在进行中。该字段 **must** 为 output only。

若资源的当前状态与用户意图状态不匹配，且系统正在调和它们，资源 **must** 把 `reconciling` 字段设为 `true`。无论进入调和的根因是用户动作还是系统动作，都是如此。

**Note:** 服务响应 `GET` 请求时 **must** 返回资源的当前状态（不是意图状态）。

## Further reading

由于聚焦于这些资源之上的自动化，大量指导对声明式友好接口更严格。下列是其它 AIPs 中声明式友好指导的完整参照：

- 资源 **should not** 使用 custom methods：见 AIP-136。
- 资源 **must** 对 repeated fields 使用 `Update` 方法：见 AIP-144。
- 资源 **must** 包含某些标准字段：见 AIP-148。
- 资源 **must** 有 `etag` 字段：见 AIP-154。
- 资源 **should** 提供变更校验：见 AIP-163。
- 资源 **should not** 实现 soft-delete。若 id 不能复用，资源 **must** 实现 soft-delete 以及 undelete RPC：见 AIP-164。
