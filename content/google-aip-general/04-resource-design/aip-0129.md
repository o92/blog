服务常常为资源字段提供默认值，偶尔也会在响应中返回之前先规范化用户输入。本文的指导描述服务如何为消费者的利益文档化此类行为。

## Guidance

### Single Owner Fields

字段 **must** 有单一所有者，无论是客户端还是服务器。服务器拥有的字段 **must** 用 `OUTPUT_ONLY` field_behavior 标明。所有其它类型的字段 **must** 视为由客户端拥有。服务器 **must** 尊重所有客户端拥有字段的值（或其缺失），并且不得修改它们。

### Effective Values

有些情形下，若客户端选择不指定某个值，服务会分配、生成或计算一个值。例如：客户端创建虚拟机时未指定静态 IP 地址供该虚拟机使用。这种情形是在选择动态 IP 地址分配。

这类字段的一些例子是：

- 生成的（UUID）
- 分配的（动态 IP 地址）
- 指定的（最近的软件包版本）

具有生效值的属性 ***must*** 在 API 中表达为两个字段：

- 一个可变字段，可由用户可选设置，并且 **must not** 被服务修改
- 一个 `OUTPUT_ONLY` 字段，记录服务决定的生效值

示例：

```proto
message VirtualMachine {
  …
  string ip_address = 4;
  string effective_ip_address = 5 [
    (google.api.field_behavior) = OUTPUT_ONLY
  ];
}
```

#### Naming

生效值 **must** 通过在可变字段名前加前缀 `effective_` 来命名。

### User-Specified Fields

对用户指定的字段，服务响应中的值 **must** 与 create 或 update 请求所提供的相同。对 string 字段，这意味着原样返回该值，只有一个例外：

- 当 string 字段有 data type annotation 时，**may** 返回表示给定值的规范化 string。

### Normalizations

被服务规范化的字段 **must** 用 `google.api.field_info` 扩展标注。使用此扩展的指导见 [AIP-202]({{< ref "aip-0202" >}})。允许的规范化集合包括以下格式：

- uuid
- ipv4
- ipv6
- email

字段上的规范化 **must** 使用 `google.api.field_info` annotation 描述。

## Rationale

服务端修改与默认值常常使实现 Declarative Clients（[AIP-9]({{< ref "aip-0009" >}})）更难。这些客户端常常无法判断其期望状态何时与这些字段的当前状态匹配，因为服务可能修改并返回值的规则复杂、不公开、且不可重复。

### Single Owner Fields 的理由

当字段没有单一所有者时，它们会给 Declarative Clients（[AIP-9]({{< ref "aip-0009" >}})）带来问题。这些客户端可能试图为会被服务器设置的值覆盖的字段设值，导致客户端进入无限循环来纠正该变更。

### Naming 的理由

一致的命名对跨 APIs 与字段识别标准行为很重要。用户指定值与生效值之间的程序化关联依赖于一致命名。

### Normalizations 的理由

规范化很重要，它让服务能以标准方式存储并返回值，同时向客户端传达哪些变更在语义上相同。在服务侧规范化值，让服务能接受更广范围的语义相同输入，而无需把每个值都作为原始 string 维护。向客户端披露正在应用的规范化，使客户端能对发送值与取回值做比较以检查差异。

例如，在某资源的特定字段上接受电子邮件地址时，客户端可能以多种方式指定给定电子邮件地址。对电子邮件 `ada@example.com`，客户端可能选择指定 `ADA@example.com`、`aDa@example.com` 或 `AdA@example.com`。这些在语义上相同，并且 *should* 全部被服务接受。服务随后可能选择通过小写化或规范化来规范化该电子邮件地址以便存储与检索。重要的是，向客户端披露的字段规范化信息不会描述规范化算法本身，而是用来准确计算两个值是否应视为相等的比较方法。

### Field Value Handling 的理由

对未使用允许的规范化的字段，Declarative Clients（[AIP-9]({{< ref "aip-0009" >}})）将无法识别哪些变更在语义上有意义。当 Declarative Client（[AIP-9]({{< ref "aip-0009" >}})）发送特定值时，它会确保该值正被服务返回，以校验它被正确设置。
