字段只接受或只提供离散且有限的一组值，是常见的。在这些情形下，使用 enumerations（一般缩写为 "enums"）可以清楚传达允许值的集合。

## Guidance

APIs **may** 为预期不频繁变化的值集合暴露 enum 对象：

```proto
// A representation of a book.
message Book {
  // Other fields...

  // Possible formats in which the book may be published.
  enum Format {
    // Default value. This value is unused.
    FORMAT_UNSPECIFIED = 0;

    // The printed format, in hardback.
    HARDBACK = 1;

    // The printed format, in paperback.
    PAPERBACK = 2;

    // An electronic book format.
    EBOOK = 3;

    // An audio recording.
    AUDIOBOOK = 4;
  }

  // The format of the book.
  Format format = 99;

  // Other fields...
}
```

- 所有 enum 值 **must** 使用 `UPPER_SNAKE_CASE`。
- enum 的第一个值 **should** 是 enum 名称本身后接后缀 `_UNSPECIFIED`。
  - 此规则的例外是存在明显有用的零值。特别是，若 enum 需要呈现 `UNKNOWN`，把它作为零值通常比两者都有更清楚、更有用。`UNKNOWN` 值 **may** 以 enum 名称为前缀，这是避免 enum 值名冲突的典型做法。
- 只在单个 message 中使用的 enums **should** 嵌在该 message 内。此时，enum **should** 在使用它之前立即声明。
  - 这种嵌套 enum 定义的非零值 **should not** 以 enum 名称本身为前缀。这通常会让用户在代码里写成 `MyState.MYSTATE_ACTIVE`，不必要地冗长。
- 会被多个 messages 使用的 enums **should** 在 package 级定义，并且 **should** 定义在 proto 文件底部（见 [AIP-191]({{< ref "aip-0191" >}})）。
  - 某些语言（包括 C++）会把 enum 值提升到父命名空间，这可能导致同一 proto package 中具有相同值的 enums 发生冲突。为避免共享值，APIs **should** 用 enum 名称给 package 级 enum 值加前缀。
- Enums **should** 文档化该 enum 是冻结的，还是预期将来会增加值。

### 何时使用 enums

在许多情形下，enums 可能比 strings 或 booleans 更易接近、更可读，但它们在变更时会增加开销。因此，enums **should** 不频繁接收新值。尽管「不频繁」的定义可能随个别用例而变，一个好的经验法则是每年不超过一次。对频繁变化的 enums，API **should** 使用 string 并文档化格式。

此外，当存在相互竞争、被广泛采用的标准表示时（例如 [language codes](https://en.wikipedia.org/wiki/IETF_language_tag) 或 [media types](https://en.wikipedia.org/wiki/Media_type)），**should not** 使用 enums。

**Note:** 若枚举值需要跨 APIs 共享，**may** 使用 enum，但 enum 值与其对应整数之间的赋值 **must** 匹配。

### Alternatives

对允许值集合频繁变化的枚举值，APIs **should** 改用 `string` 字段，并且 **must** 文档化允许值。带枚举值的 string 字段 **should** 对其值使用 `kebab-case`。

对存在相互竞争、被广泛采用的标准表示（一般但不一定是 string）的枚举值，**should** 使用该标准表示。即使只允许很小的子集，这也成立，因为在此情形使用 enums 常常导致在把多个 APIs 一起使用时出现令人沮丧的查找表。

在清楚不需要进一步灵活性的情形下，**may** 使用 boolean 字段。默认值 **must** 为 `false`。

**Note:** 使用 protocol buffers 时，无法区分 `false` 与未设置。若这是一项要求，enum **may** 是更好的设计选择（尽管 `google.protobuf.BoolValue` 也可用）。
