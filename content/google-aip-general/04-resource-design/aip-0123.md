单个 API 里，资源类型名只要自己 internally 不撞车就行。不同 API 用同一个短名常常是好事：Memcache 和 Redis 都想叫 `Instance`。

一旦要把「哪家 API 的哪种资源」画到一张图上，短名就不够了。Kubernetes、GraphQL 这类工具还会同时碰到多家提供方的 API。这时需要一个全局唯一的类型名。

## 两个词

- **Service Name：** [service configuration](https://github.com/googleapis/googleapis/blob/master/google/api/service.proto) 里定义的名称。通常（但不一定）就是用户调这个服务时用的主机名。例如 `pubsub.googleapis.com`。对应 Kubernetes 里的 [API Group](https://kubernetes.io/docs/concepts/overview/kubernetes-api/#api-groups)。
- **Type：** API 内给这个类型起的名字，例如 Protobuf `message` 的名称。对应 Kubernetes 里的 [Object](https://github.com/kubernetes/community/blob/master/contributors/devel/sig-architecture/api-conventions.md#types-kinds)。

## 类型名怎么写

API 必须为每个资源定义资源类型，模式是 `{Service Name}/{Type}`。其中 Type 必须：

- 与包含它的 API 类型名称匹配。
- 以大写字母开头。
- 只含字母数字字符。
- 是该名词的单数。
- 用 PascalCase（UpperCamelCase）。

### 例子

- `pubsub.googleapis.com/Topic`
- `pubsub.googleapis.com/Subscription`
- `spanner.googleapis.com/Database`
- `spanner.googleapis.com/Instance`
- `networking.istio.io/Instance`

### 怎么标注

应当用 [`google.api.resource`](https://github.com/googleapis/googleapis/blob/master/google/api/resource.proto) 给每个资源标上类型：

```proto
// A representation of a Pub/Sub topic.
message Topic {
  option (google.api.resource) = {
    type: "pubsub.googleapis.com/Topic"
    pattern: "projects/{project}/topics/{topic}"
    singular: "topic"
    plural: "topics"
  };

  // Name and other fields...
}
```

- Patterns 必须对应 resource name（见 [AIP-122]({{< ref "aip-0122" >}})）。
- Pattern 变量（花括号里的段）必须用 `snake_case`，不得加 `_id` 后缀。
- Pattern 变量必须符合 `[a-z][_a-z0-9]*[a-z0-9]`。
- 同一条 pattern 里，变量名必须唯一。（`projects/{abc}/topics/{abc}` 无效。通常 collection identifiers 在 pattern 里本来就不该重复，这条是它的自然推论。）
- 资源有 [多个 patterns](https://google.aip.dev/client-libraries/4231#multi-pattern-resources) 时，顺序必须稳住：新 patterns 必须加在列表末尾；既有的不得删、不得重排。否则 client library 向后兼容会破。
- Singular 必须是该类型的 lower camel case。
  - Pattern 变量必须是资源类型的单数。例如 `Topic` 的 resource ID 变量叫 `{topic}`。
- Plural 必须是 singular 的 lower camel case 复数。
  - Pattern 的 collection identifier 必须匹配这些资源的 plural。嵌套集合（见 [AIP-122]({{< ref "aip-0122" >}})）可以例外。

#### Pattern 不得撞车

一个资源上定义多条 patterns 时，这些 patterns 必须彼此唯一。唯一性的算法：去掉所有 resource ID 路径段、留下所有 `/` 分隔符之后，按字符完全相同就算撞车。

因此下面两条不得写在同一资源上：

- `user/{user}`
- `user/{user_part_1}~{user_part_2}`

## 为什么

### Type 与 message 名对齐

除了 schema 和资源对得上以外，消费者也省事：查找更简单；client libraries 里面向资源的代码名能跟生成的 `message` 对齐；参考文档也能把资源和 `message` 对在一起。

### Singular 与 Plural

单复数定清楚，客户端才知道代码和文档里该用哪个词。

lowerCamelCase 可以翻译成其它常见形式，例如 UpperCamelCase 与 snake_case。
