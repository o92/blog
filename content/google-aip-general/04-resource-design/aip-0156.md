**英文标题**：Singleton resources  
**原文**：[AIP-156](https://google.aip.dev/156) · approved · 创建 2019-05-12  
**许可**：原文 © Google，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

有的资源在任意给定 parent 下永远恰好一个。最常见的是 config。它不该再走 Create / Delete：parent 在，它就在；parent 没了，它也没了。

## 怎么建模

API 可以定义 *singleton resources*。Singleton 必须因其 parent 的存在而始终存在，每个 parent 恰好一个。

例如：

```proto
message Config {
  option (google.api.resource) = {
    type: "api.googleapis.com/Config"
    pattern: "users/{user}/config"
    singular: "config"
    plural: "configs"
  };

  // additional fields including name
}
```

`Config` singleton 会有下列 RPCs：

```proto
rpc GetConfig(GetConfigRequest) returns (Config) {
  option (google.api.http) = {
    get: "/v1/{name=users/*/config}"
  };
}

rpc UpdateConfig(UpdateConfigRequest) returns (Config) {
  option (google.api.http) = {
    patch: "/v1/{config.name=users/*/config}"
    body: "config"
  };
}
```

- Singleton 不得有用户提供或系统生成的 ID。resource name（见 [AIP-122]({{< ref "aip-0122" >}})）是 parent 的名称后接一个静态段。
  - 例如：`users/1234/config`
- Singleton 始终是单数。
  - 例如：`users/1234/thing`
- Singleton 的资源定义必须提供 `singular` 与 `plural` 字段（见上例）。
- Singleton 可以作为其它资源的 parent。
- Singleton 不得定义 Create（见 [AIP-133]({{< ref "aip-0133" >}})）或 Delete（见 [AIP-135]({{< ref "aip-0135" >}})）。parent 被创建或删除时，这个 singleton 被隐式创建或删除。
- Singleton 应当定义 Get（见 [AIP-131]({{< ref "aip-0131" >}})）与 Update（见 [AIP-134]({{< ref "aip-0134" >}})），并可以按合适程度定义 custom methods。
  - 若资源上所有字段都是 output only（见 [AIP-203]({{< ref "aip-0203" >}})），则不得定义 Update。
- Singleton 可以定义 List（见 [AIP-132]({{< ref "aip-0132" >}})），但必须按 [AIP-159]({{< ref "aip-0159" >}}) 实现。见下面的示例。
  - 路径 pattern 里通常表示集合的末段，应当用 Singleton 的 `plural`，例如 `/v1/{parent=users/*}/configs`。
  - 若按 AIP-159 给的是具体 parent resource ID 而不是连字符 `-`，服务应当返回对应该 parent 的、只含一个 Singleton 的集合。

```proto
rpc ListConfigs(ListConfigsRequest) returns (ListConfigsResponse) {
  option (google.api.http) = {
    get: "/v1/{parent=users/*}/configs"
  };
}

message ListConfigsRequest {
  // To list all configs, use `-` as the user id.
  // Formats:
  // * `users/-`
  // * `users/{user}`
  //
  // Note: Specifying an actual user id will return a collection of one config.
  // Use GetConfig instead.
  string parent = 1 [
    (google.api.resource_reference).child_type = "api.googleapis.com/Config"];

  // other standard pagination fields...
}
```

## 为什么

### 为什么还要 Standard List

Singleton 本身并不直接属于某个集合，但可以看成 parent 集合的一部分。parent 与 singleton 一对一：每个 parent 都有一个实例。再叠上跨集合读取（见 [AIP-159]({{< ref "aip-0159" >}})），基于集合的方法就自然能用。对 API 消费者来说，它间接地基于 parent 而成集合。以后若发现 Singleton 不够用，也更容易扩成真正的集合。

### 为什么还要 `plural`

Singleton 按定义是单数的。但有些场合会以复数出现，例如服务支持上面的 Standard List。预先声明复数形式，总比需要时没有好。
