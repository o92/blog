**英文标题**：Singleton resources  
**原文**：[AIP-156](https://google.aip.dev/156) · approved · 创建 2019-05-12  
**许可**：原文 © Google，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

APIs 有时需要表示这样一种资源：在任意给定 parent 内始终恰好存在一个实例。常见用例是 config 对象。

## Guidance

API **may** 定义 *singleton resources*。Singleton resource **must** 因其 parent 的存在而始终存在，每个 parent 恰好一个。

例如：

```proto
message Config {
  option (google.api.resource) = {
    type: "api.googleapis.com/Config"
    pattern: "users/{user}/config"
    singular: "config"
    plural: "configs"
  };

  // additional fields including name
}
```

`Config` singleton 会有下列 RPCs：

```proto
rpc GetConfig(GetConfigRequest) returns (Config) {
  option (google.api.http) = {
    get: "/v1/{name=users/*/config}"
  };
}

rpc UpdateConfig(UpdateConfigRequest) returns (Config) {
  option (google.api.http) = {
    patch: "/v1/{config.name=users/*/config}"
    body: "config"
  };
}
```

- Singleton resources **must not** 有用户提供或系统生成的 ID；其 resource name（[AIP-122]({{< ref "aip-0122" >}})）包含其 parent 的名称后接一个静态段。
  - 示例：`users/1234/config`
- Singleton resources 始终是单数。
  - 示例：`users/1234/thing`
- Singleton resource 定义 **must** 提供 `singular` 与 `plural` 字段（见上例）。
- Singleton resources **may** 作为其它资源的 parent。
- Singleton resources **must not** 定义 Create（[AIP-133]({{< ref "aip-0133" >}})）或 Delete（[AIP-135]({{< ref "aip-0135" >}})）标准方法。当其 parent 被创建或删除时，该 singleton 被隐式创建或删除。
- Singleton resources **should** 定义 Get（[AIP-131]({{< ref "aip-0131" >}})）与 Update（[AIP-134]({{< ref "aip-0134" >}})）方法，并且 **may** 按合适程度定义 custom methods。
  - 然而，若资源上的所有字段都是 output only（[AIP-203]({{< ref "aip-0203" >}})），singleton resources **must not** 定义 Update（[AIP-134]({{< ref "aip-0134" >}})）方法。
- Singleton resources **may** 定义 List（[AIP-132]({{< ref "aip-0132" >}})）方法，但 **must** 按 [AIP-159]({{< ref "aip-0159" >}}) 实现。见下面的示例。
  - 路径 pattern 中通常表示集合的末段 **should** 为 Singleton 资源的 `plural` 形式，例如 `/v1/{parent=users/*}/configs`。
  - 若按 AIP-159 提供了 parent resource ID 而不是连字符 `-`，则服务 **should** 返回对应该指定 parent 资源的、含一个 Singleton 资源的集合。

```proto
rpc ListConfigs(ListConfigsRequest) returns (ListConfigsResponse) {
  option (google.api.http) = {
    get: "/v1/{parent=users/*}/configs"
  };
}

message ListConfigsRequest {
  // To list all configs, use `-` as the user id.
  // Formats:
  // * `users/-`
  // * `users/{user}`
  //
  // Note: Specifying an actual user id will return a collection of one config.
  // Use GetConfig instead.
  string parent = 1 [
    (google.api.resource_reference).child_type = "api.googleapis.com/Config"];

  // other standard pagination fields...
}
```

## Rationale

### 对 Standard List 的支持

尽管 Singleton resources 本身并不直接属于某个集合，它们可以被视为其 parent 集合的一部分。parent 与 singleton 的一对一关系意味着每一个 parent 都有一个 singleton 实例，当与 Reading Across Collections（[AIP-159]({{< ref "aip-0159" >}})）的模式结合时，自然能启用某些基于集合的方法。Singleton 可以向 API 消费者呈现为集合，因为它间接地基于其 parent 而成其为集合。此外，在此类方法中把 Singleton 资源呈现为伪集合，使将来若发现 Singleton 不够用时，能够扩展为真正的集合。

### 包含 `plural` 定义

尽管 Singleton 按定义是单数的，在某些情形下 Singleton 资源可能以复数形式出现，例如若服务支持 Standard List（如本文所定义）。因此，预先声明 Singleton 资源类型的复数形式，比需要时没有它更好。
