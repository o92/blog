**英文标题**：Resource names  
**原文**：[AIP-122](https://google.aip.dev/122) · approved · 创建 2019-01-26  
**许可**：原文 © Google，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

大多数 APIs 暴露 *resources*（其主要名词），用户可以创建、检索与操作它们。此外，resources 是 *named* 的：每个资源都有用户用来引用该资源的唯一标识符，这些 names 就是用户应 *存储* 为资源规范名的东西。

## Guidance

API 定义的所有 resource names **must** 在该 API 内唯一。（跨 APIs 引用资源见下文 [完整资源名称](#完整资源名称)。）

Resource names 按 [URI path schema](https://datatracker.ietf.org/doc/html/rfc3986#appendix-A) 格式化，但没有前导斜杠：

    publishers/123/books/les-miserables
    users/vhugo1802

- Resource name 的各段 **should** 通常在 collection identifiers（例如 `publishers`、`books`、`users`）与 resource IDs（例如 `123`、`les-miserables`、`vhugo1802`）之间交替。
- Resource names **must** 使用 `/` 字符分隔资源名称的各个 segment。
  - Resource name 的非末段 **must not** 包含 `/` 字符。
  - Resource name 的末段 **should not** 包含 `/` 字符。
- Resource names **should** 只使用 [RFC-1123](https://tools.ietf.org/html/rfc1123) 所定义的 DNS 名中可用的字符。
  - 此外，resource IDs **should not** 使用大写字母。
  - 若必须使用额外字符，resource names **should not** 使用需要 URL-escaping 的字符，或 ASCII 以外的字符。
  - 若无法避免 Unicode 字符，resource names **must** 以 Normalization Form C 存储（见 [AIP-210]({{< ref "aip-0210" >}})）。
- Resources **must** 暴露包含其 resource name 的 `name` 字段。
  - Resources **may** 把 resource ID 作为单独字段提供（例如 `book_id`）。该字段 **must** 应用 [`OUTPUT_ONLY`]({{< ref "aip-0203" >}}) field behavior 分类。
  - Resources **may** 暴露单独的、系统生成的唯一 ID 字段 [`uid`]({{< ref "aip-0148" >}})。该字段 **must** 应用 [`OUTPUT_ONLY`]({{< ref "aip-0203" >}}) field behavior 分类。
  - Resources **must not** 暴露元组、self-links 或其它形式的资源标识。
  - 所有 ID 字段 **should** 是 strings。

**Note:** 此处描述的 resource names 用于单个 API 的范围（或拥有方 API 从上下文中已经清楚的情形），并且只要求在该范围内唯一。因此它们有时称为 *relative resource names*，以区别于 *full resource names*（下文讨论）。

### Collection identifiers

Resource name 中的 collection identifier 段 **must** 是该资源所用名词的复数形式。（例如，`Publisher` 资源的集合在 resource name 中称为 `publishers`。）

- Collection identifiers **must** 是简洁的美式英语术语。
- Collection identifiers **must** 为 `camelCase`。
- Collection identifiers **must** 以小写字母开头，且只含 ASCII 字母与数字（`/[a-z][a-zA-Z0-9]*/`）。
- Collection identifiers **must** 为复数。
  - 在没有复数词（"info"），或单复数相同（"moose"）的情形下，使用非复数（单数）形式是正确的。Collection segments **must not** 通过加 "s" 来「造词」（例如避免 "infos"）。
- 在任意给定的单个 resource name 内，collection identifiers **must** 唯一。（例如 `people/xyz/people/abc` 无效）

#### Nested collections

若 resource name 含多层层级，且 parent collection 的名称被用作 child resource 名称的前缀，则 child collection 的名称 **may** 省略该前缀。例如，给定通常嵌在 `users` 下的 `UserEvent` 资源集合：

```
users/vhugo1802/userEvents/birthday-dinner-226
```

API **should** 使用冗余更少的形式：

```
users/vhugo1802/events/birthday-dinner-226
```

在此情形下，*message* 与 *resource type* 仍称为 `UserEvent`；只有 pattern(s) 中的 collection 与 resource identifiers 被缩短。由于 *resource type* 未缩短，`singular` 与 `plural` 同样 *不缩短*。

```
message UserEvent {
  option (google.api.resource) = {
    type: "example.googleapis.com/UserEvent"
    // Only the collection & resource identfiers in the `pattern` are shortened.    
    pattern: "projects/{project}/users/{user}/events/{event}"
    singular: "userEvent"
    plural: "userEvents"
  };

  string name = 1;
}
```

**Note:** 希望这样做的 APIs **must** 在其定义的所有 `pattern` 条目以及 API 中引用该资源的任何其它地方一致遵循此格式，否则就完全不要这样做。

### Resource ID segments

Resource ID 段在其 parent collection 内标识该资源。在 resource name `publishers/123/books/les-miserables` 中，`123` 是 publisher 的 resource ID，`les-miserables` 是 book 的 resource ID。

- 若 resource IDs 由用户指定，API **must** 文档化允许的格式。用户指定的 resource IDs **should** 符合 [RFC-1034](https://tools.ietf.org/html/rfc1034)；该规范限制为字母、数字与连字符，首字符为字母，末字符为字母或数字，最长 63 个字符。
  - 此外，用户指定的 resource IDs **should** 把字母限制为小写（正则：以小写字母开头，中间最多 61 个 `a-z` / `0-9` / `-`，并以小写字母或数字结尾）。
  - **should not** 允许 ASCII 以外的字符；然而，若必须使用 Unicode 字符，APIs **must** 遵循 [AIP-210]({{< ref "aip-0210" >}}) 的指导。
- 若 resource IDs 不可由用户设置，API **should** 文档化基本格式以及任何上限（例如「最多 63 个字符」）。
- 更多信息见 [create]({{< ref "aip-0133" >}}) 标准方法。

### Resource ID aliases

有时为常见的 resource ID 查找模式提供别名是有价值的。例如，资源层级顶部有 `users` 的 API 可能希望提供 `users/me` 作为检索已认证用户信息的快捷方式。

APIs **may** 为常见查找模式提供编程别名。然而，API 返回的所有数据 **must** 使用规范 resource name。

### 完整资源名称

多数情况下，resource names 只在单个 API 内使用，或用在拥有方 API 已经清楚的上下文中（例如 `string pubsub_topic`）。

然而，有时服务需要引用任意 API 中的资源。此时，服务 **should** 使用 *full resource name*：无 scheme 的 URI，由拥有方 [API 的 service name]({{< ref "aip-0009" >}}) 后接相对 resource name 组成：

```
//library.googleapis.com/publishers/123/books/les-miserables
//calendar.googleapis.com/users/vhugo1802
```

**Note:** Full resource name **should not** 用于拥有方 API 已经清楚的跨 API 引用；仅当字段指向多个 API 且可能产生歧义时才使用。

### Resource URIs

Full resource name 是无 scheme 的 URI，但与我们用来访问资源的完整 URIs 略有不同。后者包含协议（HTTPS）、API 版本，以及要瞄准的具体 [service endpoint]({{< ref "aip-0009" >}})：

```
https://library.googleapis.com/v1/publishers/123/books/les-miserables
https://calendar.googleapis.com/v3/users/vhugo1802
```

版本不包含在 full resource name 中，因为期望 full resource name 跨版本持久。即使 API 表面可能在 major versions 之间变化，同一 API 的多个 major versions 期望使用相同的底层数据。

**Note:** Full resource name 与服务 endpoint 之间的对应是按约定的。特别是，一个服务可以有多个 endpoints（示例用例包括区域化、MTLS 与私有访问），而 full resource name 在这些之间并不改变。

### 表示资源名称的字段

定义资源时，第一个字段 **should** 是 resource name，其类型 **must** 为 `string`，并且 **must** 称为 `name`。该 message **should** 包含声明类型的 `google.api.resource` annotation（更多见 [AIP-123]({{< ref "aip-0123" >}})）。

```proto
// A representation of a book in the library.
message Book {
  option (google.api.resource) = {
    type: "library.googleapis.com/Book"
    pattern: "publishers/{publisher}/books/{book}"
  };

  // The resource name of the book.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [(google.api.field_behavior) = IDENTIFIER];

  // Other fields...
}
```

定义检索或作用于已存在资源的方法（例如 `GetBook` 或 `ArchiveBook`）时，请求 message 的第一个字段 **should** 是 resource name，其类型 **must** 为 `string`，并且 **must** 称为 `name`。该字段 **should** 也用 `google.api.resource_reference` annotation 标注，引用资源类型（[AIP-123]({{< ref "aip-0123" >}})）。

```proto
// Request message for ArchiveBook
message ArchiveBookRequest {
  // The book to archive.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference) = {
      type: "library.googleapis.com/Book"
    }];

  // Other fields...
}
```

**Note:** 字段 **must not** 为其它目的称为 `name`。对其它用例，要么换一个术语，要么加形容词（例如：`display_name`）。

### 表示资源 parent 的字段

定义从集合检索资源或向集合添加新资源的方法（例如 `ListBooks` 或 `CreateBook`）时，请求 message 的第一个字段 **should** 类型为 `string`，并且 **should** 称为 `parent`，表示该集合的 resource name。`parent` 字段 **should** 也用 `google.api.resource_reference` annotation 标注，引用 parent 的资源类型（[AIP-123]({{< ref "aip-0123" >}})）。

```proto
// Request message for ListBooks.
message ListBooksRequest {
  // The publisher to list books from.
  // Format: publishers/{publisher_id}
  string parent = 1 [(google.api.resource_reference) = {
    type: "library.googleapis.com/Publisher"
  }];

  // Other fields (e.g. page_size, page_token, filter, etc.)...
}
```

若可能有多于一种 parent 类型，`parent` 字段 **should** 改为在 `google.api.resource_reference` 上用 `child_type` 键标注：

```proto
// Request message for ListBooks.
message ListBooksRequest {
  // The parent to list books from.
  // Format:
  //   - publishers/{publisher_id}
  //   - authors/{author_id}
  string parent = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference) = {
      child_type: "library.googleapis.com/Book"
    }];

  // Other fields (e.g. page_size, page_token, filter, etc.)...
}
```

**Note:** 字段 **should not** 为其它目的称为 `parent`。对其它用例，尽可能使用同义术语。

### 表示另一资源的字段

当字段表示另一资源时，该字段 **should** 类型为 `string`，并接受另一资源的 resource name。字段名 **should** 等价于对应 message 名称的 snake case。

- 字段名 **may** 在合适时包含前导形容词（例如 `string dusty_book`）。
- 字段名 **should not** 使用 `_name` 后缀，除非没有它会有歧义（例如 `crypto_key_name`）。
- 表示另一资源的字段 **should** 提供带被引用资源类型的 `google.api.resource_reference` annotation。
- 若无法使用 resource name 且严格必须只使用 ID 分量，该字段 **should** 使用 `_id` 后缀（例如 `shelf_id`）。

该字段 **should not** 使用实现该资源的 `message` 作为 `message` 类型，**除非** 满足下列条件之一：

- API 仅内部使用，有紧密的生命周期关系，并且权限模型允许对嵌入资源的继承访问。
- 嵌入资源是作为 AIP-162 revisions 模式的一部分完成的。

Resource reference 示例：

```proto
// A representation of a book in a library.
message Book {
  option (google.api.resource) = {
    type: "library.googleapis.com/Book"
    pattern: "publishers/{publisher}/books/{book}"
  };

  // Name of the book.
  // Format is `publishers/{publisher}/books/{book}`
  string name = 1 [(google.api.field_behavior) = IDENTIFIER];

  // The shelf where the book currently sits.
  // Format is `shelves/{shelf}`.
  string shelf = 2 [(google.api.resource_reference) = {
    type: "library.googleapis.com/Shelf"
  }];

  // Other fields...
}
```

## Rationale

### 使用 names 而不是 IDs

对任何大型系统，都有许多种资源。若用简单的 resource IDs 标识资源，我们实际上需要用资源特定的元组来可靠标识它，例如 `(bucket, object)` 或 `(user, album, photo)`。这会带来若干问题：

- 开发者必须理解并记住这些匿名元组。
- 传递元组通常比传递字符串更难。
- 集中式基础设施，例如日志与访问控制系统，不理解专门的元组。
- 专门的元组限制 API 设计灵活性，例如提供可复用的 API interfaces。例如，[Long Running Operations]({{< ref "aip-0151" >}}) 可以与许多其它 API interfaces 协作，因为它们使用灵活的 resource names。

### 标准化为 `name`

Resource names 的概念并不新，并在 Uniform Resource Names (URN) 中与 Uniform Resource Identifiers (URI) 及 Uniform Resource Locators (URL) 一起被形式化。考虑到 "name" 一词在一般场合被严重过载，若在非常明确的含义之外使用，会对开发者造成混淆。因此，在符合 AIP 的 APIs 的上下文中，字段名 `name` 被保留，以消除与 resource names 的任何混淆，并迫使其它本会叫 "name" 的字段使用更具体的字段名。

### 禁止嵌入资源

把资源 message 直接用作另一资源中某字段的类型，会因下列原因而出问题：

- 使资源生命周期更复杂：若被依赖资源被删除，嵌入在依赖资源中的引用会怎样？数据保留与清理操作会显著复杂化。
- 绕过权限：若每个资源都有自己的权限集，对依赖资源有读权限、但对被依赖资源没有相同权限的用户会突然无法看到完整资源。
- 在各方面把资源紧紧耦合：改变任一方的 schema、权限或其它要求都会影响另一方，显著增加滚动发布的复杂度。

按名称引用（如所建议）通过防止资源数据重复，并迫使拥有方服务参与解析该引用（经由 Standard Methods），从而消除所有这些复杂度，保证按资源隔离逻辑关切。

## History

### 禁止用户指定 IDs 中的 UUIDs

作为让 APIs 更声明式友好的一部分，APIs 被要求允许在创建时由用户指定 resource ID。作为其中一部分，也鼓励提供含 UUID 的配套字段 `string uid`。随后增加了指导，劝阻 *用户指定的 resource ID* 成为 UUID，甚至不要看起来像 UUID。

表面上，`uid` 含有服务生成的 UUID，推动了对用户指定 resource ID 的这一限制，迫使用户指定的 resource ID 成为更「有意义」的值。然而我们不再认为此要求有价值，因而将其移除。
