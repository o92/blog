**英文标题**：Policy preview  
**原文**：[AIP-236](https://google.aip.dev/236) · approved · 创建 2023-03-30  
**许可**：原文 © Google，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

Policy 是一种资源，提供允许或拒绝访问其它资源的规则。一般而言，policy 的结果可以求值为一组特定结局。

未经恰当校验就变更 policies，可能产生意外后果，严重冲击客户的整体基础设施设置。为安全更新资源，通过 policy rollout APIs 测试这些变更是有益的。

Preview 是 policy 资源的一种 rollout 安全机制，让客户能在变更上线前，用生产流量校验其拟议变更的效果。对照流量求值 policy 的结果会被记录，以便给客户测试该变更正确性所需的数据。

防火墙 policies 是适合 preview 的一个例子。新配置可以对照流量求值，以观察哪些 IPs 会被允许或拒绝。这给客户提供数据，以决定是否把拟议变更提升为 live。

Preview 一个 policy 的期望流程如下：

1. 用户创建一个 experiment，其中含有旨在替换 live policy 的新 policy 配置。
2. 用户使用 "startPreview" 方法开始生成日志，对照 live 流量比较 live 与 experiment 的 policy 求值。
3. 用户检查日志，判断 experiment 是否具有意图中的结果。
4. 用户使用 "commit" 方法把 experiment 提升为 live。

## Guidance

### Non-goals

本提案只针对 policy rollouts 的安全机制。非 policy 资源的安全 rollouts 不在范围内。

### Experiments

要 preview 的 policy 新配置作为嵌套集合存储在该 policy 下。这些嵌套集合称为 experiments。

全文使用一个假想的 policy 资源 `Policy`。它具有下列 resource name pattern：

`projects/{project}/locations/{location}/policies/{policy}`

用于 preview 或其它安全 rollout 实践的该资源的实验版本，用一种新资源类型表示为 `Policy` 下的嵌套集合。资源类型 **must** 遵循命名约定 *RegularResourceType*`Experiment`。

experiment 集合使用下列 pattern：

`projects/{project}/locations/{location}/policies/{policy}/experiments/{experiment}`

用于表示 experiment 的 proto **must** 包含下列内容：

1. 资源所需的顶层字段，例如 `name` 与 `etag`
2. 正在测试的 policy message 本身
3. 字段 `preview_metadata`，包含针对特定资源类型 preview 该 experiment 的元数据。

```proto
message PolicyExperiment {

  // google.api.resource, name, and other annotations and fields

  // The policy experiment. This Policy will be used to preview the effects of
  // the change but will not affect live traffic.
  Policy policy = 2;

  // The metadata associated with this policy experiment.
  PolicyPreviewMetadata preview_metadata = 3
      [(google.api.field_behavior) = OUTPUT_ONLY];

  // Allows clients to store small amounts of arbitrary data.
  map<string, string> annotations = 4;
}
```

- Experiment proto **must** 有一个与 live policy 相同类型的顶层字段。
  - 它 **must** 以 live 资源类型命名。例如，若 experiment 针对 FirewallPolicy，则该字段 **must** 名为 `firewall_policy`。
  - 嵌入的 `policy` message 内的 name **must** 为 live policy 的 name。
- 当用户准备好提升一个 experiment 时，他们 **must** 把 `policy` message 复制进 live policy 并删除该 experiment。这可以手动完成，或经由 "commit" custom method。
- 产品 **may** 支持对单个 live policy 同时 preview 多个 experiments。
  - 每个 experiment 必须生成日志，每条条目前加 `log_prefix`，以便用户把 experiment 结果与 live policy 的行为比较。
  - 给定 live policy 的实验配置数量 **may** 设上限，并且该上限 **must** 被文档化。
- **must** 发生级联删除：若 live policy 被删除，所有 experiments **must** 也被删除。
- `map<string,string>` annotations（[AIP-128]({{< ref "aip-0128" >}})） **must** 允许客户端存储少量任意数据。

### Metadata

`preview_metadata` 跟踪 preview 该 experiment 的全部元数据。messages **must** 遵循约定：*RegularResourceType*`PreviewMetadata`。这样该 proto 可以在同一服务中为每种带 experiments 的资源类型唯一定义。

```proto
message PolicyPreviewMetadata {
  // Possible values of the state of previewing the experiment.
  enum State {
    // Default value. This value is unused.
    STATE_UNDEFINED = 0;

    // The experiment is actively previewing.
    ACTIVE = 1;

    // The previewing of the experiment has been stopped.
    SUSPENDED = 2;
  }

  // The state of previewing the experiment.
  State state = 1;

  // An identifying string common to all logs generated when previewing the
  // experiment. Searching all logs for this string will isolate the results.
  string log_prefix = 2;

  // The most recent time at which this experiment started previewing.
  google.protobuf.Timestamp start_time = 3;

  // The most recent time at which this experiment stopped previewing.
  google.protobuf.Timestamp stop_time = 4;
}
```

- `PolicyPreviewMetadata` **must** 具有上面 proto 中定义的字段。
  - 若服务或资源需要，它 **may** 有额外字段。
- 当 experiment 首次被 preview 时，`preview_metadata` **must** 缺失。
  - 一旦使用 "startPreview" 方法，它就会出现在 experiment 上。
- 所有 `preview_metadata` 字段 **must** 为 output only。
- 当 preview 开始或停止时，`state` 在 `ACTIVE` 与 `SUSPENDED` 之间变化。这分别发生在调用 "startPreview" 或 "stopPreview" custom methods 时。
- 第一次使用 "startPreview" custom method 时，系统 **must** 创建 `preview_metadata` 并做下列事情：
  - 它 **must** 把 `state` 设为 `ACTIVE`
  - 它 **must** 用当前时间填充 `start_time`。
    - 每次 `state` 变为 `ACTIVE` 时，`start_time` **must** 被更新。
  - 它 **must** 设置系统生成的 `log_prefix` 字符串，这是由系统开发者硬编码的预定义常量。
  - 对给定资源类型 preview experiments 时使用相同的值。例如，FirewallPolicy 使用 "FirewallPolicyPreviewLog"。
- 当使用 "stopPreview" custom method 时，系统 **must** 做下列事情：
  - 它 **must** 把 `state` 设为 `SUSPENDED`
  - 它 **must** 用当前时间填充 `stop_time`。

### Methods

#### create

- 资源 **must** 使用长时运行的 Create（[AIP-133]({{< ref "aip-0133" >}})）创建，并且 `google.longrunning.operation_info.response_type` **must** 为 `PolicyExperiment`。
- 创建新 experiment 以供 preview **must** 支持下列用例：
  - Preview 一个新 policy。
  - Preview 对已经 live 的 policy 的更新。
  - Preview 删除当前 policy。
- 对 update 与 delete 用例，experiment 中的 `policy` 字段 **must** 把 live policy 的完整 payload 复制进去，包括 name。
  - 用户 **must** 把规则设为新的意图状态以 preview 一次更新。
  - 用户 **must** 把规则设为表示 no-op 以 preview 一次删除。
- 要 preview 一个新 policy，系统必须做下列事情：
  - 若系统不支持没有 live policy 的嵌套集合，用户 **must** 创建一个 live policy 并把规则设为表示 no-op。例如，no-op policy 的规则 **may** 为空。
    - Experiment 作为该 no-op policy 的 child 被创建。
- 若系统支持对一个 live policy preview 多个 experiments，多次调用 "create" **must** 创建多个 experiments。

#### update

- 资源 **must** 使用长时运行的 Update（[AIP-134]({{< ref "aip-0134" >}})）更新，并且 `google.longrunning.operation_info.response_type` **must** 为 `PolicyExperiment`。
- `policy` 内的 name **must not** 改变，但其它字段可以改变，以便改变正在 preview 的 experiment，因为此 `policy` 旨在替换 live policy，而 live policy 的 name **must not** 改变。
- 若更新时 `state` 为 `ACTIVE`，系统 **must** 把 `state` 设为 `SUSPENDED`。
  - 这样用户可以容易区分正在 preview 的 experiment 的不同版本。

#### get

- **must** 为 `PolicyExperiment` 资源类型包含标准方法 Get（[AIP-131]({{< ref "aip-0131" >}})）。

#### list

- **must** 为 `PolicyExperiment` 资源类型包含标准方法 List（[AIP-132]({{< ref "aip-0132" >}})）。
- 对 `PolicyPreviewMetadata` 的过滤表明哪些 experiments 正在被主动 preview。
  - 例如，下列 filter 字符串返回正在被 preview 的 experiments 的 List 响应：`preview_metadata.state = ACTIVE`。

#### delete

- 资源 **must** 使用长时运行的 Delete（[AIP-135]({{< ref "aip-0135" >}})）删除，并且 `google.longrunning.operation_info.response_type` **must** 为 `PolicyExperiment`。

#### startPreview

```proto
// Starts previewing a PolicyExperiment. This triggers the system to start
// generating logs to evaluate the PolicyExperiment.
rpc StartPreviewPolicyExperiment(StartPreviewPolicyExperimentRequest)
    returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=policies/*/experiments/*}:startPreview"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "PolicyExperiment"
    metadata_type: "StartPreviewPolicyExperimentMetadata"
  };
}

// The request message for the startPreview custom method.
message StartPreviewPolicyExperimentRequest {
  // The name of the PolicyExperiment.
  string name = 1;
}
```

- 此 custom method 是必需的。
- `google.longrunning.Operation.metadata_type` **must** 遵循 Long-running operations（[AIP-151]({{< ref "aip-0151" >}})）的指导。
- 此方法 **must** 触发系统开始生成日志以 preview 该 experiment。
- 每当该方法成功调用时，系统 **must** 在 `PolicyPreviewMetadata` 中设置下列值：
  - `log_prefix` 为预定义常量。
  - `start_time` 为当前时间
  - `state` 为 `ACTIVE`。
- 若该方法被调用在规则表示 no-op 的 experiment 上，则系统 **must** preview 删除该 live policy。

#### stopPreview

```proto
// Stops previewing a PolicyExperiment. This triggers the system to stop
// generating logs to evaluate the PolicyExperiment.
rpc StopPreviewPolicyExperiment(StopPreviewPolicyExperimentRequest)
    returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=policies/*/experiments/*}:stopPreview"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "PolicyExperiment"
    metadata_type: "StopPreviewPolicyExperimentMetadata"
  };
}

// The request message for the stopPreview custom method.
message StopPreviewPolicyExperimentRequest {
  // The name of the PolicyExperiment.
  string name = 1;
}
```

- 此 custom method 是必需的。
- `google.longrunning.Operation.metadata_type` **must** 遵循 Long-running operations（[AIP-151]({{< ref "aip-0151" >}})）的指导。
- 此方法 **must** 触发系统停止生成日志以 preview 该 experiment。
- 每当该方法成功调用时，系统 **must** 在 `PolicyPreviewMetadata` 中设置下列值：
  - `stop_time` 为当前时间
  - `state` 为 `SUSPENDED`

#### commit

资源 **may** 暴露一个名为 "commit" 的新 custom method 以提升 experiment。系统把 experiment 中的 `policy` 复制进 live policy，然后删除该 experiment。

Declarative clients **may** 手动把字段从 experiment 复制进 live policy，然后删除该 experiment，而不是调用 "commit"（若这样更可取）。

```proto
// Commits a PolicyExperiment. This copies the PolicyExperiment's policy message
// to the live policy then deletes the PolicyExperiment.
rpc CommitPolicyExperiment(CommitPolicyExperimentRequest)
    returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=policies/*/experiments/*}:commit"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "CommitPolicyExperimentMetadata"
  };
}

// The request message for the commit custom method.
message CommitPolicyExperimentRequest {
  string name = 1;
  string etag = 2;
  string parent_etag = 3;
}
```

- `google.longrunning.Operation.metadata_type` **must** 遵循 Long-running operations（[AIP-151]({{< ref "aip-0151" >}})）的指导。
- 该方法 **must** 原子地把 experiment 中的 `policy` 复制进 live policy，然后删除该 experiment。
- 若任何 experiment 的 "commit" 失败，preview 它 **must not** 停止，并且 live policy **must not** 被更新。
- 该方法可以在处于任何状态的 experiment 上调用。
- `etag` **must** 与该 experiment 的 etag 匹配，commit 才能成功。这样用户不会提交非意图版本的 experiment。
  - 若未提供 `etag`，API **must not** 成功，以防止用户无意中提交与意图不同的 experiment 版本。
  - **may** 提供 `parent_etag`，以保证该 experiment 覆盖 live policy 的特定版本。
- 该方法不是幂等的，对同一 experiment 调用两次 **must** 返回 404 NOT_FOUND，因为该 experiment 已在第一次调用中被删除。

### 对 live policy API 方法的变更

#### delete

- 删除 live policy **must** 删除所有 experiments。
- 要在保持 experiments 的同时抵消 live policy 的效果，**must** 把 live policy 改为 no-op policy，而不是使用此方法。

### Logging

日志对用户评估是否应将 experiment 提升为 live 至关重要。

日志 **must** 包含所求值 experiment 的结果、与该 experiment 以及 live policy 关联的 `etag`，并且前面加上 `log_prefix` 的值。

- `etag` 字段帮助用户识别日志中求值的是 live 与 experiment 的哪些配置。
- `log_prefix` 帮助用户把专门为 preview 该 experiment 生成的日志与其它用例分开。

总体而言，这些日志帮助用户决定是否把 experiment 提升为 live。
