**英文标题**：Policy preview  
**原文**：[AIP-236](https://google.aip.dev/236) · approved · 创建 2023-03-30  
**许可**：原文 © Google，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

Policy 是一套规则：允许或拒绝访问其它资源。规则一改，求值结果就会变成一组特定结局。没校验就改 policy，可能把客户整套基础设施冲乱。

Preview 是给 policy 用的 rollout 安全机制。客户在变更上线前，用生产流量对照拟议配置，把求值结果记进日志，再决定要不要提升为 live。防火墙 policies 是典型场景：新规则对着流量跑一遍，看哪些 IP 会被允许或拒绝。

期望流程：

1. 用户创建一个 experiment，里面是打算替换 live policy 的新配置。
2. 用户调用 `startPreview`，开始打日志，对照 live 流量比较 live 与 experiment 的求值。
3. 用户看日志，判断 experiment 是否达到意图。
4. 用户调用 `commit`，把 experiment 提升为 live。

## 范围

本提案只覆盖 policy rollouts 的安全机制。非 policy 资源的安全 rollouts 不在范围内。

## Experiments

要 preview 的新配置，作为嵌套集合存在 live policy 下面。这些嵌套集合叫 experiments。

下文用假想资源 `Policy`，resource name pattern 是：

`projects/{project}/locations/{location}/policies/{policy}`

用于 preview 或其它安全 rollout 的实验版本，是 `Policy` 下的一种新资源类型。类型名必须遵循 *RegularResourceType*`Experiment`。

experiment 集合用下列 pattern：

`projects/{project}/locations/{location}/policies/{policy}/experiments/{experiment}`

表示 experiment 的 proto 必须包含：

1. 资源所需的顶层字段，例如 `name` 与 `etag`
2. 正在测试的 policy message 本身
3. 字段 `preview_metadata`，装着针对该资源类型做 preview 的元数据

```proto
message PolicyExperiment {

  // google.api.resource, name, and other annotations and fields

  // The policy experiment. This Policy will be used to preview the effects of
  // the change but will not affect live traffic.
  Policy policy = 2;

  // The metadata associated with this policy experiment.
  PolicyPreviewMetadata preview_metadata = 3
      [(google.api.field_behavior) = OUTPUT_ONLY];

  // Allows clients to store small amounts of arbitrary data.
  map<string, string> annotations = 4;
}
```

- Experiment proto 必须有一个与 live policy 相同类型的顶层字段。
  - 它必须以 live 资源类型命名。例如针对 FirewallPolicy 的 experiment，该字段必须叫 `firewall_policy`。
  - 嵌入的 `policy` message 内的 name 必须是 live policy 的 name。
- 用户准备提升 experiment 时，必须把 `policy` message 复制进 live policy，再删除该 experiment。可以手动做，也可以走 `commit` custom method。
- 产品可以支持对单个 live policy 同时 preview 多个 experiments。
  - 每个 experiment 必须生成日志，每条前面加上 `log_prefix`，方便跟 live policy 的行为比较。
  - 给定 live policy 上的实验配置数量可以设上限，并且该上限必须写进文档。
- 必须级联删除：live policy 删了，所有 experiments 也必须删掉。
- `map<string,string>` annotations（见 [AIP-128]({{< ref "aip-0128" >}})）必须允许客户端存少量任意数据。

## Metadata

`preview_metadata` 跟踪这个 experiment 的全部 preview 元数据。message 名必须遵循 *RegularResourceType*`PreviewMetadata`，好让同一服务里每种带 experiments 的资源类型各有一份唯一定义。

```proto
message PolicyPreviewMetadata {
  // Possible values of the state of previewing the experiment.
  enum State {
    // Default value. This value is unused.
    STATE_UNDEFINED = 0;

    // The experiment is actively previewing.
    ACTIVE = 1;

    // The previewing of the experiment has been stopped.
    SUSPENDED = 2;
  }

  // The state of previewing the experiment.
  State state = 1;

  // An identifying string common to all logs generated when previewing the
  // experiment. Searching all logs for this string will isolate the results.
  string log_prefix = 2;

  // The most recent time at which this experiment started previewing.
  google.protobuf.Timestamp start_time = 3;

  // The most recent time at which this experiment stopped previewing.
  google.protobuf.Timestamp stop_time = 4;
}
```

- `PolicyPreviewMetadata` 必须具备上面 proto 里的字段。
  - 服务或资源需要时，可以再加字段。
- experiment 第一次被 preview 之前，`preview_metadata` 必须缺失。
  - 一调用 `startPreview`，它就会出现在 experiment 上。
- 所有 `preview_metadata` 字段必须是 output only。
- preview 开始或停止时，`state` 在 `ACTIVE` 与 `SUSPENDED` 之间切换。分别对应 `startPreview` 与 `stopPreview`。
- 第一次调用 `startPreview` 时，系统必须创建 `preview_metadata`，并做这些事：
  - 必须把 `state` 设为 `ACTIVE`
  - 必须用当前时间填 `start_time`。
    - 每次 `state` 变为 `ACTIVE`，`start_time` 都必须更新。
  - 必须设置系统生成的 `log_prefix`。这是系统开发者硬编码的预定义常量。
  - 同一资源类型 preview experiments 时用同一个值。例如 FirewallPolicy 用 `"FirewallPolicyPreviewLog"`。
- 调用 `stopPreview` 时，系统必须：
  - 把 `state` 设为 `SUSPENDED`
  - 用当前时间填 `stop_time`

## 方法

### create

- 资源必须用长时运行的 Create（见 [AIP-133]({{< ref "aip-0133" >}})）创建，并且 `google.longrunning.operation_info.response_type` 必须是 `PolicyExperiment`。
- 创建新 experiment 必须能覆盖这些用例：
  - Preview 一个新 policy。
  - Preview 对已经 live 的 policy 的更新。
  - Preview 删除当前 policy。
- 对 update 与 delete 用例，experiment 里的 `policy` 字段必须把 live policy 的完整 payload 复制进去，包括 name。
  - 用户必须把规则设成新的意图状态，才能 preview 一次更新。
  - 用户必须把规则设成表示 no-op，才能 preview 一次删除。
- 要 preview 一个新 policy，系统必须：
  - 若系统不支持没有 live policy 的嵌套集合，用户必须先建一个 live policy，并把规则设成 no-op。例如规则可以为空。
    - Experiment 作为该 no-op policy 的 child 被创建。
- 若系统支持对一个 live policy preview 多个 experiments，多次调用 create 必须创建多个 experiments。

### update

- 资源必须用长时运行的 Update（见 [AIP-134]({{< ref "aip-0134" >}})）更新，并且 `google.longrunning.operation_info.response_type` 必须是 `PolicyExperiment`。
- `policy` 内的 name 不得改变。其它字段可以改，用来调整正在 preview 的 experiment：这份 `policy` 旨在替换 live policy，而 live policy 的 name 不得改变。
- 若更新时 `state` 是 `ACTIVE`，系统必须把它改成 `SUSPENDED`。
  - 这样用户容易区分正在 preview 的不同版本。

### get

- 必须为 `PolicyExperiment` 提供标准方法 Get（见 [AIP-131]({{< ref "aip-0131" >}})）。

### list

- 必须为 `PolicyExperiment` 提供标准方法 List（见 [AIP-132]({{< ref "aip-0132" >}})）。
- 对 `PolicyPreviewMetadata` 做过滤，可以看出哪些 experiments 正在被主动 preview。
  - 例如 `preview_metadata.state = ACTIVE` 会返回正在被 preview 的那一批。

### delete

- 资源必须用长时运行的 Delete（见 [AIP-135]({{< ref "aip-0135" >}})）删除，并且 `google.longrunning.operation_info.response_type` 必须是 `PolicyExperiment`。

### startPreview

```proto
// Starts previewing a PolicyExperiment. This triggers the system to start
// generating logs to evaluate the PolicyExperiment.
rpc StartPreviewPolicyExperiment(StartPreviewPolicyExperimentRequest)
    returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=policies/*/experiments/*}:startPreview"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "PolicyExperiment"
    metadata_type: "StartPreviewPolicyExperimentMetadata"
  };
}

// The request message for the startPreview custom method.
message StartPreviewPolicyExperimentRequest {
  // The name of the PolicyExperiment.
  string name = 1;
}
```

- 此 custom method 是必需的。
- `google.longrunning.Operation.metadata_type` 必须遵循长时运行操作（见 [AIP-151]({{< ref "aip-0151" >}})）。
- 此方法必须触发系统开始生成日志，用来 preview 该 experiment。
- 每次成功调用，系统必须在 `PolicyPreviewMetadata` 里设置：
  - `log_prefix` 为预定义常量
  - `start_time` 为当前时间
  - `state` 为 `ACTIVE`
- 若 experiment 的规则表示 no-op，系统必须 preview「删除该 live policy」。

### stopPreview

```proto
// Stops previewing a PolicyExperiment. This triggers the system to stop
// generating logs to evaluate the PolicyExperiment.
rpc StopPreviewPolicyExperiment(StopPreviewPolicyExperimentRequest)
    returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=policies/*/experiments/*}:stopPreview"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "PolicyExperiment"
    metadata_type: "StopPreviewPolicyExperimentMetadata"
  };
}

// The request message for the stopPreview custom method.
message StopPreviewPolicyExperimentRequest {
  // The name of the PolicyExperiment.
  string name = 1;
}
```

- 此 custom method 是必需的。
- `google.longrunning.Operation.metadata_type` 必须遵循长时运行操作（见 [AIP-151]({{< ref "aip-0151" >}})）。
- 此方法必须触发系统停止为该 experiment 生成 preview 日志。
- 每次成功调用，系统必须在 `PolicyPreviewMetadata` 里设置：
  - `stop_time` 为当前时间
  - `state` 为 `SUSPENDED`

### commit

资源可以暴露一个叫 `commit` 的 custom method 来提升 experiment。系统把 experiment 里的 `policy` 复制进 live policy，然后删除该 experiment。

Declarative clients 也可以手动把字段从 experiment 复制进 live policy，再删除 experiment，而不调用 `commit`。

```proto
// Commits a PolicyExperiment. This copies the PolicyExperiment's policy message
// to the live policy then deletes the PolicyExperiment.
rpc CommitPolicyExperiment(CommitPolicyExperimentRequest)
    returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=policies/*/experiments/*}:commit"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "CommitPolicyExperimentMetadata"
  };
}

// The request message for the commit custom method.
message CommitPolicyExperimentRequest {
  string name = 1;
  string etag = 2;
  string parent_etag = 3;
}
```

- `google.longrunning.Operation.metadata_type` 必须遵循长时运行操作（见 [AIP-151]({{< ref "aip-0151" >}})）。
- 该方法必须原子地把 experiment 里的 `policy` 复制进 live policy，然后删除该 experiment。
- 若任何 experiment 的 `commit` 失败，preview 不得停，live policy 也不得被更新。
- 该方法可以在处于任何状态的 experiment 上调用。
- `etag` 必须与该 experiment 的 etag 匹配，commit 才能成功。这样用户不会提交非意图版本。
  - 若未提供 `etag`，API 不得成功，以免用户无意中提交错版本。
  - 可以提供 `parent_etag`，保证这次覆盖的是 live policy 的特定版本。
- 该方法不是幂等的。对同一 experiment 调用两次，必须返回 404 NOT_FOUND：第一次已经把它删了。

## 对 live policy API 方法的变更

### delete

- 删除 live policy 必须同时删除所有 experiments。
- 想抵消 live policy 的效果、但又要保住 experiments，必须把 live policy 改成 no-op，而不是走删除。

## 日志

日志决定用户敢不敢把 experiment 提升为 live。

日志必须包含所求值 experiment 的结果、与该 experiment 以及 live policy 关联的 `etag`，并且前面加上 `log_prefix`。

- `etag` 帮助用户识别日志里求值的是哪一版 live 与 experiment。
- `log_prefix` 帮助用户把专门为这次 preview 打的日志跟其它用例分开。
