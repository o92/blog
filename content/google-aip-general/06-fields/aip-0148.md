某些概念在任何 API 语料中都很常见。此时，有一致使用的标准字段名与行为来传达该概念很有用。

## Guidance

标准字段 **should** 用于描述其对应概念，并且 **should not** 用于任何其它目的。

### Resource names and IDs

#### name

每个资源 **must** 有 `string name` 字段，用于 resource name（[AIP-122]({{< ref "aip-0122" >}})），它 **should** 是资源中的第一个字段。

**Note:** 除非本文另有涵盖，`_name` 后缀 **should not** 用于描述其它类型的名称。

#### parent

`string parent` 字段指集合 parent 的 resource name，并且 **should** 用于大多数 `List`（[AIP-132]({{< ref "aip-0132" >}})）与 `Create`（[AIP-133]({{< ref "aip-0133" >}})）请求。

### Other names

#### display_name

`string display_name` 字段 **must** 是可变、用户可设置的字段，用户可提供人类可读名称以用于用户界面。[声明式友好资源]({{< ref "aip-0128" >}}) **should** 包含此字段。

Display names **should not** 有唯一性要求，并且 **should** 限制为 <= 63 个字符。

#### title

`string title` 字段 **should** 为实体的官方名称，例如公司名。这是 `string display_name` 的更正式变体。

#### given_name

`string given_name` 字段 **must** 指人或动物的 given name。资源 **must not** 对此概念使用 `first_name`，因为在许多文化中 given name 并不放在前面。

#### family_name

`string family_name` 字段 **must** 指人或动物的 family name。资源 **must not** 对此概念使用 `last_name`，因为在许多文化中 family name 并不放在后面。

### Timestamps

#### create_time

output only 的 `google.protobuf.Timestamp create_time` 字段 **must** 表示资源被创建的时间戳。这 **may** 是发起创建的时间或完成创建的时间。[声明式友好资源]({{< ref "aip-0128" >}}) **should** 包含此字段。

#### update_time

output only 的 `google.protobuf.Timestamp update_time` 字段 **must** 表示资源最近被更新的时间戳。用户对资源做的任何变更 **must** 刷新此值；服务内部对资源做的变更 **may** 刷新此值。[声明式友好资源]({{< ref "aip-0128" >}}) **should** 包含此字段。

#### delete_time

output only 的 `google.protobuf.Timestamp delete_time` 字段 **must** 表示资源被软删除的时间戳。这 **may** 对应用户请求删除的时间，或服务成功软删除资源的时间。若资源未被软删除，`delete_time` 字段 **must** 为空。

支持软删除（[AIP-164]({{< ref "aip-0164" >}})）的资源 **should** 提供此字段。

#### expire_time

`google.protobuf.Timestamp expire_time` 字段 **should** 表示给定资源或资源属性不再有用或有效的时间（例如轮换的安全密钥）。它 **may** 用于 [AIP-214]({{< ref "aip-0214" >}}) 中描述的类似过期形式。

服务 **may** 提供不精确的 `expire_time` 值，但资源 **must not** 在该时间之前过期。

#### purge_time

`google.protobuf.Timestamp purge_time` 字段 **should** 表示软删除资源将从系统中清除的时间（见 [AIP-164]({{< ref "aip-0164" >}})）。它 **may** 用于 [AIP-214]({{< ref "aip-0214" >}}) 中描述的类似过期形式。支持软删除的资源 **should** 包含此字段。

服务 **may** 提供不精确的 `purge_time` 值，但资源 **must not** 在该时间之前从系统中清除。

### Annotations

为存储少量任意数据，**may** 添加 `map<string, string> annotations` 字段。

`annotations` 字段 **must** 使用 [Kubernetes limits](https://kubernetes.io/docs/concepts/overview/working-with-objects/annotations/#syntax-and-character-set) 以保持线上兼容，并且 **should** 要求点命名空间的 annotation keys，以防止工具互相践踏。

可能值得存储在 annotations 中的信息示例包括：

- 对 CI/CD，用于传播的 pipeline run 标识符或版本控制标识符。

**Note:** Annotations 与各种形式的 labels 不同。Labels 可由服务端策略使用，例如 IAM conditions。Annotations 存在是为了让客户端工具存储自己的状态信息而无需数据库。

### Well known string fields

#### IP address

表示 IP 地址的字段 **must** 符合下列要求：

* 使用类型 `string`
* 使用名称 `ip_address` 或以后缀 `_ip_address` 结尾，例如 `resolved_ip_address`
* 通过受支持格式 `IPV4`、`IPV6` 之一指定 IP 地址版本格式，或若可以是二者之一，则为 `IPV4_OR_IPV6`（见 [AIP-202]({{< ref "aip-0202" >}})）

#### uid

output only 的 `string uid` 字段指资源的系统分配唯一标识符。提供时，此字段 **must** 为 [UUID4](https://en.wikipedia.org/wiki/Universally_unique_identifier#Version_4_(random))，并且 **must** 通过 `UUID4` 格式扩展指定此格式（见 [AIP-202]({{< ref "aip-0202" >}})）。[声明式友好资源]({{< ref "aip-0128" >}}) **should** 包含此字段。

## Rationale

### Well known string fields

有些字段表示定义非常清楚、有时其语义也有严格治理的概念或产物。对此类字段，呈现同样标准化的 API 表面很重要。这能改进 API 消费者工具与文档的开发，以及跨平台更统一的用户体验。

## History
