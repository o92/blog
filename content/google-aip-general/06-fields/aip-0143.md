**英文标题**：Standardized codes

许多常见概念，例如口语、国家、货币等，都有用于数据通信与处理的常用代码（通常由 [International Organization for Standardization](https://www.iso.org/) 正式化）。这些代码解决的问题是：书面语言中常常有不同方式表达同一概念（例如 "United States" 与 "USA"，或 "Español" 与 "Spanish"）。

## Guidance

对存在标准化代码且普遍使用的概念，表示这些概念的字段 **should** 在输入与输出上都使用标准化代码。

```proto
// A message representing a book.
message Book {
  // Other fields...

  // The IETF BCP-47 language code representing the language in which
  // the book was originally written.
  // https://en.wikipedia.org/wiki/IETF_language_tag
  string language_code = 99;
}
```

- 表示标准化概念的字段 **must** 使用该标准代码的适当数据类型（通常是 `string`）。
  - 表示标准化概念的字段 **should not** 使用 enums，即使它们只允许一小部分可能值。此时使用 enums 常常导致把多个 APIs 一起用时令人沮丧的查找表。
  - 表示标准化概念的字段 **must** 指明它们遵循哪个标准，最好带链接（指向标准本身、Wikipedia 描述、或类似内容）。
- 除非该概念有明显更清楚的后缀，字段名 **should** 以 `_code` 或 `_type` 结尾。
- 接受用户提供的值时，验证 **should** 大小写不敏感，除非这会引入歧义（例如同时接受 `en-gb` 与 `en-GB`）。向用户提供值时，APIs **should** 使用规范大小写（上例中为 `en-GB`）。

### Content types

表示内容或媒体类型的字段 **must** 使用 [IANA media types](https://www.iana.org/assignments/media-types/media-types.xhtml)。出于遗留原因，字段 **should** 称为 `mime_type`。

### Countries and regions

表示个别国家或民族的字段 **must** 使用 [Unicode CLDR region codes](http://cldr.unicode.org/)（[列表](https://www.unicode.org/cldr/charts/46/supplemental/territory_information.html)），例如 `US` 或 `CH`，并且字段 **must** 称为 `region_code`。

**Important:** 请阅读此要求的 [rationale](#countryregion-field-naming)。

### Currency

表示货币的字段 **must** 使用 [ISO-4217 currency codes](https://en.wikipedia.org/wiki/ISO_4217)，例如 `USD` 或 `CHF`，并且字段 **must** 称为 `currency_code`。

**Note:** 要表示特定货币中的金额，而不是货币代码本身，使用 [`google.type.Money`](https://github.com/googleapis/googleapis/blob/master/google/type/money.proto)。

### Language

表示口语的字段 **must** 使用 [IETF BCP-47 language codes](https://en.wikipedia.org/wiki/IETF_language_tag)（[列表](https://www.unicode.org/cldr/charts/46/supplemental/territory_information.html)），例如 `en-US` 或 `de-CH`，并且字段 **must** 称为 `language_code`。

### Time zones

表示时区的字段 **should** 使用 [IANA TZ](http://www.iana.org/time-zones) 代码，并且字段 **must** 称为 `time_zone`。

字段也 **may** 表示 UTC 偏移而不是时区（注意二者有细微不同）。此时，字段 **must** 使用 [ISO-8601 格式](https://en.wikipedia.org/wiki/ISO_8601#Time_offsets_from_UTC) 来表示，并且字段 **must** 名为 `utc_offset`。

## Rationale

### Country/region field naming

使用 `region_code` 而不是 `country_code` 对于能够传达与任何国家不同的地区、并避免与该地区主权或归属相关的任何政治争议至关重要。Google 与许多其它公司是 Unicode CLDR 的支持者，并把产品国际化工作标准化到 Unicode CLDR 上，APIs 在此并无不同。此外，Unicode CLDR 支持的许多值本身并不是国家，因此使用更通用的名称实际上更兼容该规范。
