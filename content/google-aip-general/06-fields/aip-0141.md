许多服务需要表示物品的离散数量（字节数、英里数、节点数等）。

## Guidance

带有明确计量单位（例如字节、英里等）的数量 **must** 把计量单位作为后缀。适当时候，单位 **should** 使用普遍接受的缩写，并且缩写 **should not** 复数化（例如 `distance_km` 而不是 `distance_kilometers`）。

```proto
// A representation of a non-stop air route.
message Route {
  // The airport where the route begins.
  string origin = 1;

  // The destination airport.
  string destination = 2;

  // The distance between the origin and destination airports.
  // This value is also used to determine the credited frequent flyer miles.
  int32 distance_miles = 3;
}
```

若数量是物品的数目（例如集群中的节点数），则字段 **should** 使用后缀 `_count`（**不是**前缀 `num_`）：

```proto
// A cluster of individual nodes.
message Cluster {
  // The number of nodes in the cluster.
  int32 node_count = 1;
}
```

**Note:** 字段 **must not** 使用无符号整数类型，因为许多编程语言与系统对它们支持不佳。

### Compound units

带复合计量单位的数量 **may** 按需在单位之间使用分隔下划线以保持清晰。未缩写的单位 **must** 分隔。缩写单位 **should not** 分隔，除非否则会产生歧义。复合单位 **should** 为复数形式，除最后一个分量单位外所有分量单位用单数形式，最后一个分量单位应为复数形式，除非已缩写。

- `energy_kwh`（**不是** `energy_kw_h`）
- `energy_kw_fortnights`（**不是** `energy_kwfortnight` 或 `energy_kw_fortnight`）

**Note:** 公制前缀 **must not** 与其基本单位分隔。

### Inverse units

计量单位是或包含倒数单位的数量 **should** 把所有倒数单位作为复合单位，放在任何非倒数单位的复合之后，用单词 "per" 分隔。倒数复合单位 **should** 为单数形式。

- `speed_miles_per_hour`（**不是** `speed_mph`）
- `speed_meters_per_second`（**不是** `speed_meters_per_seconds` 或 `speed_meter_per_second`）
- `event_count_per_hour`（**不是** `events_per_hour`、`event_counts_per_hour` 或 `hourly_events`）
- `price_per_kwh`（使用 [`google.type.Money`](https://github.com/googleapis/googleapis/blob/master/google/type/money.proto)）

**Note:** 此指导不适用于存在普遍接受的、带特殊名称与符号的派生单位来表示倒数数量的情形。例如，对倒数时间，适当时候 **should** 使用派生单位 'hertz'。

### Specialized messages

有时创建表示特定数量的 message 很有用。这在两种情形下特别有价值：

- 把两个或更多个别数量分组在一起。例如：[`google.protobuf.Duration`](https://github.com/protocolbuffers/protobuf/blob/master/src/google/protobuf/duration.proto)
- 表示计量单位本身可能变化的常见概念。例如：[`google.type.Money`](https://github.com/googleapis/googleapis/blob/master/google/type/money.proto)

适当时候 APIs **may** 创建 messages 来表示数量。把这些 messages 用作字段时，若直观上说得通，APIs **should** 使用 message 名称作为字段名的后缀。
