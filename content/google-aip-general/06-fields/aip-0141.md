服务经常要表示「有多少」：多少字节、多少英里、多少节点。单位写进字段名，读的人不用猜，跨 API 也不容易各写各的。

## 单位做后缀

带明确计量单位的数量（字节、英里等）必须把单位放在字段名后缀。适当时候，单位应当用普遍接受的缩写，并且不应当把缩写再复数化（例如 `distance_km`，不是 `distance_kilometers`）。

```proto
// A representation of a non-stop air route.
message Route {
  // The airport where the route begins.
  string origin = 1;

  // The destination airport.
  string destination = 2;

  // The distance between the origin and destination airports.
  // This value is also used to determine the credited frequent flyer miles.
  int32 distance_miles = 3;
}
```

数量若是「有几件东西」（例如集群里有几个节点），字段应当用后缀 `_count`，**不是**前缀 `num_`：

```proto
// A cluster of individual nodes.
message Cluster {
  // The number of nodes in the cluster.
  int32 node_count = 1;
}
```

字段不得使用无符号整数类型。很多编程语言和系统对它们支持不好。

### 复合单位

带复合计量单位的数量，分量之间可以加下划线，好读就加。未缩写的单位必须分开。缩写单位不应当分开，除非不分开会歧义。复合单位应当用复数形态：前面的分量用单数，最后一个用复数；已经缩写的除外。

- `energy_kwh`（**不是** `energy_kw_h`）
- `energy_kw_fortnights`（**不是** `energy_kwfortnight` 或 `energy_kw_fortnight`）

公制前缀不得跟基本单位拆开。

### 倒数单位

计量单位是倒数、或含倒数时，应当把所有倒数单位收成一段复合单位，放在非倒数单位后面，用单词 per 隔开。倒数复合单位应当用单数。

- `speed_miles_per_hour`（**不是** `speed_mph`）
- `speed_meters_per_second`（**不是** `speed_meters_per_seconds` 或 `speed_meter_per_second`）
- `event_count_per_hour`（**不是** `events_per_hour`、`event_counts_per_hour` 或 `hourly_events`）
- `price_per_kwh`（使用 [`google.type.Money`](https://github.com/googleapis/googleapis/blob/master/google/type/money.proto)）

已有普遍接受的派生单位（有专名和符号）时，这条不适用。例如倒数时间，适当时候应当用 hertz。

### 专用 message

有时值得专门做一个表示某种数量的 message。两种情形特别有用：

- 把两个或更多个别数量捆在一起。例如 [`google.protobuf.Duration`](https://github.com/protocolbuffers/protobuf/blob/master/src/google/protobuf/duration.proto)
- 表示计量单位本身可能变化的常见概念。例如 [`google.type.Money`](https://github.com/googleapis/googleapis/blob/master/google/type/money.proto)

适当时候，API 可以创建这类 message。把它们当字段用时，直观的话应当用 message 名称当字段名后缀。
