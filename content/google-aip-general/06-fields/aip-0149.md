**英文标题**：Unset field values

在许多 messages 中，许多字段是可选的：用户不必提供它们，或者对输出字段，服务可能不填充该字段。

在大多数情形下，把它设为默认值（例如 `0`）与完全不设置没有有意义的区别；然而，偶尔此区分是有意义的。

## Guidance

在 protocol buffers 中定义的服务 **should** 仅当有必要区分把字段设为其默认值（`0`、`false` 或空字符串）与完全不设置时，才对 primitives 使用 `optional` 关键字：

```proto
// A representation of a book in a library.
message Book {
  option (google.api.resource) = {
    type: "library.googleapis.com/Book"
    pattern: "publishers/{publisher}/books/{book}"
  };

  // The name of the book.
  string name = 1 [(google.api.field_behavior) = IDENTIFIER];

  // The rating for the book, from 0 to 5.
  // 0 is distinct from no rating.
  optional int32 rating = 2;
}
```

**Important:** 服务大多数时候 **should not** 需要区分默认值与未设置；若不需要此类区分的替代设计存在，通常更可取。实践中，这意味着 `optional` **should** 仅用于整数与浮点。

**Important:** 跟踪字段存在性与 [AIP-203]({{< ref "aip-0203" >}}) 中定义的文档化 API 字段行为*不是*同一回事。例如，为存在性跟踪而标注 `optional` 的字段，若该字段必须设置，**may** 同时标注 `google.api.field_behavior = REQUIRED`。若你只想文档化服务器感知的字段行为，阅读 [AIP-203]({{< ref "aip-0203" >}})。

### Backwards compatibility

向现有字段添加或移除 `optional` 限定符是向后不兼容变更。这是因为编译后的 src API 会改变（在某些语言中）。例如，在 Golang 中，添加 `optional` 会把 primitives 的字段类型改为其原始类型的指针变体，例如先前类型为 `string` 的字段变为 `*string` 等。因此，此变更要求客户端与服务器同步更新对已变更字段的使用，这有风险且易出错。更多信息见 [Protobuf 文档](https://protobuf.dev/programming-guides/field-presence/#considerations-for-change-compatibility)。

## Rationale

### field behavior and `optional`

字段行为 annotation 与 `optional` 标签并不互斥，因为它们解决不同问题。前者 `google.api.field_behavior` 专注于传达服务器对该字段在 API 内的感知，例如它是否 required、是否 immutable 等。后者 proto3 的 `optional` 是用于切换字段存在性跟踪的线上格式与代码生成选项。尽管字段同时标注 `google.api.field_behavior = REQUIRED` 并标为 `optional` 可能令人困惑，实践中它们不相关，可以合理地一起使用。
