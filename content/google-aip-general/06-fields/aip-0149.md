**英文标题**：Unset field values

许多 message 里，不少字段是可选的：用户不必提供；对输出字段，服务也可能不填。多数时候，设成默认值（例如 `0`）和完全不设，没有有意义的差别。偶尔，这个差别是有意义的。proto3 的 `optional` 就是为这个差别准备的，不要当成「这个字段可以不填」的文档手段。

## 只在需要区分「默认值」和「没设」时用 optional

在 protocol buffers 里定义的服务，应当仅当有必要区分「设成默认值」（`0`、`false` 或空字符串）和「完全不设」时，才对 primitives 使用 `optional` 关键字：

```proto
// A representation of a book in a library.
message Book {
  option (google.api.resource) = {
    type: "library.googleapis.com/Book"
    pattern: "publishers/{publisher}/books/{book}"
  };

  // The name of the book.
  string name = 1 [(google.api.field_behavior) = IDENTIFIER];

  // The rating for the book, from 0 to 5.
  // 0 is distinct from no rating.
  optional int32 rating = 2;
}
```

服务大多数时候不应当需要区分默认值和未设置。若不需要这类区分的替代设计存在，通常更可取。实践中，这意味着 `optional` 应当只用于整数和浮点。

跟踪字段存在性，和 [AIP-203]({{< ref "aip-0203" >}}) 里定义的文档化 API 字段行为，**不是**同一回事。例如，为存在性跟踪而标了 `optional` 的字段，若该字段必须设置，可以同时标注 `google.api.field_behavior = REQUIRED`。若你只想文档化服务器感知的字段行为，读 [AIP-203]({{< ref "aip-0203" >}})。

### 向后兼容

向现有字段添加或移除 `optional` 限定符是向后不兼容变更。编译后的 src API 会变（在某些语言里）。例如在 Go 里，加上 `optional` 会把 primitives 的字段类型改成指针，原先的 `string` 变成 `*string`。因此客户端和服务器必须同步改用法，有风险、也容易出错。更多信息见 [Protobuf 文档](https://protobuf.dev/programming-guides/field-presence/#considerations-for-change-compatibility)。

## 为何 field_behavior 和 optional 可以同时出现

字段行为 annotation 和 `optional` 标签并不互斥，因为它们解决不同问题。`google.api.field_behavior` 专注于传达服务器对该字段在 API 里的感知：是否 required、是否 immutable 等。proto3 的 `optional` 是线上格式和代码生成选项，用来打开字段存在性跟踪。字段同时标 `google.api.field_behavior = REQUIRED` 又标 `optional`，看起来可能令人困惑，但实践中它们不相关，可以合理地一起用。
