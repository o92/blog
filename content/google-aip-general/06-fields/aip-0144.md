**英文标题**：Repeated fields  
**原文**：[AIP-144](https://google.aip.dev/144) · approved · 创建 2020-03-19 · 更新 2022-06-02  
**许可**：原文 © Google，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

API 里表示一份列表，往往比看起来棘手。用户常常要就地改列表；单个资源里序列一长，分页也跟不上。这篇约定 repeated 字段怎么命名、什么时候该拆成子资源，以及整表 Update 和 Add / Remove 两种改法。

## 可以用，但要有上限

适当时候，资源可以用 repeated 字段。

```proto
message Book {
  option (google.api.resource) = {
    type: "library.googleapis.com/Book"
    pattern: "publishers/{publisher}/books/{book}"
  };

  string name = 1 [(google.api.field_behavior) = IDENTIFIER];

  repeated string authors = 2;
}
```

- Repeated 字段必须用复数字段名。
  - 英语单复数相同的词（"moose"、"info"），必须用词典里的那个词，不要生造复数。
- Repeated 字段应当有强制上限，避免单个资源 payload 过大。经验法则是 100 个元素。
  - 数据有可能变得很大时，API 应当改用子资源。
- Repeated 字段不得内联另一资源的正文。相反，message 应当提供关联资源的 resource names。

### 标量还是 message

若确定将来不需要额外数据，repeated 字段应当用标量（例如 `string`）。上 message 会明显加重认知负担，代码也更绕。

但将来很可能要加额外数据时，应当主动用 message 而不是标量，免得日后并排出现两个 repeated 字段。

### 怎么更新

资源可以用两种策略改 repeated 字段：走标准 Update 方法直接改（见 [AIP-134]({{< ref "aip-0134" >}})），或提供自定义的 `Add` 与 `Remove` 方法。

标准 Update 有一个关键限制：用户只能改**整份**列表。Field mask 无法点到 repeated 字段里的某一条。用户必须先读资源，改完 repeated 值再发回去。很多情形这样没问题，尤其是列表预期很小（大约少于 10），而且竞态不是问题，或可以用 ETag 挡住（见 [AIP-154]({{< ref "aip-0154" >}})）。

声明式友好资源必须用标准 Update，不要引入 `Add` 与 `Remove`。若声明式工具需要推理某几条关系、同时忽略其它关系，考虑改成子资源。

需要原子增删时，API 应当用动词 `Add` 与 `Remove` 定义 custom methods。

这两种策略都太受限时，考虑改用子资源。

```proto
rpc AddAuthor(AddAuthorRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{book=publishers/*/books/*}:addAuthor"
    body: "*"
  };
}

rpc RemoveAuthor(RemoveAuthorRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{book=publishers/*/books/*}:removeAuthor"
    body: "*"
  };
}
```

- 正在添加或移除的数据应当是 primitive（通常是 `string`）。
  - 对带主键的更复杂结构，API 应当改用带 Update 方法的 map。
- RPC 名称必须以单词 `Add` 或 `Remove` 开头。其余部分应当是正在添加的那个字段的单数形式。
- 请求 message 必须与 RPC 名称匹配，并带 `Request` 后缀。
- 响应 message 应当是资源本身。除非响应里有有用的上下文要带上，这时响应 message 必须与 RPC 名称匹配，并带 `Response` 后缀。
  - 响应是资源本身时，应当包含完全填充的资源。
- HTTP 动词必须是 `POST`，跟 custom methods 通常一样（见 [AIP-136]({{< ref "aip-0136" >}})）。
- HTTP URI 必须以 `:add*` 或 `:remove*` 结尾，其中 `*` 是正在添加或移除的字段的 snake-case 单数名。
- 接收 resource name 的请求字段应当映射到 URI 路径。
  - HTTP 变量应当是资源的名称（例如 `book`），不是 `name` 或 `parent`。
  - 该变量应当是 URI 路径里唯一的变量。
- `google.api.http` annotation 里的 body 子句应当是 `"*"`。
- `Add` 时若数据已经存在，该方法必须以 `ALREADY_EXISTS` 报错。
- `Remove` 时若数据不存在，该方法必须以 `NOT_FOUND` 报错。

#### 请求 message

```proto
message AddAuthorRequest {
  // The name of the book to add an author to.
  string book = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];

  string author = 2 [(google.api.field_behavior) = REQUIRED];
}

message RemoveAuthorRequest {
  // The name of the book to remove an author from.
  string book = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];

  string author = 2 [(google.api.field_behavior) = REQUIRED];
}
```

- 必须包含资源字段。它应当是资源的名称（例如 `book`），不是 `name` 或 `parent`。
  - 该字段应当标注为 required（见 [AIP-203]({{< ref "aip-0203" >}})）。
  - 该字段应当标明它所引用的 resource type（见 [AIP-123]({{< ref "aip-0123" >}})）。
- 必须包含正在添加或移除的那个值。它应当用该字段的单数名。
  - 该字段应当标注为 required（见 [AIP-203]({{< ref "aip-0203" >}})）。
- 请求 message 不得再包含任何其它必填字段，也不应当再塞其它可选字段，除非本文或另一篇 AIP 有写。
