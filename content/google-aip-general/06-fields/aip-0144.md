**英文标题**：Repeated fields  
**原文**：[AIP-144](https://google.aip.dev/144) · approved · 创建 2020-03-19 · 更新 2022-06-02  
**许可**：原文 © Google，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

在 API 中表示数据列表往往比看起来更棘手。用户常常需要就地修改列表，并且单个资源内较长的数据序列对分页构成挑战。

## Guidance

适当时候资源 **may** 使用 repeated 字段。

```proto
message Book {
  option (google.api.resource) = {
    type: "library.googleapis.com/Book"
    pattern: "publishers/{publisher}/books/{book}"
  };

  string name = 1 [(google.api.field_behavior) = IDENTIFIER];

  repeated string authors = 2;
}
```

- Repeated 字段 **must** 使用复数字段名。
  - 若英语单数与复数单词相同（"moose"、"info"），**must** 使用词典单词，而不是试图创造新的复数形式。
- Repeated 字段 **should** 有不会导致单个资源 payload 过大的强制上限。经验法则是 100 个元素。
  - 若 repeated 数据有过大的可能，API **should** 改为使用子资源。
- Repeated 字段 **must not** 内联表示另一资源的正文。相反，message **should** 提供关联资源的 resource names。

### Scalars and messages

若确定将来不需要额外数据，repeated 字段 **should** 使用标量类型（例如 `string`），因为使用 message 类型会增加显著的认知开销并导致更复杂的代码。

然而，若将来很可能需要额外数据，repeated 字段 **should** 主动使用 message 而不是标量，以避免并行的 repeated 字段。

### Update strategies

资源 **may** 使用两种策略来启用更新 repeated 字段：使用 [标准 `Update`]({{< ref "aip-0134" >}}) 方法直接更新，或自定义 `Add` 与 `Remove` 方法。

标准 `Update` 方法有一个关键限制：用户只能更新*整个*列表。Field masks 无法寻址 repeated 字段中的个别条目。这意味着用户必须读取资源，按需修改 repeated 字段值，再把它发回。这对许多情形没问题，尤其当 repeated 字段预期规模较小（大约少于 10）且竞态不是问题，或可以用 [ETags]({{< ref "aip-0154" >}}) 防护时。

**Note:** 声明式友好资源 **must** 使用标准 `Update` 方法，并且不引入 `Add` 与 `Remove` 方法。若声明式工具需要推理特定关系同时忽略其它关系，考虑改为使用子资源。

若需要原子修改，API **should** 使用动词 `Add` 与 `Remove` 定义 custom methods：

**Note:** 若这两种策略都太受限，考虑改为使用子资源。

```proto
rpc AddAuthor(AddAuthorRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{book=publishers/*/books/*}:addAuthor"
    body: "*"
  };
}

rpc RemoveAuthor(RemoveAuthorRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{book=publishers/*/books/*}:removeAuthor"
    body: "*"
  };
}
```

- 正在添加或移除的数据 **should** 为 primitive（通常是 `string`）。
  - 对带主键的更复杂数据结构，API **should** 改为使用带 `Update` 方法的 map。
- RPC 的名称 **must** 以单词 `Add` 或 `Remove` 开头。RPC 名称的其余部分 **should** 为正在添加的字段的单数形式。
- 请求 message **must** 与 RPC 名称匹配，并带 `Request` 后缀。
- 响应 message **should** 为资源本身，除非响应中有有用的上下文要提供，此时响应 message 必须与 RPC 名称匹配，并带 `Response` 后缀。
  - 当响应是资源本身时，它 **should** 包含完全填充的资源。
- HTTP 动词 **must** 为 `POST`，与 [custom methods]({{< ref "aip-0136" >}}) 通常一样。
- HTTP URI **must** 以 `:add*` 或 `:remove*` 结尾，其中 `*` 是正在添加或移除的字段的 snake-case 单数名称。
- 接收 resource name 的请求 message 字段 **should** 映射到 URI 路径。
  - HTTP 变量 **should** 为资源的名称（例如 `book`）而不是 `name` 或 `parent`。
  - 该变量 **should** 是 URI 路径中的唯一变量。
- `google.api.http` annotation 中的 body 子句 **should** 为 `"*"`。
- 若 `Add` RPC 中正在添加的数据已经存在，该方法 **must** 以 `ALREADY_EXISTS` 报错。
- 若 `Remove` RPC 中正在移除的数据不存在，该方法 **must** 以 `NOT_FOUND` 报错。

#### Request Message

```proto
message AddAuthorRequest {
  // The name of the book to add an author to.
  string book = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];

  string author = 2 [(google.api.field_behavior) = REQUIRED];
}

message RemoveAuthorRequest {
  // The name of the book to remove an author from.
  string book = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference).type = "library.googleapis.com/Book"
  ];

  string author = 2 [(google.api.field_behavior) = REQUIRED];
}
```

- **must** 包含资源字段。它 **should** 为资源的名称（例如 `book`）而不是 `name` 或 `parent`。
  - 该字段 **should** 被 [标注为 required]({{< ref "aip-0203" >}})。
  - 该字段 **should** 标识它所引用的 [resource type]({{< ref "aip-0123" >}})。
- **must** 包含正在添加或移除的值的字段。它 **should** 为该字段的单数名称。
  - 该字段 **should** 被 [标注为 required]({{< ref "aip-0203" >}})。
- 请求 message **must not** 包含任何其它必填字段，并且 **should not** 包含其它可选字段，除非本文或另一篇 AIP 有描述。
