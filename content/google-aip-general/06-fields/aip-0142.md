**英文标题**：Time and duration  
**原文**：[AIP-142](https://google.aip.dev/142) · approved · 创建 2019-07-16

服务经常要表示时间。日历和时区本身就绕，JSON 这类交换格式又没有原生时间类型，字段一不小心就会各写各的。这篇把「绝对时刻、时长、日历日期」拆开，并约定该用哪些 common components。

## 用现成的时间类型

表示时间的字段应当用常见、普遍使用的组件，例如 [`google.protobuf.Timestamp`](https://github.com/protocolbuffers/protobuf/blob/master/src/google/protobuf/timestamp.proto) 或 [`google.type.Date`](https://github.com/googleapis/googleapis/blob/master/google/type/date.proto)。这些类型是 common components（见 [AIP-213]({{< ref "aip-0213" >}})）。大家用同一套，基础设施和工具处理时间值时才好做。

### Timestamp

表示绝对时间点（跟时区、日历无关）的字段应当用 [`google.protobuf.Timestamp`](https://github.com/protocolbuffers/protobuf/blob/master/src/google/protobuf/timestamp.proto)。底层是 UNIX timestamp，精度到纳秒。

这些字段应当以 `_time` 结尾，例如 `create_time`、`update_time`。Repeated 字段应当改以 `_times` 结尾。

许多时间戳对应一项活动：`create_time` 就是这个资源何时被创建。这类字段应当按 `{imperative}_time` 来命名。例如一本书正在出版，记下这件事发生时刻的字段用动词 to publish 的祈使形式 publish，得到 `publish_time`。不应当用过去时，例如 `published_time`、`created_time`、`last_updated_time`。

### Duration

表示两个时间点之间的跨度（同样跟时区、日历无关）的字段应当用 [`google.protobuf.Duration`](https://github.com/protocolbuffers/protobuf/blob/master/src/google/protobuf/duration.proto)。

时间戳和时长的差别，用一条航班记录就能看清：

```proto
// A representation of a (very incomplete) flight log.
message FlightRecord {
  // The absolute point in time when the plane took off.
  google.protobuf.Timestamp takeoff_time = 1;

  // The length (duration) of the flight, from takeoff to landing.
  google.protobuf.Duration flight_duration = 2;
}
```

细心的读者会发现 [timestamp](https://github.com/protocolbuffers/protobuf/blob/master/src/google/protobuf/timestamp.proto) 和 [duration](https://github.com/protocolbuffers/protobuf/blob/master/src/google/protobuf/duration.proto) 的结构一样（`int64 seconds` 加 `int32 nanos`）。但语义不同，这个区分很重要。工具也可以按用的是哪个 message 来决定行为。例如 Python 侧可以把 timestamp 转成 [datetime](https://docs.python.org/3/library/datetime.html#datetime.datetime)，把 duration 转成 [timedelta](https://docs.python.org/3/library/datetime.html#datetime.timedelta)。

### 流内的相对片段

有时要表示一段流里面的时间片段。这时应当用 [`google.protobuf.Duration`](https://github.com/protocolbuffers/protobuf/blob/master/src/google/protobuf/duration.proto)，字段名应当以 `_offset` 结尾。为把含义说清楚，该字段必须有注释，说明这个偏移相对哪一点。

例如表示音频流里的一段：

```proto
message AudioSegment {
  // The duration relative to the start of the stream representing the
  // beginning of the segment.
  google.protobuf.Duration start_offset = 1;

  // The total length of the segment.
  google.protobuf.Duration segment_duration = 2;
}
```

### 民用日期和时间

表示日历日期或墙上时钟时间的字段应当用对应的 common components：

- 民用日期：[`google.type.Date`](https://github.com/googleapis/googleapis/blob/master/google/type/date.proto)
- 墙上时钟时间：[`google.type.TimeOfDay`](https://github.com/googleapis/googleapis/blob/master/google/type/timeofday.proto)

表示民用日期的字段应当以 `_date` 结尾。表示民用时间或日期时间的字段应当以 `_time` 结尾。

`Date` 和 `TimeOfDay` 都跟时区无关。需要感知时区的字段应当用 `DateTime`（见下一节）。

### 民用时间戳

表示民用时间戳（日期加时间，可选带时区）的字段应当用 [`google.type.DateTime`](https://github.com/googleapis/googleapis/blob/master/google/type/datetime.proto)，字段名应当以 `_time` 结尾。

### 兼容遗留格式

偶尔，API 因遗留或兼容性没法用这些常见结构。例如要对齐另一份规范，那份规范强制时间戳是整数或 [ISO-8601](https://www.iso.org/iso-8601-date-and-time-format.html) 字符串。

这时字段可以用别的类型。若可能，按下面约定命名：

- 整数：带上含义（例如 `time`、`duration`、`delay`、`latency`），**以及**计量单位做最后的后缀。有效单位：`seconds`、`millis`、`micros`、`nanos`。例如 `send_time_millis`。
- 字符串：带上含义（例如 `time`、`duration`、`delay`、`latency`），不要单位后缀。

无论哪种情形，都要把期望格式和选用它的理由写清楚。
