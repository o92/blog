**英文标题**：States  
**原文**：[AIP-216](https://google.aip.dev/216) · approved · 创建 2018-10-01 · 更新 2022-06-02

许多 API 资源带有「state」概念：资源在生命周期里走到了哪一步。虚拟机可能正在供给、可供使用、正在关闭。作业或查询可能正在准备、正在跑、已经完成。这篇约定：用 `State` enum 来表达，不要用 Update 直接改，走自定义的状态转换方法。

## 用 State，不要用 Status

需要传达 state 的资源应当用 enum。它应当叫 `State`（若需要更具体，以单词 `State` 结尾）。当它只作为该 message 内的字段使用时，此 enum 应当嵌套在它所描述的 message 内。

我们用术语 `State`，**不是** `Status`（后者留给 HTTP 与 gRPC statuses）。

### Enum 取值

理想情况下，Google APIs 在表达相同语义时全程用相同术语。表达某个 state 往往有很多词可选，但客户常常把多个 API 一起用，术语一致时他们更好过。

高层次约定：

- 可供使用的资源是 `ACTIVE`（优先于 ready、available 这类词）。
- 已完成（通常是终止性的）所请求动作的资源，用过去分词（通常以 `-ED` 结尾），例如 `SUCCEEDED`（不是 successful）、`FAILED`（不是 failure）、`DELETED`、`SUSPENDED`。
- 当前正在经历 state 变更的资源，用现在分词（通常以 `-ING` 结尾），例如 `RUNNING`、`CREATING`、`DELETING`。这时期望该 state 是暂时的，会自行落到另一 state，不必再等用户动作。

只添加对客户有用的 states。仅仅因为内部系统里有，就暴露一大堆 states，没必要，还会给客户添乱。每个 state 必须带有为何必要的用例。

### Output only

资源里引用 `State` enum 的字段，应当按 [AIP-203]({{< ref "aip-0203" >}}) 表现为并文档化为 Output only。

API 不应当允许通过 Update 方法直接改 `State` enum（也不应当通过 Create 直接设），而应当改用自定义的 state transition methods。

原因有二。Update 一般不期望有副作用。直接改 state 还意味着可以把它设成任何可用值，而 states 通常反映的是资源在生命周期里的进展。

### 状态转换方法

State transition methods 是一类特殊的 custom method，负责把 state 字段从一个 enum 值转到另一个。转换过程中其它字段也可能变，例如 `update_time`。方法定义应当如下：

```proto
// Publishes a book.
// The `state` of the book after publishing is `PUBLISHED`.
// `PublishBook` can be called on Books in the state `DRAFT`; Books in a
// different state (including `PUBLISHED`) returns an error.
rpc PublishBook(PublishBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:publish"
    body: "*"
  };
}
```

- 方法名称应当是动词后跟资源 message 名称的单数形式。
- 请求 message 必须与 RPC 名称匹配，并带 `Request` 后缀。
- 响应 message 应当是资源本身。
  - 若 RPC 是长时运行的（见 [AIP-151]({{< ref "aip-0151" >}})），响应 message 应当是解析为资源本身的 `google.longrunning.Operation`。
- HTTP 动词必须是 `POST`。
- HTTP URI 必须使用 `:` 后跟自定义动词（上例是 `:publish`），并且 URI 里的动词必须与 RPC 名称中的动词匹配。
  - 若需要词分隔，必须用 `camelCase`。
- `google.api.http` annotation 里的 `body` 子句必须是 `"*"`。
- 接收 resource name 的请求字段应当映射到 URI 路径。
  - 该字段应当叫 `name`。
  - `name` 字段应当是 URI 路径里唯一的变量。其余参数应当映射到 URI query parameters。
- 若不允许这次 state 转换，服务必须以 `FAILED_PRECONDITION`（HTTP 400）报错。

请求 message 应当如下：

```proto
message PublishBookRequest {
  // The name of the book to publish.
  // Format: publishers/{publisher}/books/{book}
  string name = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference) = {
      type: "library.googleapis.com/Book"
    }];
}
```

- 必须包含 resource name 字段。它应当叫 `name`。
- 该字段的注释应当文档化资源 pattern。
- 可以包含其它字段。

## 补充约定

### 默认值

每个 state enum 的零值应当遵循下列约定：

```proto
enum State {
  // The default value. This value is used if the state is omitted.
  STATE_UNSPECIFIED = 0;

  // Other values...
}
```

资源不应当向用户提供未指定的 state，这个值实际上也不应当被使用。

### 取值不得撞名

同一 package 内的多个顶层 enums 必须不共享相同的值。C++ protoc 代码生成器会把顶层 enum 值展平到单个命名空间。

State enums 应当住在资源定义内部。

### 前缀

在每个 enum 值上加 `STATE_` 前缀没有必要。除默认值 `STATE_UNSPECIFIED` 外，State enum 值不应当以前缀带上 enum 名称。

### 破坏性变更

简短说：向用户讲清楚，state enums 将来可能收到新值；向现有 enum 加 states 时保持审慎。

向现有 states enum 添加 states *可能* 破坏现有用户代码，但添加 states 不视为破坏性变更。设想只有两个值的 state：`ACTIVE` 与 `DELETED`。用户可能写 `if state == ACTIVE`，else 里简单假定资源已删除。API 后来为另一目的加了新 state，这段代码就会坏。

我们最终控制不了这种写法，但 API 文档应当积极鼓励用户：针对 state enums 写代码时，预期它们将来可能收到新值。

适当时候 API 可以向现有 State enum 添加新 states，并且添加新 state **不**视为破坏性变更。

### 什么时候别用 states

有时 `State` enum 不是对你的 API 最好的选择，尤其是潜在值非常少，或 states 并非互斥。

还是上面只有 `ACTIVE` 与 `DELETED` 的例子。这时 API 可能更好地暴露 `google.protobuf.Timestamp delete_time`，让用户靠它是否设置来判断删除。

### 常用 states

下面是常用 states 的列表。确定 state 名称时，API 应当考虑先例；先例冲突时，应当把局部一致性放在全局一致性之上。

#### Resting states

Resting states 是生命周期 states：没有用户动作时，预期会无限期保持。用户可以发起动作，把处于 resting state 的资源移到其它 states（resting 或 active）。

- `ACCEPTED`
- `ACTIVE`
- `CANCELLED`
- `DELETED`
- `FAILED`
- `SUCCEEDED`
- `SUSPENDED`
- `VERIFIED`

#### Active states

Active states 是通常会自行落到单个预期 resting state 的生命周期 states。

只暴露对客户有用的 states。仅当资源会在该 state 里停留足够长时间时，active states 才有价值。state 变更是立即的，就不需要 active states。

- `CREATING`（通常变为 `ACTIVE`）
- `DELETING`（通常变为 `DELETED`）
- `PENDING`（通常变为 `RUNNING`）
- `REPAIRING`（通常变为 `ACTIVE`）
- `RUNNING`（通常变为 `SUCCEEDED`）
- `SUSPENDING`（通常变为 `SUSPENDED`）
