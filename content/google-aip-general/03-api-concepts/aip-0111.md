API 上的资源与方法可按其驻留或操作的 *plane* 划分。就 API 而言，定义下列 planes：

- Management plane：统一、面向资源的 API，主要用于配置并允许检索资源。
- Data plane：异质 API（最好仍面向资源），读写用户数据。常常连接到由 management plane 供给的实体，例如虚拟机。

"plane" 一词原用于网络架构。尽管系统与网络架构常常还定义其它 planes（例如 control plane 或 power planes），由于 AIP 聚焦于接口，那些 planes 不在本 AIP 中定义。

## Guidance

### Management Plane

管理资源与方法的存在，主要是为了供给、配置并审计 data plane 所对接的那些资源。

例如，对云提供商而言，下列被视为管理资源：

- 虚拟机
- 虚拟私有网络
- 虚拟磁盘
- 一个 blob store 实例
- 一个 project 或 account

### Data Plane

data plane 上的方法以多种数据格式操作用户数据，并且一般对接经由 management plane API 供给的资源。data plane 方法的例子包括：

- 对表读写行
- 向消息队列推送或从中拉取
- 向 blob store 实例上传 blobs，或从中下载 blobs

由于包括高吞吐、低延迟、或须遵循既有接口规范（例如 ANSI SQL）在内的要求，Data plane APIs 在更大的 API 表面上 **may** 是异质的。

- 为方便起见，操作于 data plane 的资源与方法 **may** 通过面向资源的 management APIs 暴露自己。若如此，那些资源与方法 **must** 遵守其它 AIP 中为 management plane 规定的要求（[AIP-131]({{< ref "aip-0131" >}}) 至 [AIP-135]({{< ref "aip-0135" >}})）。

### 管理平面与数据平面的主要区别

- [Declarative Clients]({{< ref "aip-0009" >}}) 只操作于 management plane。
- Data planes 常常处于面向用户功能的关键路径上，因此：
  - 可用性要求高于 management planes。
  - 比 management planes 更对性能敏感。
  - 比 management planes 需要更高吞吐。
