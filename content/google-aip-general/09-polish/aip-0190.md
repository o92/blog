名字一旦发出去就很难改。这篇把 interfaces、resources、collections、methods、messages 的命名约定收在一起，好让很多 APIs、很长时间内，开发者体验还是同一套。一般而言，这些约定适用于所有 Google 管理的服务。

## 总原则

API 使用的所有名称应当是：

- straightforward（直白）
- intuitive（直观）
- consistent（一致）

英语对许多开发者是第二语言。命名约定的目标之一，是让每个 API 名称对大多数开发者可理解。办法是：给 methods 与 resources 起名时，用简单、一致、较小的词汇。

- APIs 中使用的名称应当使用正确的美式英语。例如 license（而不是 licence）、color（而不是 colour）。
- 为简洁起见，可以使用被普遍接受的长词缩写。例如 API 优于 Application Programming Interface。
- 除非另有规定，定义必须使用 UpperCamelCase 名称，如 [Google Java Style](https://google.github.io/styleguide/javaguide.html#s5.3-camel-case) 所定义。
- 尽可能用直观、熟悉的术语。例如描述移除（并销毁）资源时，delete 优于 erase。
- 对同一概念使用相同名称或术语，包括跨 APIs 共享的概念。
- 避免名称过载。对不同概念使用不同名称。
- 避免在该 API 以及更大的 Google APIs 生态语境中含糊的、过于宽泛的名称。它们容易让人误解 API 概念。应当选能准确描述 API 概念的具体名称。这对定义一阶 API 元素（例如 resources）的名称尤其重要。没有一份「不要用的名字」确定清单，因为每个名称都必须放在其它名称的语境里评估。Instance、info 与 service 是过去出过问题的名称示例。所选名称应清楚描述 API 概念（例如：instance of what?），并把它与其它相关概念区分开（例如："alert" 是指规则、信号还是通知？）。
- 仔细考虑可能与常见编程语言关键字冲突的名称。此类名称可以使用，但很可能在 API 评审中触发额外审查。谨慎且节制地使用。

### interface name

为避免与 Service Names（见 [AIP-9]({{< ref "aip-0009" >}})）（例如 `pubsub.googleapis.com`）混淆，术语 interface name 指在 .proto 文件中定义 `service` 时使用的名称：

```proto
// Library is the interface name.
service Library {
  rpc ListBooks(...) returns (...);
  rpc ...
}
```

可以把 service name 想成对一组 APIs 实际实现的引用，而 interface name 指 API 的抽象定义。

interface name 应当使用直观名词，例如 Calendar 或 BlobStore。该名称不应当与编程语言及其运行时库中任何已确立的概念冲突（例如 File）。

在罕见情形下，当 interface name 会与 API 内另一个名称冲突时，应当使用后缀（例如 `Api` 或 `Service`）来消歧。

### 方法名

服务可以在其 IDL 规范中定义一个或多个对应集合与资源上方法的 API methods。方法名应当遵循 UpperCamelCase 的 `VerbNoun` 命名约定，其中名词通常是资源类型。

标准方法及其 Batch 变体的命名指导：

| Method | Standard | Batch |
|--|--|--|
| `Get` | [AIP-131]({{< ref "aip-0131" >}}) | [AIP-231]({{< ref "aip-0231" >}}) |
| `List` | [AIP-132]({{< ref "aip-0132" >}}) | N/A |
| `Create` | [AIP-133]({{< ref "aip-0133" >}}) | [AIP-233]({{< ref "aip-0233" >}}) |
| `Update` | [AIP-134]({{< ref "aip-0134" >}}) | [AIP-234]({{< ref "aip-0234" >}}) |
| `Delete` | [AIP-135]({{< ref "aip-0135" >}}) | [AIP-235]({{< ref "aip-0235" >}}) |

所有其它方法视为 Custom Methods，命名见 [AIP-136]({{< ref "aip-0136" >}})。

### Message 名称

Message 名称应当短、精炼。避免不必要或冗余的词。若没有不含该形容词的对应 message，形容词常常可以省略。例如，若没有非共享的 proxy settings，则 `SharedProxySettings` 中的 `Shared` 是不必要的。

Message 名称不应当包含介词（例如 "With"、"For"）。一般而言，带介词的 message 名称更好地表示为 message 上的 optional 字段。

#### 请求与响应 messages

请求与响应 message 名称见 [AIP-136]({{< ref "aip-0136" >}})（custom methods）以及标准方法对应的 AIP。
