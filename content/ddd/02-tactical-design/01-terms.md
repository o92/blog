## 简单逻辑

### Transaction Script

- **中文**：事务脚本
- 按**对外一次操作**组织过程式逻辑；每次调用必须具备事务语义（全成或全败）。适合 Supporting / 简单 ETL；不适合 Core。

### Active Record

- **中文**：活动记录
- 用对象封装较复杂数据结构 + CRUD；业务过程仍常是 Transaction Script，只是通过 Active Record 访问数据。适合「数据复杂、规则仍简单」。

## Domain Model 构件

### Domain Model

- **中文**：领域模型
- 用对象同时承载**数据与行为**，表达复杂状态迁移、规则与不变量。优先业务语言，避开基础设施泄漏。

### Value Object

- **中文**：值对象
- **简称**：VO
- 由属性值整体标识；**不可变**；相等比的是值。描述实体属性（金额、电话、颜色等），集中校验与行为，对抗 Primitive Obsession。

### Entity

- **中文**：实体
- 需要显式身份（Id）；状态可随生命周期变化。在 Domain Model 中通常不独立落地，而作为 **Aggregate** 的一部分。

### Aggregate

- **中文**：聚合
- 一致性与事务边界：外部只读其状态，只能通过命令改；**一次数据库事务只改一个聚合实例**。尽量小，只纳入必须强一致的对象；外部聚合用 Id 引用。

### Aggregate Root

- **中文**：聚合根
- 聚合对外唯一入口；内部实体/值对象经根访问与修改。

### Domain Event

- **中文**：领域事件
- 描述域内**已发生**的重要事实（过去时命名）；携带必要数据；由聚合发布，供订阅方反应。

### Domain Service

- **中文**：领域服务
- 放不进单个实体/聚合、但仍属领域的操作（常跨多个聚合的**只读**协作或计算）。**不是**「一次事务改多个聚合」的后门。

### Repository

- **中文**：仓储
- 按聚合加载/保存的抽象；应用层：加载 → 执行命令 → 保存，并处理并发冲突。

## 时间与架构

### Event Sourcing

- **中文**：事件溯源
- **简称**：ES
- 以领域事件序列为事实来源；当前状态由事件重放得到。利于审计、时间线洞察；常与 CQRS 搭配。

### Layered Architecture

- **中文**：分层架构
- 表现 / 业务 / 数据访问等横向层。业务常依赖数据访问，适合 Transaction Script / Active Record；难彻底隔离 Domain Model。

### Ports & Adapters

- **中文**：端口与适配器（六边形）
- 业务在中心，基础设施经端口适配；依赖倒置。适合 Domain Model。

### CQRS

- **中文**：命令查询职责分离
- Command 侧改状态（写模型），Query 侧用专门读模型。利于多模型/多存储、Event Sourcing 投影；投影可同步或异步。

## 通信

### Outbox

- **中文**：发件箱模式
- 聚合状态与待发消息在**同一原子事务**落库，再由中继投递到消息总线，保证「改库成功则消息终将发出」。

### Saga

- **中文**：saga
- 跨多个事务/组件的长流程；常把事件映射为下一步命令，流程相对线性。

### Process Manager

- **中文**：过程管理器
- 维护流程状态，按业务规则决定下一步；比 Saga 更适合有分支、策略的复杂编排。
