战术设计专名。悬停看气泡；「显示更多」跳到本页词条。

## 简单逻辑

### Transaction Script

- **中文**：事务脚本
- 按**对外一次操作**组织过程式逻辑；每次调用必须具备事务语义（全成或全败）。适合 Supporting / 简单 ETL；不适合 Core。

### Active Record

- **中文**：活动记录
- 用对象封装较复杂数据结构 + CRUD；业务过程仍常是 Transaction Script，只是通过 Active Record 访问数据。适合「数据复杂、规则仍简单」。

## Domain Model 构件

### Domain Model

- **中文**：领域模型
- 用对象同时承载**数据与行为**（俗称**充血模型**），表达复杂状态迁移、规则与不变量。优先业务语言，避开基础设施泄漏。
- 对比：**Anemic Domain Model（贫血模型）** 只有数据、行为在外部 Service——不是本模式。

### Value Object

- **中文**：值对象
- **简称**：VO
- 由属性值整体标识；**不可变**；相等比的是值。描述实体属性（金额、电话、颜色等），集中校验与行为，对抗 Primitive Obsession。

### Primitive Obsession

- **中文**：原始类型偏执
- 过度用 `string` / `int` 等原始类型承载有业务含义的概念，校验与意图分散。用 Value Object 表达电话、金额等可缓解。

### Entity

- **中文**：实体
- 需要显式身份（Id）；状态可随生命周期变化。在 Domain Model 中通常不独立落地，而作为 **Aggregate** 的一部分。

### Aggregate

- **中文**：聚合
- 一致性与事务边界：外部只读其状态，只能通过命令改；**一次数据库事务只改一个聚合实例**。尽量小，只纳入必须强一致的对象；外部聚合用 Id 引用。

### Aggregate Root

- **中文**：聚合根
- 聚合对外唯一入口；内部实体/值对象经根访问与修改。

### Domain Event

- **中文**：领域事件
- 描述域内**已发生**的重要事实（过去时命名）；携带必要数据；由聚合发布，供订阅方反应。

### Domain Service

- **中文**：领域服务
- 放不进单个实体/聚合、但仍属领域的操作（常跨多个聚合的**只读**协作或计算）。**不是**「一次事务改多个聚合」的后门。

### Repository

- **中文**：仓储
- 按聚合加载/保存的抽象；应用层：加载 → 执行命令 → 保存，并处理并发冲突。

## 时间与架构

### Event Sourcing

- **中文**：事件溯源
- **简称**：ES
- 以领域事件序列为事实来源；当前状态由事件重放得到。利于审计、时间线洞察；常与 CQRS 搭配。

### Layered Architecture

- **中文**：分层架构
- 表现 / 业务 / 数据访问等横向层。业务常依赖数据访问，适合 Transaction Script / Active Record；难彻底隔离 Domain Model。

### Ports & Adapters

- **中文**：端口与适配器（六边形）
- 业务在中心，基础设施经端口适配；依赖倒置。适合 Domain Model。

### CQRS

- **中文**：命令查询职责分离
- Command 侧改状态（写模型），Query 侧用专门读模型。利于多模型/多存储、Event Sourcing 投影；投影可同步或异步。

## 通信

### Outbox

- **中文**：发件箱模式
- 聚合状态与待发消息在**同一原子事务**落库，再由中继投递到消息总线，保证「改库成功则消息终将发出」。

### Saga

- **中文**：长流程编排（saga）
- **要解决的事**：一次数据库事务只能改一个 Aggregate，但真实业务流程常跨多个聚合/服务。
- **做法**：把长流程拆成一串本地事务；每步成功后发事件，下一步靠「事件 → 命令」推进。
- **特点**：映射关系简单、流程大致**线性**；编排逻辑可分散在各订阅方（像接力），本身通常**不持有**复杂流程状态机。
- **失败**：用补偿命令（反向业务操作），不是分布式大事务回滚。

### Process Manager

- **中文**：过程管理器
- **要解决的事**：和 Saga 一样跨事务，但路径会**分叉**、要记「流程走到哪了」、按规则选下一步。
- **做法**：有一个中央组件持有**流程实例状态**，订阅相关事件，按业务逻辑发出下一步命令（更像总指挥）。
- **相对 Saga**：Saga ≈ 简单的事件→命令表；Process Manager ≈ 带状态与分支的流程决策器。
