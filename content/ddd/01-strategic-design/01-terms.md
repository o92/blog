## 域与子域

### Domain-Driven Design

- **中文**：领域驱动设计
- **简称**：DDD
- 以业务域为核心，对齐模型与软件设计。

### Business Domain

- **中文**：业务域
- 公司主要活动领域；向客户提供的服务（可有多个，也可随时间迁移）。

### Subdomain

- **中文**：子域
- 更细的业务活动块；全部子域合起来支撑 Business Domain。单个子域通常不够「赢」，要彼此协作。

### Core Subdomain

- **中文**：核心子域
- **简称**：Core（亦称 Core Domain）
- 相对对手的差异化来源（发明、优化、诀窍、IP）。本身复杂、易变；应 **自研**，用最强工程能力。原书偏好 Core Subdomain，以免与 Business Domain 混淆。

### Supporting Subdomain

- **中文**：支撑子域
- **简称**：Supporting
- 业务需要，但不提供竞争优势；逻辑多为 CRUD / ETL 级「显而易见」；可自研或外包，不必上最重模式。

### Generic Subdomain

- **中文**：通用子域
- **简称**：Generic
- 大家做得一样的复杂问题（认证、加密、清结算等）；**买/采用**现成方案通常更划算，本身不构成差异化。

### Domain Expert

- **中文**：领域专家
- 业务侧权威；需求与心智模型的源头。不是「写代码的分析师」，而是业务问题提出者或深度使用者。

## 语言与模型

### Ubiquitous Language

- **中文**：统一语言 / 通用语言
- **简称**：UL
- 项目各方共用的**业务**用语（不要技术黑话）。在所属 Bounded Context **内**一致；不是全公司一个万能词表。

### Model

- **中文**：模型
- 有目的的简化表示：强调有用细节、忽略其余。地图是经典类比——「所有模型都错，有用的才留下」。

### Analysis Model

- **中文**：分析模型
- 传统流程里把业务「翻译」成工程师可读需求的中间产物；多次翻译易丢领域知识（类似传话游戏）。

## 边界

### Bounded Context

- **中文**：限界上下文
- **简称**：BC
- Ubiquitous Language / Model 的一致性边界与适用范围。**设计出来的**（相对 Subdomain 的「发现」）。常对应独立可演进的服务/项目，并最好由**一个团队**拥有。

### Context Map

- **中文**：上下文映射
- 画出各 Bounded Context 及之间集成关系的鸟瞰图；也反映团队协作与组织问题。

## 集成模式

### ad hoc

- **中文**：临时的 / 就事论事的
- 拉丁语，字面「为此（目的）」：没有事先订好的通用协议，碰到问题再当面协商、按这次需要处理。Partnership 里的「双向 ad hoc」= 两边随时口头/即时对齐改接口，而不是先公布一份固定的 Published Language。

### Partnership

- **中文**：合作伙伴
- 协作良好时的 ad hoc 双向协调；双方共同解决集成问题。对地理分散团队往往吃力。

### Shared Kernel

- **中文**：共享内核
- **简称**：SK
- 多个 Bounded Context **共享一小块**必须一致的模型（理想上主要是契约与跨边界数据结构）。变更要立刻传播并跑集成测试；仅在「重复成本 > 协调成本」时用。

### Customer–Supplier

- **中文**：客户–供应商
- 上游提供服务、下游消费；权力可能偏向上游或下游。

### Upstream / Downstream

- **中文**：上游 / 下游
- Supplier 为 Upstream；Consumer 为 Downstream。

### Conformist

- **中文**：顺从者
- 下游接受上游模型（行业标准、或「够用」时）。

### Anticorruption Layer

- **中文**：防腐层
- **简称**：ACL
- 下游把上游模型**翻译**成适合自己的模型；保护 Core、隔离遗留脏模型、缓冲频繁变更。

### Open-Host Service

- **中文**：开放主机服务
- **简称**：OHS
- 上游为消费者提供便利的公共协议，把实现模型与集成模型解耦；公共侧常用 **Published Language**，并可多版本并行。

### Published Language

- **中文**：发布语言
- 面向集成的公共协议用语；不必等同于上游内部 Ubiquitous Language。

### Separate Ways

- **中文**：各行其道
- 不协作、在各自上下文中重复实现。适用于沟通成本过高、Generic 本地集成更便宜、或模型差到翻译不划算等；**应避免**在 Core Subdomain 上重复。
