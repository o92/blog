基于 Evelyn van Kelle、Gien Verschatse、Kenny Baas-Schwegler《Collaborative Software Design: How to facilitate domain modeling decisions》的学习笔记（摘记）。专名以 **英文** 为准；悬停看气泡。可与站内 [Domain-Driven Design]({{< ref "ddd" >}}) 对照阅读。

### 这本书在说什么

好技术团队 + 善意业务方，仍可能做出对组织无效的软件：团队过早钻解决方案、利益相关方在技术场合噤声、张力与冲突不处理。书主张：**协作是要学的技能**；可视化协作工具有用，但还需要 **Facilitator** 引导。

核心手段是 **Collaborative Modeling**：用可视化，与相关利益相关方和决策者一起分析复杂、易冲突的决策过程，建立**共享理解**。凡参与造软件的人，书里都视为 **designer**，都可以学着主持或有效参与这类会话。

贯穿案例是虚构影院链 **BigScreen**（真实咨询问题的合成）：大泥球系统拖垮「Anytime, Anywhere」购票愿景；协作建模同时改架构边界与协作方式。
