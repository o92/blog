对应原书 **7.1**：偏差不是「不理性」的骂人标签；系统性让它可预期、可观察、可引导。

## 什么是（7.1 / 7.1.1）

**Cognitive Bias**：影响决策与判断的、相对某规范的**系统性**偏离——大脑简化信息处理的心理捷径。定义里的 **systematic** 很关键：可预测，故几乎每场协作建模都能看到相似模式；引导者可把观察还给群体，一起判断「这里帮了忙还是挡了路」。

每天信息爆炸，若每件事都刻意处理（闹钟、洗澡、开车、停车……），人会瘫痪。大脑无法理性登记一切，于是走捷径：只取决策所需、靠经验快速拍板。协作里大量无意识决策——选 pivotal event、怎么拆组、便签贴哪、何时离开争论——都部分靠偏差。没有捷径，建模时间会被「想清楚一切」吃光。

作者自称是偏差的粉丝：常被污名化，但没有它生活更复杂、也更无趣。

## 长什么样（7.1.2）

例：EventStorm 要定 pivotal event 时，常是相对高 rank 的人先指一个——「我觉得这个该是 pivotal」。其余人要么跟，要么只在时间线上**附近**微调。这是 **anchoring（锚定）**：第一建议成锚，群体往锚靠（常与 ranking 叠加）。

后文会展开确认偏差、琐事定律、虚假共识、可得性、损失厌恶、加法偏差等。

## System 1 / System 2（7.1.3）

Kahneman《Thinking, Fast and Slow》：

| | System 1 | System 2 |
|--|--|--|
| 速度 | 快、近乎自动、直觉 | 慢、需注意 |
| 努力 | 省力 | 费力 |
| 与偏差 | 高度受益于捷径，也易被带偏 | 可质疑、反思 |

不必时时用 System 2 审问 System 1——那样既累又浪费；要学会识别「出错代价高」的情境。

## 拥抱偏差（7.1.4）

多数时候捷径让我们有效率，协作建模也需要这种效率。拥抱双系统：

- 识别情境与偏差 → 再决定是否挑战（无普适对错，看语境）
- 同一偏差对不同人行为影响不同；挑战时要意识到会牵动行为
- 目标是**平衡与引导**，不是消灭偏差，也不是把偏差当骂人标签
